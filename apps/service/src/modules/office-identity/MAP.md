# Office-identity: module map

## Owns

- The Office identity, the only credentials The Office's git uses: `OfficeIdentity.forGitCommand(remote, inherited)` (one git command's `-c` arguments and environment) and `needsOf(remote)` (`RemoteNeeds`: `signed-in-https`, `ssh`, `anonymous-https`, `local`, `refused`), making nothing.
- In `<office-data>/identity/`: `OfficeGitHome` (home folder and global config), `OfficeSshKey` (made on first need, `regenerate()` beside the current key then moved), `OfficeKnownHosts` (GitHub's keys from `<api>/meta`, confirmed hosts; Unconfirmed hosts in memory).
- `GitCredentialHelper`: a signed-in GitHub https command gets `-c credential.<origin>.helper=…` and its secret in `OFFICE_GIT_CREDENTIAL_SECRET`; the script asks a loopback listener; `GitCommandIdentity.release()` ends the secret.
- `GitHubSite` (one value for the https check, helper origin, ssh host and meta URL); `OfficeIdentityHttpModule` (the app's alone) serves the public key, regeneration and known hosts (`OfficeIdentityController`).

## Talks to

- The platform only. Projects and Skills import `GitIdentityModule` from `index.ts` and run each git command with `forGitCommand`; Projects reads `needsOf`.
- `app.module.ts` binds `GitHubUserToken` to the github module's `GitHubAccess` through the global `GitHubUserTokenModule`; the module imports no other module.

## Traps

- Every caller of `forGitCommand` calls `release()` once git exits.
- The token is read only when git asks the helper; a failed read fails the command (`quit=1`), never anonymously. The secret is never an argument (`/proc/<pid>/cmdline`); the token is in no argument, variable or file; `GIT_TRACE_REDACT=1`.
- Clear only credential helpers (`-c credential.helper=`), never global or system config (LFS filters); `HOME` is the identity folder; `GIT_CONFIG_GLOBAL` includes the user's by absolute path.
- `http.emptyAuth=false` (an empty user lets curl answer with the Windows sign-in); git-lfs still answers Negotiate (spec §5.5 known gap); http settings are set again for the remote's own URL.
- `GIT_SSH_COMMAND` runs in git's sh and names files by `-o IdentityFile=`, never `-i`.
- `GIT_ALLOW_PROTOCOL` is `https:ssh`, plus `file` only for a local remote.
- `GitIdentityModule` holds no controller; only this module writes the `identity` folder.
- The fake GitHub takes `GITHUB_ED25519` from `index.domain.ts`, never `index.fixtures.ts` (tsx has no decorator metadata).

# People: module map

## Owns

- Roles hired from presets or from scratch (`roleKeyFor`, never a preset's key), Role cards and their versions (`roles`, `role_card_versions`, `proposed_by`, `saved_by`), let go and hire back, Avatars, Memory notes.
- The Authority (`domain/authority.ts`: a setting per Office tool area, group or tool; capped and followed rows; the four Hard switches as named groups, `hardSwitchesOf`), capabilities, Task limits, each person's engine settings per engine type.
- The duties (`domain/duties.ts`, `DUTIES`; `duty_assignments`; `Duties`: `holderOf`, `heldBy`, `holders`, `changeAll`, `DutyChangeChecks`), the Caretaker (`CARETAKER`, seeded by migration 0087), the office set-up (`OfficeSetup`).
- The engine and model cascades (`EngineCascade`, `EngineCascadeModule`, `standInsApplying`) and the capability check (`PipelineRoleCapabilityChecks`, `PipelineRoleSources`, `newlyNamedRolesProblems`).
- Move-overs at start (`AuthorityMoveOver`, `giveDutiesJobs`, `ProjectSettingProposalsMoveOver`), Office actions (`PeopleOfficeActions`: `hire_role`, `change_role_card`, `let_go_role`, `hire_back_role`, `delete_memory_note`, `set_avatar_from_attachment`, `remove_avatar`).

## Talks to

- Engine (`EngineModels`, `EngineModelLists.refreshStale`, `EngineReferenceLock`, `EngineSettingsChecks`), Skills (a Role's skills), MCP servers (`RoleMcpServers`).
- Work and Pipelines read cards through `KnownPeople`→`RoleCards`; Conversations reads the index and applies Role Proposals through `RoleService`.
- Ports: `KnownProjectLevels`→`ProjectService`, `ProjectLevelsSaves`→Projects' `EngineLevelsChecks`, `KnownWorkLevels`→`WorkEngineLevelsModule`; registries others fill: `AvatarSources`, `SessionPeople`, `MemoryTaskTitles` (Work, Conversations call People). People never imports Projects. Bindings in [app.module.ts](../../app.module.ts).
- Other domains take its pure values from `index.domain.ts` (`DUTIES`, `ASK_ME`, `CARETAKER`, `heldToCap`, `isAuthorityGroup`, `authorityWithHardSwitches`), never `index.ts`.

## Traps

- Rollback shims: the stored card keeps `roleOverride`, `effort` and `hardSwitches` written in step with `authority`, marked `ROLLBACK SHIM (Authority)` / `ROLLBACK SHIM (engine settings)` (grep it, here and in Conversations); each comes out in the first release after the one that ships its change, never the same one. A missing `changeProjectSettings` switch reads Ask me.
- `PostgresRoleRepository` reads Authority as stored `authority` with stored Hard switches over it; strips retired rows (`RETIRED_AUTHORITY_GROUPS`, `withoutRetiredRows`).
- The Caretaker's card (capabilities, profile, Authority, Task limit) is fixed and refused by `builtInCardProblems`; after move-overs it is at version 3, so tests don't count its versions.
- Test cards: `aRoleCard` (domain), `aCardToSend` (HTTP), `aCardSavedBeforeAuthority` (stored by the release before). Only `adapters/http/roles.controller.test.ts` hires from presets (fixed keys, [testing](../../../docs/testing.md)).
- Every test file shares `duty_assignments`: tests use `DutyRepositoryForTests`/`dutiesOver`; office set-up tests bind `OfficeSetupRepositoryForTests`. Stand-ins for People's cascade use `EngineCascadeStandIn`; for `SessionRole`, `MCP_TOOL_DEFAULT_STAND_IN`.
- `EngineCascade.of` throws `NoEngineListed` while no engine is listed; `applying` gives none.
- A let-go person keeps the key (`letGoAt`): `RoleCards.find` treats them as not filling it; a duty naming them falls back.
- `DutyHolderChanged` is published only on the user's setting; hire, let go and hire back change holders without it, so subscribers hear those too.
- Which Stand-in list a place weighs comes only from `standInsApplying`; an override weighs none. Duties named by Stages are weighed by their holder's Role (`withDutiesResolved`).
- `changeCard` and `hireFromScratch` hold `EngineReferenceLock`, publishing after release.
- An Avatar's file is written before the row names it and removed after; it saves no card version.
- The MCP tool default follows the duty: with Devops not hired an unset tool reads Ask me.
- `PostgresRoleRepository`/`PostgresDutyRepository` reads go through platform `readOnce`; writes through `forgettingReads`.

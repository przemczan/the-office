# Activity: module map

**Owns:** Activity (spec [2.14](../../../../../docs/spec/2.14-activity.md)), whose Nest module is `ActivityModule`: everything The Office is running, read afresh on each request (`ActivityService.read`, in a read scope of its own) and merged by the pure `domain/activity.ts` (`activityOf`): running Tasks, `failed-task` and `stopped-task` (a started Task whose current Stage, the one run last, failed or was stopped, with no Decision open on it, keyed by that run), each Off-board Task listed once as its own kind (`onboarding` for an Onboard Task, `run-environment-set-up` for a "Set up the run environment" Task) while queued (with its place and short reasons), in progress, waiting on you, paused or failed (a Stage out of tries, its Decision open), ended once Done or Dropped, with its Stage and its tokens so far, test instances Building, Running, Built or Failed, CI runs, environment checks, Connected devices not Disconnected and pull requests ready to merge. An ended item stays listed until the user has seen it, or until it ended over `ENDED_KEPT_DAYS` (7) ago; the running first, then the newest first; `count` is every item listed. What each user has seen (`activity_seen`, by user and item id, forgotten after `SEEN_KEPT_DAYS`, 30, on each mark). `GET /activity`, `POST /activity/seen` and `activity.changed`, one per burst of the source events (`ActivityChanged`, announced in the background).

**Talks to:** nothing calls it. It reads through its ports, bound in [app.module.ts](../../app.module.ts): `ActivityTasks` to Work's `TaskService` (`started`, `doneSince`, `findAll`, `stateChangesOf`), `ActivityOffBoardTasks` to Work's `OffBoardTaskReader` (`listAll`), `ActivityStages` to Pipelines' `TaskStagesService.progress`, `ActivityDecisions` to Conversations' `DecisionService.listOpen`, `ActivityTestInstances` to `TestInstances.activity(since)`, `ActivityCiRuns` to Projects' `CiRunWatch.list`, `ActivityEnvironmentChecks` to Projects' `EnvironmentChecks.latestOfAll`, `ActivityPullRequests` to Projects' `PullRequestWatch.list` and `ActivityDevices` to `ConnectedDevices.open`. Each port answers the module's own small types; the bound services satisfy them structurally. It subscribes to Work's, Pipelines', Conversations' Decision, Test instances', Projects' (CI runs, environment checks, pull requests) and Devices' events.

**Traps:**
- An ended item's id differs from the running one's (`…:ended`, `…:done`, a test instance's state, a failed or stopped Task's run id), so seeing an item while it runs never hides it once it ends.
- An Off-board Task is never a `task`, `failed-task` or `stopped-task` item: the domain leaves out every started or Done Task the reader lists, and any whose `madeFor` is an Off-board kind (one archived meanwhile, which `listAll` leaves out). Its status `ready` (made before they started at once, waiting for Start) isn't listed.
- The domain keeps the owning modules' states as plain strings; `adapters/http/activity-responses.ts` parses each item with the contracts' `activityItemSchema`.

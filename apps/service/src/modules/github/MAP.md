# GitHub: module map

## Owns

- Sign in with GitHub: the GitHub App registered by the manifest flow (`github_app`), the user's sign-in through it (`github_sign_in`, `GitHubSignIn`), the token in use (`GitHubAccess`), the App's permissions (`GitHubPermissions`, `REQUIRED_PERMISSIONS`, `check_github_permissions`).
- GitHub's API for others: pull requests (open, status, merge, close), CI runs and re-runs, manual Workflows and refs, installations' repositories, issues (`GitHubIssues`), and Continue with GitHub's identity (`GitHubIdentities`).
- `FakeGitHub` (`index.fixtures.ts`, `serve-fake-github.fixtures.ts`) for every test that reaches GitHub, with its `/_fake/*` control paths.

## Talks to

- GitHub through the `GitHubApi` port (`GitHubRestApi`) on the base URLs `GitHubModule.register(urls)` is given (`OFFICE_GITHUB_URL`, `OFFICE_GITHUB_API_URL`).
- The platform's Office identity binds `GitHubAccess` as its `GitHubUserToken`, so git gets the token through the credential helper; Projects wraps it as `GitHubCodeHost`; the users module's `GitHubIdentityProvider` calls `GitHubIdentities`; Engine's `OfficeToolRegistry` for the Office action; the web through `github.changed`.

## Traps

- No secret reaches a log or event: `GitHubRestApi` parses only what is kept, and a failure names GitHub's status, never its body (except a pull request's 422 messages and a refused merge's or close's message). Secrets and tokens are never in an HTTP answer or URL.
- GitHub refuses token requests with HTTP 200 and an `error`, and answers form-encoded without `Accept: application/json`.
- Every token read and sign-in change runs one at a time on `SignInChanges` (each refresh ends both tokens); a waiter re-reads kept tokens rather than refreshing again.
- Continue with GitHub revokes its token at once, one by one, never `/grant` (it would end the git identity's token for the same user); it never touches `github_sign_in`.
- Registering the App again ends the sign-in. Callback URLs come from the address the request reached; any mismatch goes to the App's first callback URL (Sign in with GitHub's), worded there.
- `Link` pages are followed only on the API's own origin; calls time out after 30 s.
- Conditional reads: up to 500 parsed answers kept by token hash and URL, ETag and 304 (no rate limit cost); one provider per module.
- Only the combined status' `statuses` are read (its `state` is `pending` with none); `stale` or unknown conclusions count as pending; `mergeable` is null until GitHub works it out. The Office never deletes a branch here.
- The fake's default permissions (`FAKE_DEFAULT_PERMISSIONS`) lack `actions: write` and `issues: write`: grant them for re-runs, dispatches and issue writes.

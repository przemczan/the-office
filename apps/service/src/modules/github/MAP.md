# GitHub: module map

**Owns:** Sign in with GitHub (spec §5.3, §5.5): the GitHub App the user registers from Settings › Office identity by GitHub's manifest flow, kept in one row (`github_app`: Client ID, client secret, slug, owner), and the user's sign-in through it (`github_sign_in`: login, tokens and their expiries, or why The Office signed the user out). Registering: `GET /github/app/manifest` hands the browser a form for GitHub's new-App page with an unguessable state (`PendingStates`, GitHub's hour); GitHub sends the browser back to `GET /github/app/registered?code&state`, which converts the code (`POST /app-manifests/{code}/conversions`), replaces the App, publishes `GitHubAppRegistered` and redirects to Settings › Office identity, a failure carrying why in `registrationFailed`. Signing in (`GitHubSignIn`, GitHub's web flow for an App's user token): `GET /github` gives the state with the App's slug, owner and install page (`appInstallUrl`, on the website URL), never a secret; `POST /github/sign-in` gives GitHub's authorize URL (state, PKCE S256, `offline_access`); GitHub sends the browser back to `GET /github/sign-in/callback`, which exchanges the code with the client secret and verifier, keeps the tokens, publishes `GitHubSignedIn` and redirects to Settings, a failure carrying why in `signInFailed`. `DELETE /github/sign-in` forgets the tokens (`GitHubSignedOut`). `GET /github` gives the state. The token in use (`GitHubAccess`, the public entry): `userToken()` gives it for one command, refreshing it first when it expires within fifteen minutes (`grant_type=refresh_token` with the client secret, both tokens replaced); a refresh GitHub refuses, or a refresh token past its expiry, signs the user out with a reason (`GitHubSignedOut`), and GitHub unreachable fails the command keeping the sign-in. `GET /github/repositories` lists the repositories of the App's installations the user reaches (`GET /user/installations`, `…/{id}/repositories`, every page by the `Link` header's `next`, suspended installations left out), each with its default branch, Private, when it was last pushed (`pushed_at`, null when GitHub has none) and its description (empty when it has none), 409 while signed out, 502 when GitHub fails. Pull requests (`GitHubPullRequests`, the public entry, for Projects' Push + PR): `whyCannotOpen(remoteUrl)` says, without asking GitHub or refreshing, that a remote isn't a repository on GitHub's website (`repositoryOnGitHubOf`: an http(s) URL by `webUrl`'s origin, ssh by its host) or that no one is signed in; `open` posts `POST /repos/{owner}/{repo}/pulls` with the user token and, on a 422, gives the open one for `head=owner:branch` into the base (`GET …/pulls?state=open`), otherwise GitHub's refusal in words (`PullRequestNotOpened`), answering `{ number, url }` (`OpenedPullRequestOnGitHub`). Reading them, for Projects' list of the pull requests The Office opened: `reaches(remoteUrl)` (on GitHub's website, asking no one); `whyCannotRead(remoteUrl)`, never throwing: not on GitHub, no one signed in, or the token couldn't be renewed now (`GitHubAccessFailed`'s reason); `openPullRequests(remoteUrl)` (`GET …/pulls?state=open`, every page: `OpenPullRequestOnGitHub`, branch, base branch and both commits); `status(remoteUrl, number)` (`GET …/pulls/{n}`, then the head commit's `GET …/commits/{sha}/check-runs`, every page, and `…/status`'s `statuses`: `PullRequestStatusOnGitHub`), mapped by `domain/pull-request-status.ts` into host-neutral words (`GitHubPullRequestState` open/merged/closed by `merged_at`, `GitHubChecks` failing over pending over passing over none, unknown when GitHub refuses the checks with 403 or 404, `GitHubMergeable` yes/conflicts/unknown while `mergeable` is null); both throw `NotSignedInWithGitHub` while signed out and `GitHubAccessFailed` otherwise.
Merging and closing them, for Projects' Merge and Close: `mergeMethods(remoteUrl)` (`GET /repos/{owner}/{repo}` by ETag: the `allow_*` flags, a flag GitHub leaves out offering its method, and `delete_branch_on_merge`, by `domain/merge-refusal.ts`' `allowedMergeMethodsOf`); `merge(remoteUrl, number, { method, expectedHeadCommit })` (`PUT …/pulls/{n}/merge` with `merge_method` and `sha`, a squash also with `commit_title` "<title> (#n)" and `commit_message` the pull request's body, read by `GET …/pulls/{n}`), answering `{ commit }`; `close(remoteUrl, number)` (`PATCH …/pulls/{n}` with `state: closed`). The Office never deletes a branch. GitHub's refusals become `PullRequestNotChanged` in `merge-refusal.ts`' words (405 "GitHub won't merge #n: <message>", 422 "GitHub refused: <message>", 403/404 "Your GitHub account can't merge in owner/repo." or "… can't close pull requests in …", no answer "GitHub couldn't be reached."), and a 409, the head moved past `sha`, `PullRequestChangedOnGitHub` ("#n changed on GitHub since The Office last read it. Refresh, then try again."), which Projects' `GitHubCodeHost` throws as `CodeHostChangedSince`. GitHub Actions runs, for Projects' CI runs: `recentRuns(remoteUrl, count)` (`GET …/actions/runs?per_page=<count>`, one page, `CiRunOnGitHub`: workflow, title, trigger, branch, commit, attempt, `startedAt`/`updatedAt`, its `status` mapped by `domain/ci-run-status.ts` into `GitHubCiRunStatus` queued/waiting/running/succeeded/failed/cancelled/skipped/unknown, a completed run by its conclusion) and, for an Action's Workflow run, `runsStartedByHand(remoteUrl, { file, branch, createdSince })` (`GET …/actions/workflows/{file}/runs?branch&event=workflow_dispatch&actor=<the signed-in login, GitHubAccess.signedInLogin>&created=>=…`, filtered again here, GitHub's created time being whole seconds, oldest first), `run(remoteUrl, runId)` (`GET …/actions/runs/{id}`, undefined on 404) and `workflowRunsUrl(remoteUrl, file)` (the Workflow's runs page, asked of nobody); the fake serves both and records each dispatched run's `path`, `actor` and `createdAt`; `rerun(remoteUrl, runId, onlyFailed)` (`POST …/actions/runs/{id}/rerun` or `…/rerun-failed-jobs`, 201 drops the repository's cached runs); both throw like `openPullRequests`, GitHub's 403, 404 or 422 as `GitHubAccessFailed` quoting its `message`. Starting workflows by hand (`workflow_dispatch`), for Projects' manual Workflows: `manualWorkflows(remoteUrl, ref)` (`GET …/actions/workflows`, every page, the `active` ones under `.github/workflows/`, then each file's `GET …/contents/{path}?ref=`, base64, a 404 leaving the workflow out: `ManualWorkflowOnGitHub`, file name, name, page and inputs), parsed by `domain/workflow-dispatch.ts`' `dispatchInputsOf` (the `yaml` package as YAML 1.2, so the key `on` isn't true; `on` as the string, a list or a map; each input's description, required, default as a string, type, an unknown one string, and a choice's options; undefined for a file that isn't YAML or lacks the trigger); `refs(remoteUrl)` (`GET …/branches` and `…/tags`, every page, at most 1,000 of each: `RefsOfRepositoryOnGitHub`); `startWorkflow(remoteUrl, { file, ref, inputs })` (`POST …/actions/workflows/{file}/dispatches` with `{ ref, inputs }`, the inputs as strings; a 204 drops the repository's cached runs, so the queued run shows in the next `recentRuns`). All three throw like `rerun`, GitHub's 403, 404 or 422 (such as "Unexpected inputs provided: […]") quoting its `message`.
Issues (`GitHubIssues`, the public entry, for Projects' GitHub issues, docs/design/issues-as-tasks.html): `openIssues(remoteUrl, { label?, order, most })` (`GET …/issues?state=open&sort=created&direction=…&labels=…`, every page until `most`, the pull requests GitHub's issues API lists among them, marked `pull_request`, left out; `IssueOnGitHub`: number, title, body, author, labels, `openedAt`); `issue(remoteUrl, number)` (`GET …/issues/{n}`, with `state` open or closed and `closedAt`; undefined for a 404, a 410 or a pull request); `comment(remoteUrl, number, body)` (`POST …/issues/{n}/comments`, 201) and `close(remoteUrl, number, "completed" | "not_planned")` (`PATCH …/issues/{n}` with `state_reason`) and `reopen(remoteUrl, number)` (`PATCH …/issues/{n}` with `state: open`); all throw like `rerun`, a write's 403, 404, 410 or 422 quoting GitHub's `message`. A deleted author is GitHub's `ghost`.
The App's permissions (`GitHubPermissions`): `REQUIRED_PERMISSIONS` (`domain/github-app.ts`, also the manifest's `default_permissions`: metadata read, contents, pull requests, workflows, actions and issues write, checks and statuses read), compared with what each installation that isn't suspended granted (`GET /user/installations`' `permissions`, a higher level satisfying a lower); `lacking()` answers the missing ones once each, the App's permission settings (`/organizations/{owner}/settings/apps/{slug}/permissions` or `/settings/apps/{slug}/permissions`) and each lacking installation's page to accept them on, or undefined when nothing is missing, no one is signed in or GitHub can't be asked (logged at warn). Kept five minutes, dropped on `GitHubSignedIn`, `GitHubSignedOut` and `GitHubAppRegistered`. `GET /github` gives them as the signed-in state's `permissions` (null when none are missing); `POST /github/permissions/check` (Check again) drops them, reads them again, publishes `GitHubPermissionsChecked` (`github.changed` on the web) and answers the state. Continue with GitHub (`GitHubIdentities`, the public entry, which the users module's `GitHubIdentityProvider` calls): who a user of The Office is on GitHub, through the same App by its user authorization flow: `isAvailable` (an App registered), `authorizeUrl` with the caller's state, PKCE S256 and callback URL and no scope (so no `offline_access`), and `identityOf`, which exchanges the code (`exchangeSignInCode`), reads `GET /user` (`userOf`: GitHub's numeric id and login) and revokes that one token (`DELETE /applications/{client_id}/token` with the client ID and secret by Basic auth, never `/grant`; a failed revoke is logged without the token), answering `{ subject, name }`. It never reads or writes `github_sign_in`, never runs on `SignInChanges` and publishes nothing. The manifest's `callback_urls` list Sign in with GitHub's callback first, then `/api/sign-in/github/callback` on the registering origin and on `OFFICE_PUBLIC_ADDRESS` when set; at the public address the origin is the configured one (`officeOriginOf` with `OfficeAddresses`), since behind the proxy requests look like plain HTTP.

**Traps:** the conversion's answer holds the App's private key and webhook secret, and token answers hold tokens. `GitHubRestApi` parses only what is kept, and a failure names GitHub's status, never its body (except a pull request's 422, whose validation errors' `message`s GitHub writes for the user, and a refused merge's or close's `message`, such as "Pull Request is not mergeable"), so no secret reaches a log or an event; the client secret and tokens are never in an HTTP answer or a URL (sent in the body). GitHub refuses token requests with HTTP 200 and an `error`, and answers form-encoded without `Accept: application/json`. Registering the App again ends the sign-in (tokens of the App before won't refresh), and a sign-in begun under the App before fails. The callback URL and `redirect_url` are built from the address the request reached The Office on; signing in from another address than the one the App was registered from gets `redirect_uri_mismatch`. GitHub sends any mismatch to the App's first callback URL, Sign in with GitHub's, Continue with GitHub's included: `GitHubSignIn.complete` words a mismatch with a state it didn't issue as "add this address's callback URL" (a browser not signed in gets the guard's 401 there instead). Continue with GitHub's tokens are revoked at once and only one by one: `/grant`, or the user revoking the App's authorization on GitHub, would end the git identity's token too when it is the same GitHub user. Every read of the token and every sign-in change runs one at a time on `SignInChanges`, shared by `GitHubSignIn` and `GitHubAccess`: GitHub ends both tokens on each refresh, so two refreshes at once would sign the user out, and a token isn't kept after the sign-out or new App that came in meanwhile. A caller waiting behind a refresh re-reads the kept tokens rather than refreshing again. `Link` pages are followed only on the API's own origin, so the token goes nowhere else. Calls to GitHub time out after 30 seconds, so a hung refresh can't hold up every git command. `GitHubRestApi` makes its reads conditional: it keeps up to 500 answers (what it parsed, never the whole body) by the token's SHA-256 and the URL, sends their ETag as `If-None-Match` and reuses the kept answer on a 304, which costs no rate limit; so a page read every few seconds stays cheap, and its own instance holds them, the one provider per module. A workflow file's answer is kept as the inputs `dispatchInputsOf` read, not its text. The combined status' own `state` is `pending` for a commit with no status at all, so only its `statuses` are read. A check run concluding `stale` or a conclusion GitHub may add counts as pending, never passing. GitHub's `mergeable` is null until it has worked it out, which the first read starts. The App's owner is kept by login only: its kind comes from an installation on that account, else an owner other than the signed-in user is taken as an organization.

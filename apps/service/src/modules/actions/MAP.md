# Actions: module map

## Owns

- Action runs (`action_runs`) of the Actions Projects defines: `ActionRuns.start` resolves the source (`ActionSources`) to its fetched tip and refuses in `domain/action-run-words.ts`'s words (`ActionRunRefused`); one start at a time (`oneAtATime`) behind `action_runs_one_running`.
- Runs in the background (`RunsInBackground`): Project command runs (`CommandRuns`, own checkout `<office-data>/action-runs/<run id>/`, in a compose project or on the workstation, `OFFICE_ACTION*` variables, time limit, Stop, Project device holds), Test target runs (`ActionTestInstances`, "run as"), Workflow runs (`WorkflowRuns`, `WORKFLOW_SHOW_MS`, no Stop).
- Masked logs (`ActionRunLogs`, `<run id>.log`), each Action's History (newest `KEPT_RUNS` 20), Actions at once (`action_settings`, `ActionLimits`, the Office action `set_action_settings` in `ActionSettingsOfficeActions`).
- Stops from outside (`ActionRunReactions`: ASAP alarm, Actions switched off, an Action removed) and the startup sweep (`sweep`, from `office.ts`).

## Talks to

- Projects (`ActionProjects`, `ActionWorkflowHost`→`ActionWorkflows`; fills `ActionLastRuns` via `ActionLastRunsRegistration`), Run environments only through `RunEnvironmentsCommandRuns` (no slot), Test instances (`ActionTestInstances`), Devices (`ActionDevices`), Work (`ActionSources`, the fire alarm); events through `ActionRunSignals`. Engine's registry for the Office action.
- Raises `ActionRunStarted`, `ActionRunStateChanged`, `ActionRunChanged`, `ActionRunsRemoved`, `ActionSettingsChanged`; [app.module.ts](../../app.module.ts) binds Activity's and Office updates' ports to `runningCommandRuns()` (busy work `action-run`).

## Traps

- Running command runs are in memory: only the sweep from `office.ts` ends rows left running, never a module's start.
- A Workflow run's CI run is found by file, branch, actor and time only: a run skips CI runs other Action runs already follow and takes the oldest left.
- A Test target run raises no Outcome of its own (Test instances raise theirs).
- A hold's own end is Disconnected as run ended: `CommandRuns` forgets the hold before letting go, and only an end from outside fails the run.
- `checkFree` at the start holds nothing; the device is held once the compose project is up, so a race fails the run at its hold rather than refusing it.
- Application tests run on rows in memory (`actionsTestbed`, `actions-ports.fixtures.ts`); only the Postgres repository's test writes `action_runs`.
- In e2e the fake GitHub serves no git, so Workflow runs are tested in the service and e2e confirms with a command Action on a local remote.

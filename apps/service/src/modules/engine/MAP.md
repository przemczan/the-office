# Engine: module map

**Owns:** the engines a Role may pick (`ENGINES`, `ENGINE_MODELS`: `agent-sdk` and the `-p` fallback `claude-code-p`), the `AgentEngine` port and its adapters, one per engine in `AgentEngines`: the Agent SDK adapter, the fallback's (`adapters/claude-code-p/`: the pinned binary in `-p`, stream-json in and out through `StreamJson`), and the scripted engine every other test runs on (`adapters/scripted/`). What both Claude Code adapters share (the event mapping, tool refusals, the Office rules hook and `toolDecision`, the Office tools' names) is in `adapters/claude-code/`. The fallback's hook reaches the service on `localhost` (`adapters/http/`, under `/api/engine/claude-code-p/`), behind a token per session (`SessionEndpoints`); its Office tools are served in-process through the binary's own stream (`OfficeToolServer` answering `mcp_message` control requests, which `StreamJson` routes to it), judging every call by the session's rules again as it runs. `ClaudeCodePEngine` opens both before it spawns the binary and closes them when the session ends. `EngineSessions` starts and resumes a session on the engine its settings name, and reads capabilities per engine. The Office rules in the `PreToolUse` hook (profiles, the git deny, secrets, protected paths, PowerShell twins), and before them a session's `ToolHold` (`SessionOptions.toolHold`, asked at every call: while it gives words, every call is refused in them, as the fire alarm does; the scripted engine honours it too, running no Office tool), Office tools (`OfficeToolRegistry`), and the 5-hour and 7-day windows (`UsageWindowsChanged`, `EngineDown`).

**Talks to:** no module. A session's owner hands it the skills folder, the options and the environment; modules give it their Office tools through `OfficeToolRegistry`. It never reads Skills.

**Traps:** what the pinned SDK does is checked by the engine check ([docs/engine-check.md](../../../../../docs/engine-check.md)); re-run it on every SDK bump. Live adapter tests run only with `OFFICE_ENGINE_TESTS=live` ([testing](../../../docs/testing.md)). The fallback's live test serves the endpoints itself (`serveSessionEndpoints`). Keep the fallback's Office tool answers on the binary's input: over a separate channel (the old `localhost` MCP endpoint) an answer overtook a `next` message on Windows (engine-check.md, `fallback.priority-next-office-tool`).

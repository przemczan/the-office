# Telemetry: module map

## Owns

- Stats (`StatsModule`, no table of its own): the basic stats (`BasicStats`, `GET /stats/basic`, pure `domain/basic-stats.ts`).
- The full stats from the Grafana in use (`FullStats`, `GET /stats/full`, pure `domain/full-stats.ts`), System health (`SystemHealth`, `GET /stats/system-health`, pure `domain/system-health.ts`), the Grafana check (`GrafanaCheck`, `POST /stats/grafana-check`; here, as the platform can't import a module).
- The Office action `save_telemetry` (`TelemetryOfficeActions`). The telemetry plumbing every module uses (exporters, `Telemetry`, the logger, Settings › Telemetry, the bundled Grafana) is in `src/platform/telemetry/`, not here.

## Talks to

- Nothing calls it but its Office tools. It reads Notifications' `DayTokenHistory`, Pipelines' `StageRunTotals`, `RunningStageRuns`, `StageRunEngines`, Engine's windows (`EngineWindows`), Work's Tasks, the platform's Health readings and the Grafana in use through `StatsSource` (`GrafanaInUse`→`SettingsGrafanaInUse`).

## Traps

- The saved Grafana read address and token apply at once; only the export settings wait for the next start.
- The check asks data sources afresh, never from `GrafanaDataSourceCache`; a 403 on `/api/datasources` is a Viewer token, on `/api/frontend/settings` a refused one.
- Tokens per day and Usage windows are Office-wide; the basic Project filter narrows only top Tasks, Tasks done and retries. Basic and full totals aren't meant to match (Stage runs only vs every engine call).
- Every count leaves cache reads out (`countedTokens`); a negative day kind answers 0.
- "This week" starts at `weekStartOf(now)` on the `Schedule`'s clock.
- Ids are only in Loki records, never in metric attributes; the full stats' Project filter narrows by the Project's name now (a rename splits history).
- Buckets are fixed UTC steps aligned to the epoch, not office days.
- `office.stage.run` is the run's number on its Task, not its id; engines are named by the run's names, then `EngineWindows`', then "Removed engine", never by id.
- Grafana metric, label and data source names live only in `adapters/grafana/grafana-queries.ts`; on every pin bump run the Grafana live check (`grafana-stats-source.live.test.ts`, [testing](../../../docs/testing.md#the-grafana-live-check)) and re-record `recorded/*.json`.
- System health histogram buckets are costly: each block reads them once (`bucketsQuery`) and takes every p95 and Max from that answer; never add a query over `_bucket` or read them over the whole range.
- 1 h never asks Grafana; nothing of it is stored.

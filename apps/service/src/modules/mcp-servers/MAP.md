# MCP servers: module map

**Owns:** the MCP server library (`mcp_servers`, spec §5.4): each server's local command and arguments (stdio) or remote URL (Streamable HTTP), its Server values (environment variables of a local server, headers of a remote one; plain or secret; required or not) with their Office-wide values, and whether it is on. A server is added off (`McpServerLibrary.add`), and an edit to its command, arguments, URL, transport or its values' names turns it off; a pasted JSON config in the shape of Claude Code's `mcpServers` entries is read into a server for the form (`POST /mcp-servers/pasted-config`, `pastedMcpServer`), and nothing is kept until the user adds it.

**Talks to:** no module yet; Settings › MCP servers in the web, over `/mcp-servers`.

**Traps:** a secret's Office-wide value is kept in the database and never leaves the service: the controller answers `officeWideValueSet` instead, an edit without a value keeps the one kept, and a secret made plain loses its value so a later GET can't show it. The events name the server and never carry it, so a subscriber to every event never sees a secret. The name is never changed: it names the server's tools (`mcp__<name>__<tool>`), so it has single hyphens only, at most 32 characters, and `office` is the Office tools' own.

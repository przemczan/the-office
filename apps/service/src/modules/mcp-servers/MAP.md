# MCP servers: module map

## Owns

- The MCP server library (`mcp_servers`): each server's stdio command or remote URL, its Server values (plain or secret, required or not) with Office-wide values, on or off, and the tools its review listed when turned on.
- The review (`McpServerLibrary.review`, `reviewDigest` in `domain/mcp-server-review.ts`); turning on needs a matching digest (an Agent's call reviews itself first); pasted Claude Code `mcpServers` config (`pastedMcpServer`).
- Office actions (`MCP_SERVERS_OFFICE_ACTIONS`) in `McpServerOfficeActionsModule`, apart from `McpServersModule`, so its readers don't take the Engine in.

## Talks to

- The platform's `McpClientModule`, the Engine's Office tool registry; launches from `application/mcp-server-launch.ts`.
- People reads a Role's servers (`RoleMcpServers.byRole`, `McpServerOnCard`); Conversations prepares a session's (`SessionMcpServers`); the web's Settings › MCP servers.

## Traps

- An edit to the command, arguments, URL, transport or value names turns the server off and forgets its tools.
- A secret's Office-wide value never leaves the service: answers carry `officeWideValueSet`; an edit without a value keeps it; a secret made plain loses it; events never carry it; a server's own words go through `withoutSecrets`.
- A call giving a secret's value is also ruled by Secret values (never Allowed or Consult) and shows by name only; fingerprints hold names and flags, never values.
- Tools named over 64 characters are left out of sessions (`toolsTooLong`).
- The name never changes: it names the tools (`mcp__<name>__<tool>`), single hyphens, at most 32 characters, and `office` is reserved.

# Test instances: module map

## Owns

- Test instances (`test_instances`): Hosted, Build to install and Install on a device targets launched on an Initiative's branch (`launchOnInitiative`) or any branch of a Project (`launchOnBranch`); the checkout (`<office-data>/test-instances/<id>/`) and log (`<id>.log`, through the target's mask); the limit and Idle time; Built files (`test-builds/`, retention, signed QR links).
- The Proxy (`TestInstanceProxy`): the Proxy ports, per-instance cookie prefixes, the hand-off (`TestInstanceHandOffs`, `GET /__office/hand-off?t=`), reachable addresses (`reachableHostnames`, `WorkstationAddresses`); `test_instance_settings`.
- Office actions: `launch_initiative_test_instance`, `launch_project_test_instance`, `stop_test_instance`, `open_test_instance`, `link_built_file` (`TEST_INSTANCE_OFFICE_ACTIONS`).

## Talks to

- Run environments only through `HostedServices` (`start`, `build`, `install`, `stop`, `sweep`): no slot, not busy work, so a Running instance holds back no Office update.
- Projects (`TestInstanceCheckouts`, `ProjectTestTargets`, `TestTargets.launchSettingsOf`, `ProjectFeaturesChanged`), Work through `Initiatives` (`adapters/work/`) and `InitiativeStateChanged` (in the background), Devices (installs' holds).
- [app.module.ts](../../app.module.ts) gives it Work, Projects, Run environments, Devices, `OfficePort` and `OFFICE_HOST`; `office.ts` starts the proxy and the sweep.

## Traps

- The checkout is `<id>/` itself (`TestInstanceCheckouts` refuses anything else), so the log lives beside it as `<id>.log`, which the sweep keeps.
- Running state, masks and idle stops are in memory; the sweep at start (from `office.ts` only) ends rows left Building or Running.
- Every test file shares `test_instances`: application tests use `TestInstanceRepositoryForTests`; only the Postgres repository's test writes the table (ports in the 61000s); only `test-instances-http.test.ts` writes `test_instance_settings`, restoring defaults.
- A stop while Building aborts the start; a checkout can't be aborted, so the build removes it once it lands. An invalid `.devcontainer/` ends Failed, not a refused launch.
- `branchCommit` is the local tip with no fetch.
- The proxy listens only once `office.ts` calls `start()`; its test starts it on free loopback ports of its own.
- Browsers don't separate cookies by port: an app gets only its own prefixed cookies (`oti_…`), dropping `office_signed_in`.
- The listener answers for whichever instance holds its port now (`byPort` per request); a port's opens and closes run one after another.
- The upstream sees Host `localhost:<target port>`, not the host port.
- A build stopped while Building is Failed by `stopped` itself; `ended` doesn't call `HostedServices.stop` for a build.
- The sweep leaves `test-builds/` alone; the build cache volume stays.
- An install and its build are two rows ending apart, both written inside `oneAtATime`; Devices publishes Disconnected for the install's own `letGo` too (`letGoOf` forgets the hold's id first).
- Open's answer carries the single-use hand-off link: never log it.
- Tests: builds scripted via `onExec` and `ProjectTestTargetsForTests.onBuild`, installs via `onAttach` and `InstallDevicesForTests`; Running instances from `testInstancesTestbed(hostedServices, officeDataPath)`.

# Users: module map

## Owns

- Users and signing in (`users`, scrypt hashes by `ScryptPasswordHashing`, one-time passwords), signed-in devices, wrong tries (`domain/wrong-tries.ts`), passkeys (`passkeys`, relying party from `relyingPartyAt`), the authenticator and recovery codes, pending sign-ins (`pending_sign_ins`).
- First-run setup (`first_run_setup`, `FirstRunSetup`, the setup token `domain/setup-token.ts`, host commands `set-password.ts`, `setup-token.ts`).
- Linked identities (`linked_identities`, `LinkedIdentities`, the one callback `GET /sign-in/<provider>/callback`, `IdentityTrips`), the Google OAuth client (`google_client`, `GoogleIdentityProvider`, the only user of `arctic`), the OpenID Connect provider (`openid_connect_provider`, `OpenIdConnectDiscovery`).
- Extension points: `SignIns.finish(user, way, request)` where every way ends; `SecondSteps` (bound to `AuthenticatorSecondStep`); `IdentityProviders`, `IdentitySignIns`.

## Talks to

- The platform's `SignedInRequests` (bound to `CookieSignedInRequests` through `RequestAccessModule`), `OfficeAddresses`, the `Schedule`; the github module's `GitHubIdentities` (through `GitHubIdentityProvider`).
- Bindings in [app.module.ts](../../app.module.ts).

## Traps

- A signed-in device and a pending sign-in are never called a session, in code, API or database.
- `UserRepository.find` answers removed users too; everything that signs in or lists goes through `findByEmail`, `listActive` or a `removedAt` check. Removal deletes devices in its own transaction; `SignedInDeviceRepository.add` holds the user `FOR SHARE`.
- The sign-in controllers are `@OpenWithoutSignIn()`; `SignInStarts` limits provider and passkey starts per client address (20 at once): a test starting more from one address gets 429.
- A user is found from a provider only by (provider, subject), never email or login. A new OpenID Connect issuer removes the old issuer's links.
- Secrets (Google, OpenID Connect) are never answered; an empty secret keeps the saved one; events never carry the secret.
- `takeStep` is a conditional UPDATE: a code's step is taken once. A test's next sign-in after setup uses the next step's code (`ManualSchedule.advanceBy` 30 s).
- The host commands boot through `src/host-command.module.ts` without the event stream, providing their own `WebEventForwarding` and `EarlierRecordsModule`.
- `UsersModule` is registered once and the same instance is given to `RequestAccessModule`.
- The domain keeps its own `AddressKind` (the boundary lint allows only `DomainEvent` from the platform).
- Unknown emails' wrong tries are in memory (reset at restart); a user's are in the database.
- Tests: other modules boot unguarded (`EveryoneSignedIn`); guarded tests use `startUsersApplication`, `signedInCookie`, `turnOnAuthenticator`, `authenticatorCodeOf`, `newSetupToken(office)` on a `freshTestDatabase`.
- More test helpers: `passkeys.fixtures.ts`, the software authenticator, `FakeIdentityProvider`/`FakeGoogleIdentityProvider`. The fixtures' `send` sets Content-Length (Node sends no DELETE body without it).
- Shared rows: only each Postgres repository's own test writes `google_client` and `openid_connect_provider`; others bind `googleClientForTests()`, `openIdConnectProviderForTests()`, `openIdConnectDiscoveryForTests()`; `linked_identities` is shared, so use a random subject, and the OpenID Connect controller test uses an in-memory repository.
- A GitHub redirect URI mismatch goes to the App's first callback URL, Sign in with GitHub's (see the github module's map).

# Users: module map

**Owns:** users and signing in (spec §2.10): `users` (name, email kept as typed and unique ignoring case, a scrypt password hash `scrypt$N$r$p$salt$key` from `ScryptPasswordHashing`, the wrong tries: how many in a row, the next try allowed at, locked until) and `signed_in_devices` (one row per browser signed in: the SHA-256 of its token only, its user agent and address kind, signed in, last seen and expires, 30 days after the last use, both written at most once a minute). The first user (`FirstUser`, `POST /sign-in/first-user`) is made only while none exists, in one transaction, so two at once make one. `PasswordSignIn` counts a try wrong before checking the password and clears the count once it matches; `domain/wrong-tries.ts` holds the Defaults (3 free tries, then waits of 2, 4, 8 and 16 s answered as 429 with when to try again, never slept on; the 10th in a row locks for 15 minutes, doubling up to a day). An unknown email gets the same answers, hashed against a dummy (`UnknownEmailTries`, in memory). `SignedInDevices` lists, checks and signs out devices; `Passwords` sets a password (the host's `npm run set-password`, `src/set-password.ts`), lifting the lockout and signing out every device; `Accounts` answers `/account`. The cookie (`adapters/http/sign-in-cookie.ts`, `office_signed_in`) is `HttpOnly`, `SameSite=Lax`, `Path=/`, `Secure` only when the request came through the public address over https.

**Extension points:** `SignIns.finish(user, way, request)` is where every way of signing in ends: it asks the `SecondSteps` port (bound to `NoSecondSteps`; the authenticator Task binds its own) and makes the signed-in device. `SignInWays` is the registry of ways (`SignInWay`: its kind, the address kinds it works at, whether it is available); a way's module `add`s itself, and `GET /sign-in` lists those for the request's address kind. Contracts' `SignInWay` and the sign-in answer's `outcome` are discriminated unions (only `password` and `signed-in` now), as is the web's way-kind map (`surfaces/sign-in/sign-in-ways.tsx`). Every later way's callback lives under `/api/sign-in/`, the only path open without a signed-in device.

**Talks to:** the platform's `SignedInRequests` port, bound in `app.module.ts` to `CookieSignedInRequests` through `RequestAccessModule`, which the platform's guard and event stream ask who a request's device is, and whose `onSignedOut` (the `SignedOut` event) closes that device's WebSockets; the platform's `OfficeAddresses` for the address kind (`adapters/http/sign-in-request.ts` maps it to the domain's own copy); the `Schedule` for the time. Publishes `UserCreated`, `SignedIn`, `SignedOut`, `PasswordSet`.

**Traps:** a signed-in device is never called a session, in code, API or database. The domain keeps its own `AddressKind`, since the boundary lint allows it nothing from the platform but `DomainEvent`. Unknown emails' wrong tries are in memory and start again at a restart; a user's are in the database and don't. Other modules' tests boot unguarded (`startTestApplication` binds `EveryoneSignedIn`); a test that needs the guard uses `startUsersApplication` and `signedInCookie` from `index.fixtures.ts`.

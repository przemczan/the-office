# Skills: module map

## Owns

- The skill library (`skills`, `skill_versions`): uploads, skills written in place, skills installed from a Source at a pinned version (`SkillLibrary.install`, `SkillSources`), off until reviewed, "everyone"; updates (`SkillUpdates`: daily check, draft and diff, apply).
- Role skills (`role_skills`, `role_skill_changes` with `changed_by`; `SkillsEarlierRecords`), Project skills found in the checkout (each with its `key`), each session's plugin folder (`SessionSkills`, `session_skills`, `<office-data>/sessions/<session id>/skills/`; `forget`, `sweep`).
- User-only skills (`disable-model-invocation: true`, `isUserOnly`, `PreparedSkills.userOnly`), skill uses (`SkillUses`, `skill_uses`, `SkillUsed`, 7-day window, daily prune `SKILL_USE_PRUNE`), the skill commands a Thread offers (`SkillCommands`).
- Office actions (`SKILLS_OFFICE_ACTIONS` in `SkillOfficeActions`); the raw-byte routes stay on `SkillsController`.

## Talks to

- Engine: `SkillCalled` (counts uses), `OfficeToolRegistry` (imports `EngineModule`, so a test app loading `SkillsModule` loads `TelemetryModule` too). The Engine takes the folder and never reads Skills.
- Notifications' Now through `SkillUpdatesFound`→`SkillLibrary.withUpdate()`; People, Projects and Conversations call it; `SessionPeople` (filled by Conversations).
- Sources' git repositories through `SourceFetcher` on the Office identity (`GitIdentityModule`; URL resolved by `ls-remote --get-url` first), no checkout.

## Traps

- A use counts only once the session's record resolves the name; unknown names and forgotten sessions are dropped.
- The prune removes uses on the shared database: a test running it or storing past uses sets its clock to a year no other file reaches (2002, 2003).
- A Project skill's key is not its listed name; two rows may share one.
- A skill on and for everyone reaches every session on the shared test database: no test stores one; `session-skills.test.ts` uses `everyoneHere` ([testing](../../../docs/testing.md)).
- `SessionSkills.prepare` leaves out a skill removed meanwhile but fails on a listed skill with no files (`SkillVersionNotKept`).
- Tests never reach a real Source (`source-repository.fixtures.ts`); the update check in tests reads only `ownSources`.
- A Source comes from a model's Proposal: `sourceRepositoryProblems` admits only https, ssh, `git@` and file URLs; `GitSourceFetcher` pins transports and never prompts. An unreadable Source is logged and skipped.

# Notifications: module map

## Owns

- Notifications (`notifications`): the kinds tree and routing (`domain/notification-kinds.ts`), each user's routing and timing (Account › Notifications), delivery (`NotificationDelivery`: quiet hours, phone held while at the desk, `PhonePush` bound to `RecordingPhonePush`), collapses and quiet-hours summaries.
- Now and the status strip as one shared read model (`NowService`, pushed whole as `now.changed`), Needs you, Waiting for you, Since you left, Tokens today, the Office status (`show_office_status`).
- Day figures (`DayFiguresModule`: `OfficeDayFigures`, `TaskOutcomeRepository`, `DayFigures`), held apart so Work's Days reads them without a module cycle.

## Talks to

- Reacts to the events of Work, Pipelines, Conversations, People, Engine, Test instances, Actions and Busy work; only Telemetry's Stats calls it (`DayTokenHistory`).
- Ports: `WaitingInConversations`, `PullRequestsWaiting`→`PullRequestRecords`, `SkillUpdatesFound`→`SkillLibrary`, `OfficeUpdateAvailable`→`OfficeUpdates`, `StandInChoicesWaiting`→`StandInChoices`, `OfficeStatusCards`→`ThreadCards`, `OfficeInitiatives`; Work's `FireAlarmService.read`. Bindings in [app.module.ts](../../app.module.ts).

## Traps

- In-app and desktop live in the browser: the service routes per user and sends `notification.raised` to that user's devices alone (`forwardToUser`); the web ignores `phone`.
- Test instance and Action run Outcomes are never batched. Their pointers are new: the previous release can't parse them.
- Delivery runs on The Office's clock (`Schedule`), never `new Date()`; waits are in memory and set again at boot. The old `notifications.channels`, `held`, `phone_pushed_at`, `notification_routing` and `notification_timing` stay for the previous release, no longer written.
- A gathering Notification (`collapsed-outcomes`, `quiet-hours-summary`) is no kind of the tree; it is one user's own; handling it clears only what it replaced for that user.
- Delivery acts only on Notifications the clock has reached; tests raising on clocks of their own (2001, 2100) stay apart; the delivery test keeps its state in fixtures (`ports/delivery.fixtures.ts`).
- Routing, timing and activity rows are by user and shared: tests use users of their own (`OfficeUsersForTests`, `signedInAs` with a random id).
- A Decision raises `needs-you.decision` only when it waits on the user on a Task or in an Initiative's Thread on no Task; never put to a Consultant or in a chat (a test publishing `DecisionOpened` gives its Thread a `home`).
- Waiting for you never joins `needsYou` (no tab title count, no Notification).
- `EventBus.publish` waits for handlers: Now is read and announced in the background (`announceInBackground`). `TokensCounted` reads only `tokensToday` onto the last Now; never make it read Now whole.
- Since you left is not in Now: a change announces `now.changed` even when Now is unchanged.
- "Today" is `officeDayOf`; an Office kind's `shortLine` is made by the same function as its line, never in a person's voice.
- Engine-down and window kinds are per engine id; a window `reset` only once its `resetsAt` came; a used-up window is handled only by `used-up-window-reset` or a later refusal.
- The Stand-in choice raises one Notification per opening of the card, reacting to `StandInChoicesChanged` (not `StageAwaitsStandInChoice`); a test raising it clears it before and after.

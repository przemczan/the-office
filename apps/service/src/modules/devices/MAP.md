# Devices: module map

## Owns

- Connected devices (`connected_devices`, `ConnectedDevices`): the record and its states (Connecting, Connected, Waiting, Disconnected), held by exactly one of a Task, an Action run or a test instance (`connected_devices_one_holder`).
- Connect, pair over wireless debugging (`WirelessDevices`), disconnect, the relay socket per device (`DEVICE_RELAY_PATH_PATTERN`, `DeviceRelayLink` behind `RelayLink`), the Office device helper's use, the sweep.
- Project devices (`project_devices`, `ProjectDevices`): add, pair (in a pairing environment), lend to a Task, hold for a run, give back; state words for `list_projects` (`ProjectDeviceLines`).
- Office action `lend_project_device` (`adapters/office-actions/device-office-actions.ts`).

## Talks to

- Work: `DeviceTasks`→`TaskService`, `TaskConnectedDevices`, `TaskStateChanged`. Run environments: `RunEnvironments.attach`, `RunEnvironmentStarted`/`Stopped`/`Removed`, `PairingEnvironments`. Projects: `RunEnvironmentStart`, `PairingDefinitionExports`, `ProjectDeviceLines`, `ProjectDeviceFeature`, `ProjectRunEnvironmentChanged`, `ProjectFeaturesChanged`.
- Conversations' `SessionThreads` for the session's person; the platform's `WebSocketRoutes`. Bindings in [app.module.ts](../../app.module.ts).

## Traps

- The application never sees a frame, close code or `ws`: frames are the contracts' codec behind the `RelayLink` port; the domain can't import contracts, so `HELPER_NOTICE_CODES` and `SLOW_ROUND_TRIP_MS` mirror them (`devices-relay.test.ts` checks); the `adb-key` frames are built in an adapter behind `AdbKeyInput`.
- `RunEnvironmentStarted` handlers run inside the Task's step: only attach (no step) and wait for READY at most 10 s, never throwing; reconnecting runs there and never starts a run environment.
- A stop forgets the environment before its containers stop; weigh that as the helper ends, not later in the device's lock.
- Relays and run holds live in memory: the sweep (from `office.ts`, never module start) ends open records as tab closed and holds as run ended; holds also end at shutdown and start (the release before reads every open record as a Task's).
- A round trip that didn't matter is dropped, not saved (a 5 s PING never writes).
- adb steps and pairing run detached under their own `adb:<id>` key, never holding the device's lock; each result is weighed against the record as it is then.
- The adb private key and a pairing code never leave the service: only into the helper's or `adb pair`'s stdin, never a record, log, event, response, command line or variable (`project-devices.test.ts` scans them all).
- A wireless phone keeps its endpoint while Waiting; a Waiting wireless record with a null endpoint ends as device unplugged at the next start.
- A Project device is given back only in `ProjectDevices`' `ConnectedDeviceChanged` handler, under the record's lock: it never takes a `ConnectedDevices` lock, calls back in, or throws.
- `ever_connected` is kept on the record, never in memory.
- Lend and hold run the holder check and insert in one transaction holding the Project device's row (`withDeviceLocked`), the insert in a savepoint.
- Task-only paths never see a hold; a run waiting for a USB Android phone is told only after `followAndroidUsb`'s adb steps.
- Agent-facing words never name a Project device's Address or Port.
- `ScriptedAdb` is built, not a fixture: `src/e2e.ts` hooks it into the scripted runtime's `onAttach`; `devicesTestbed` uses it too.
- One device pairs in one environment at a time (`office-<office>-pairing-<id>`); a cut-off pairing finds itself out of `running` and writes nothing more.

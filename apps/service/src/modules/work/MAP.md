**Traps:** Never run git inside a database hold: `InitiativeBranching` makes branches first, judges them in the hold, and removes what the attempt made on any failure, one attempt per Initiative at a time (`KeyedLocks`); the Projects side makes them with `createRef`, never an overwriting `setRef`. Shaping → Backlog is Confirm's alone, outside `NEXT_STATES` so nobody can ask for it: `confirmInitiative` moves an Initiative's Tasks in Shaping in the one transaction of `InitiativeRepository.updateWithTasks`, which `dropInitiative` shares to drop them with a shaping Initiative, the Initiative's row held first and its Tasks' rows after; `addTaskToInitiative` reads the state from the Initiative as held, so no Task joins during either.

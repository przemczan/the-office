# Settings surface: map

## Owns

- Settings (`settings-page.tsx`, the shell's `SectionLayout`): Pipelines and Stage templates (`pipelines/`), Skills (`skills/`), MCP servers (`mcp-servers/`), Engines (`engines/`: Defaults, Stand-in Engines, each kind's fields, accounts, models, Window starts, removal), Office limits (`office-limits/`: limits, Usage, Context policy, Run environments, Test instances, Actions).
- Also: Duties (`duties/`), Office instructions (`office-instructions/`), Prompt templates (`prompt-templates/`), Office identity (`office-identity/`), Users (`users/`), Signing in (`signing-in/`), Telemetry (`telemetry/`), Updates (`updates/`), and First-run setup (`first-run-setup/`, drawn outside the shell at `/setup`).

## Talks to

- The service through `src/api/` (see [the web app's map](../../MAP.md)); the shell's Pipelines kit and flow editor, `OfficeProposalOnFlow`, `EngineTypeAccountFields`, `StandInEngineRows`, `secret-value-input.tsx`, engine and duty words.

## Traps

- Each read of an MCP server's review starts or calls the server: `mcpServerQueries.review` sits outside the library's key, is read once per open review and dropped on close; only `mcp-server.changed` refreshes an open one.
- The grid's rows are levels of the service's kinds tree, keyed as the service keys them: a kind added there needs its row here.
- The library's check gives problems (hold Save) and flags (don't); the Pipeline rows' warning comes from one library check (`GET /pipelines/library/needs-fixing`).
- A Save, Duplicate or Remove awaits only the list (`refreshPipelineList`, exact): awaiting the `["pipelines"]` prefix would hold the address behind every check.
- Saving a Stage template changes no Stage; applying its edit does, to the ticked linked Stages; the dialog decides what changed from the template as it opened (`fieldsChanged`).
- `skill.used` refetches the library list alone, by exact key.
- Secrets and keys never come back: drafts leave them out (keeping them) unless typed or removed.
- Engines are edited as one draft sent whole by `PUT /settings/engines`; `engine.window-start-changed` and `engine.account-changed` re-read exactly, keeping the draft.
- A saved default model no longer listed stays as "<model> · No longer offered".
- Test instance ports are checked with contracts' `testInstanceSettingsSchema` before sending; refusals mark their field.

# Account surface: map

**Owns:** the user's account (`/account`, opened from the top bar's user menu, spec §2.10): "Your account" with their name and email (`userQueries.account`), and "Signed-in devices" (`userQueries.signedInDevices`), most recently used first, as `packages/ui`'s `DataTable` (stacked under 640px): each device's browser in words from its user agent (`browserWords` in `account-words.ts`: "Chrome on Linux", "A browser" when unknown), the kind of address in words (`ADDRESS_KIND_WORDS`: Localhost, Loopback IP, Local network, Public address), when it signed in and was last used, "This device" marked with a badge, and Sign out on each, through the shell's `useSignOut`: another device's reads the list again, this one's lands on the sign-in page. "Authenticator" (`authenticator-section.tsx`) between them: off, with Set up the authenticator; on, with a badge, the recovery codes left, Make new recovery codes and Turn off. Each opens a window (`authenticator-dialogs.tsx`): setting up shows the QR code, drawn here by `uqr`'s `renderSVG` into an `<img>` data address (dark on light in every palette, as scanners need it), the key in groups of 4 to type by hand and the code field, then, once on, the recovery codes this once (`recovery-codes-view.tsx`, with Copy the codes and Download the codes, a text file made in the browser); Turn off takes a code or a recovery code, New recovery codes a code, then shows the new ones. The code field and the refusal with its wait are the shell's (`shell/code-answer-field.tsx`), shared with the code page.

**Talks to:** the service through `api/users.ts` (`GET /account`'s `authenticator`, `POST /account/authenticator`, `/confirm`, `DELETE /account/authenticator`, `POST /account/recovery-codes`, refused as `RefusedAs<SignInRefusal>`); the shell's `useSignOut` (`shell/use-sign-out.ts`, shared with the user menu) and the time words.

**Traps:** a signed-in device is never called a session, in words or names. Signing out another device closes its WebSocket with 4401 and its next request answers 401; nothing here waits for that. The secret and the recovery codes live only in the mutation that answered them and go when its window closes; nothing caches them. Later Tasks add the password, linked identities and passkeys here.

## Talks to

- `api/notifications.ts`, `api/users.ts`, `api/passkeys.ts`, `api/linked-identities.ts`; the shell's `useSignOut`, `CodeAnswerField`, `passkey-words.ts`, `google-words.ts`, `AccountAppearance` and `packages/ui`'s appearance store. See [the web app's map](../../MAP.md).

## Traps

- A signed-in device is never called a session, in words or names.
- Signing out another device closes its WebSocket (4401); nothing here waits for that.
- The authenticator secret and recovery codes live only in the mutation that answered them; nothing caches them.
- A wrong current password counts toward the same slow-down and lockout as signing in.
- A passkey's options are tied to the asking device and live 5 minutes. Tests mock `@simplewebauthn/browser`.
- Notifications settings are the signed-in user's alone: dropped with the cache when the user changes (`use-signed-in.ts`); e2e changes them only as `asOwnUser`.

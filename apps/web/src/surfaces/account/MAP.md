# Account surface: map

**Owns:** the user's account (`/account`, opened from the top bar's user menu, spec §2.10), a `SectionLayout` of sections (`account-page.tsx`'s `SECTIONS`; `/account` opens Profile): Profile (`profile-section.tsx`: the name and email from `userQueries.account`, Save sending `PATCH /account` and setting the account query from the answer, Discard; and the Password card, the current password and the new one twice, `POST /account/password`, which signs out every other device, the list then read again), Appearance (`appearance-section.tsx`, moved from Settings: the Palette card, a choice per palette in `PALETTES`, each previewed by `PalettePreview`, or following the system, and the Density card, a choice per density in `DENSITIES`, previewed by `DensityPreview`, through `useAppearance`, which the shell's `AccountAppearance` saves to the account) and Signed-in devices (`signed-in-devices-section.tsx`, `userQueries.signedInDevices`, most recently used first, as `packages/ui`'s `DataTable`, stacked under 640px: each device's browser in words from its user agent, `browserWords` in `account-words.ts`, "Chrome on Linux", "A browser" when unknown; the kind of address in words, `ADDRESS_KIND_WORDS`; when it signed in and was last used; "This device" marked; and Sign out on each, through the shell's `useSignOut`: another device's reads the list again, this one's lands on the sign-in page).

**Talks to:** the service through `api/users.ts`; the shell's `useSignOut` (`shell/use-sign-out.ts`, shared with the user menu), its page heading and toasts, and the time words; `packages/ui`'s appearance store, whose choices the shell's `AccountAppearance` (`shell/account-appearance.tsx`) saves.

**Traps:** a signed-in device is never called a session, in words or names. Signing out another device closes its WebSocket with 4401 and its next request answers 401; nothing here waits for that. A wrong current password is answered in the account's words ("The current password is wrong."), but it counts toward the same slow-down and lockout as signing in. Later Tasks add their sections here: the authenticator, recovery codes, linked identities and passkeys.

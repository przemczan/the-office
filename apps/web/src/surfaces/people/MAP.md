# People surface: map

## Owns

- The People grid (the Caretaker pinned first, `people-order.ts`; the set-up hint while nobody is hired, `office-setup-hint.tsx`) and a person's page: Overview, Work, Conversations, Memory, Role card (view and `role-card-form.tsx`), Avatar (`avatar-block.tsx`).
- Hiring from a preset (`hire-dialog.tsx`), from scratch, or from a Proposal's card (`/hire?proposal=…`).
- The Role card's Engine group (`engine-type-rows.ts`, `EngineFields`, "Runs on" `EngineThatApplies`), MCP servers (`role-card-mcp-server-fields.tsx`, `role-mcp-servers.ts`), Authority (`role-card-authority.tsx`, `AuthorityView`, `AuthorityFields`).
- The Authority tab (`/authority`, `authority-tab.tsx`, `authority-table.ts`, `authority-row-parts.tsx`; `people-tabs.tsx`).

## Talks to

- The service through `src/api/` (see [the web app's map](../../MAP.md)); paged lists with `ShowMore`/`api/pages.ts`; the shell's `role-card-words.ts`, `duty-words.ts`, `useAskInChat`, `ImageRow`, `worksWithLines`.

## Traps

- MCP servers are kept by the MCP servers module: Save sends the card only when it changed (an unchanged one adds an empty version), then `PUT /mcp-servers/:name/roles` per server whose tick changed; hiring assigns after, with the new key.
- The card keeps only set tool settings: choosing `mcpToolDefault` removes the key; unticking a server drops its tools' keys. A tool may consult the card's own Role only when the default names it.
- Authority: the card keeps only set rows; picking the default or Reset removes a row (`withAuthorityRow`). The card still carries `hardSwitches`; the service ignores them once `authority` is sent.
- The Authority tab saves each changed person's card in its own request; a refusal keeps those edits; leaving with unsaved edits asks first (`useBlocker`).
- The Caretaker's fixed fields show disabled (`FixedForTheCaretaker`); it has no Let go.
- Duties are set in Settings, never on the card; the "Runs on" cascade sits under its own `ENGINE_CASCADE` key.
- The Memory tab names a note's Task by the service's `taskTitle`, loading no Task.

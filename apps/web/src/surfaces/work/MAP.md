# Work surface: map

## Owns

- The Work board (`board-columns.ts`, `board-card.tsx`, `card-marks.ts`, filters `board-filters.ts`/`filter-bar.tsx`, Saved views, grouping `board-grouping.ts`/`board-groups.ts`, Initiative blocks `board-blocks.ts`).
- Ideas, the Initiatives tab (`initiatives-board.tsx`), the Archived tab (`archived-page.tsx`), Pull requests, CI, Days, and the Work tabs and counts (`work-tabs.tsx`, `work-tab-counts.ts`).
- The Task page (`task-page.tsx`): record tabs and folds (`record-fold.tsx`, `record-folds.ts`), Needs you card, Before Ready, planning parts, commit message, Kinds and Bugs, Pipeline rail and Stage history (`pipeline-rail.tsx`, `pipeline-progress.ts`, `stage-history-window.tsx`, `run-details.tsx`).
- On the Task page too: diagram, "Edit for this Task", Start and the queue (`start-action.tsx`, `queue-parts.tsx`), conversation tabs (`task-conversation.tsx`, `person-tab.tsx`), Devices, Engine fold, History.
- The Initiative page (`initiative-page.tsx`): Task graph (`task-graph.tsx`, `task-graph-routes.ts`), planning words, Pipelines block and editor, Start Ready Tasks, Pause/Resume, Back to Shaping, membership, test instances, Engine fold, conversation (`initiative-conversation.tsx`).
- `RecordAction`s (`record-actions.tsx`): each head action defined once, shown as a button and in the More menu.

## Talks to

- The service through `src/api/` (see [the web app's map](../../MAP.md)); writes to Tasks, Ideas and Initiatives go through `callOfficeAction`.
- The shell's Work kit (`shell/work/`), Pipelines kit, Decision and Gate cards, test-instance and device parts, `ImportIssuesDialog`.

## Traps

- `GET /tasks` answers board Tasks as `TaskSummary` (no long texts); read the Task by id for those. Anything that looks a Task up by id or may name an archived one reads `useEveryTask()`.
- `isOnBoard` keeps Off-board Tasks, Shaping Tasks and archived Tasks off the board, counts and search; blockers and graphs still read them. `NOT_STARTED` holds Shaping, so Shaping checks itself (`PARTS_EDITED_IN`).
- Reported met is read from `GET /tasks/:id/stages` (`definitionOfDoneMet`), never worked out here.
- The conversation's tab and the first tab are chosen once; only the address moves them. Looking at a tab opens nothing (`useFirstMessage` opens the Thread on the first message).
- The conversation drawer (≤900px) is always mounted, hidden by `visibility`; links open or close it by what the address gained.
- `use-timeline-scroll.ts` never moves a reader who scrolled up; only the log scrolls, never the page.
- A card's popover lies on the body but React bubbles its events: card handlers act only on the card's own DOM.
- An Initiative block is a `group`, never a region or heading: e2e tests find columns by region and `h3`; lookups of another `group` must be exact.
- Task graph routing is fitted to `.task-graph-columns`' 44px gap (`EDGE_ROUTING`); arrowheads are paths, never SVG markers; `EDGE_ROUTING.stroke` matches the CSS stroke.
- The design system's Button styles itself inline: tinted and ghost classes use `!important`.
- Drop dialogs keep their counts from the click on (events land before the answer).
- A folded body stays mounted; whatever starts from a fold's side and must be seen calls `fold.open`. Only the Needs you card carries the Decision's element id.
- Command outputs are read per run under their own key; Days' past queries are `staleTime: Infinity` and today comes from the service, never the browser's clock.
- The working mark keeps its least width (`.board-card-working`, basis 0); the Stage label is `contain: inline-size`.
- Refs and workflow files are read under `["manual-workflows", …]`, apart from `["ci-runs"]`.
- Devices: a serial board's key holds a tab-lived id (match again by USB ids); a pairing code is never kept (no query key, URL, storage or log); nothing on the page closes a relay on unmount.
- Tests find a person's Model and Effort selects through their `role="group"`; register device transports on top of the module's.

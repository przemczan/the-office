# Projects surface: map

## Owns

- The Projects page (`projects-page.tsx`: list beside the open Project in the shell's `SectionLayout`, `NoProjectOpen`), Add a Project (`add-project-dialog.tsx`, `add-project-source.ts`, `repository-clone-step.tsx`, `github-repository-picker.tsx`, `project-details-step.tsx`), and asking Devops to onboard (`AskDevopsButton`).
- A Project's page and sections: Overview (`overview/`, tiles), Files and the Repository file browser (`repository-files/`, `file-preview.tsx`), onboarding (`onboarding-block.tsx`, `OffBoardTaskStatus`), Commands, Environment, Run environment.
- More sections: Engine (`engine-stand-ins.tsx`, `engine-people.tsx`), Pipelines (`pipelines/`), Features (`features-block.tsx`), Devices (`devices-block.tsx`), Test targets and Test instances, Actions (`actions/`, `run-window.tsx`), GitHub issues, Appearance, Skills, Server values, Recent activity.
- The Branch picker (`branch-picker.tsx`), run environment words (`run-environment-words.ts`).

## Talks to

- The service through `src/api/` (see [the web app's map](../../MAP.md)); the shell's Pipelines kit, test-instance and device parts, `ImportIssuesDialog`, `StandInEngineRows`, engine words.

## Traps

- `/projects` is the parent route of every Project's (the list stays beside the open one); Overview has no redirect (it would drop `?chat=…&thread=…`); `.project-page` is the `page` container; `ProjectPage` shows `Missing` for an unknown Project.
- Add a Project lays out by its own `add-project` container (the window sits on the body).
- `off-board-task.fixtures.tsx` waits for reads in a second `act`, as reads start once the first render commits.
- The Run environment tab hides while Off; turning it On is Features' row.
- The design system's `SegmentedControl` can't disable a segment: Test targets' unbuilt kinds are dimmed and ignored by `onChange`.
- A test target's Secret value is kept under its name: renaming loses it until typed. The variables editor is keyed on the saved environment; another tab's save resets it.
- The GitHub issues block reads `GET /projects/:id/issues` with `retry: false` under `OPEN_ISSUES`, never the Projects' key.
- A `Switch` with a `label` doesn't name it and flips on any click in the label: rows use bare `Switch`es in a `role="group"` named by the row; `design-system/` stays as exported.
- Commands may be blank ("Not set"); a set one can't be cleared and a key never changes (the pencil never offers it). The before and after publishing lines are the exception: blank clears.
- The force needs a Project default: going back to "Office's default" sends `default` and `force` null together after asking; a new engine type sends the force fitted (`forceOnType`).
- `AppearanceBlock` holds a draft only while it differs from the saved mark; How it looks draws `.appearance-sample-item`, never `.project-head` (tests find the real ones). Pass `ProjectMark` the whole record (it shows the Icon only with `id` and `icon`).
- No event follows Server values: a save puts the answer in the query, under the Project's key.
- `skill.used` refetches that Project's skills by exact key only.
- The Action editor keeps one draft across kinds and sends only the chosen kind's; Leaves the workstation is kept as sent.
- Devices: a pairing's end is learned only from `project-device.changed`, never the Pair answer.
- The Branch picker reads branches, Initiatives and Tasks only once opened.
- Recent activity reads `projectQueries.settingChanges` under the Projects' key.

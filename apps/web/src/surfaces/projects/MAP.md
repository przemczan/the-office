**Traps:** The GitHub issues section learns whether the repository is on GitHub only from `GET /projects/:id/issues`, which lists GitHub (up to 500 issues) each time it is read, so the block reads it with `retry: false` under `OPEN_ISSUES`, never under the Projects' key. The write-back and auto-import switches are bare `Switch`es in rows with `role="group"` named by the row, as a `Switch` with a `label` doesn't name it. The variables editor is keyed on the saved environment, so a save, here or elsewhere, starts it again from the Project's, a typed Secret value cleared and a kept one shown as set; an edit in progress is lost when another tab saves. A Project's commands may be not set (blank): step 2 marks them optional in one `Field` with a hint, the Commands block shows "Not set" with its pencil to set one, and the environment check shows "Not set" for a skipped one, each step by the command's name; the service refuses clearing one once set, and a command added later can't be blank. The before and after publishing lines are the exception: blank shows "None" and saving blank clears one. A command's key is fixed once added, so the pencil never offers it; the rules (key, name, line) are the service's, shown as it answers. Add a Project lays its columns out by its own `add-project` container, as the window sits on the body, outside the page's. From GitHub fills the body's height so only the rows scroll; the other steps leave the body to scroll. A folder's Project has no Repository URL, so its repository is never marked Already added. The colour input shows while the mark's colour is a custom one, so that colour is all the state Custom has; choosing Custom again keeps it. Overview has no redirect, as one would drop a link's `?chat=…&thread=…`; `ProjectPage` reads the Project and shows `Missing`, so an unknown Project says so at every section's address. `Switch` with a `label` wraps a `<span role="switch">` in a `<label>` that flips it on a click anywhere and doesn't name it, and `design-system/` stays as exported: a skill row keeps a bare `Switch` beside its text, so selecting a path changes nothing, and its `role="group"` carries the skill's name for screen readers and the tests. The Project default can't be cleared while "Use for every Role" is on, so the block leaves out its "Office default" choice then; the switch needs a Project default. `AppearanceBlock` holds a draft only while it differs from the Project's mark, so a change from another tab shows when nothing is being edited; only How it looks shows the draft, and the page head above keeps the saved mark until Save. `MarkPicker` is handed the Project's name alone, so its tile shows the letters even with an Icon, which How it looks shows instead. How it looks shares the head's styles and the card's `.project-tile` classes, never `.project-head` or `.project-card`, which the real page and card own and the tests find them by. Every other mark is drawn by `ProjectMark` from a Project's record, so `project.mark-changed` and `project.image-changed` refreshing the Projects' key is what updates them. Only a Project's page and card show `ProjectLogo`, which falls back to `ProjectMark`; `ProjectMark` shows the Icon only when it is handed the Project's `id` and `icon`, so pass it the whole record. No event follows a Project's Server values, so a save puts the answer in the query; the query sits under the Project's key, so the library's events, which refresh the Projects, refresh it too. `skill.used` for a Project skill refetches that Project's skills alone, as an exact key, so nothing else under `["projects", id]` is read again on every use.

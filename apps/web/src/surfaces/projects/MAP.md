# Projects surface: map

**Owns:** the Projects page (a card each with its onboarding badge; adding one by asking Devops to onboard it, `AskDevopsButton`, or the user's own form, "Where it is" a folder, a git URL or From GitHub (`github-repository-picker.tsx`: the repositories the App is installed on, searched by name, picking one starting its clone as a typed URL does; signed out or not registered, a line linking Settings › Office identity); a URL is cloned first, `repository-clone-step.tsx`, its progress read live from `repository-clone.changed`, then the form opens with the clone's path, Repository URL, name and default branch, the base branch picked from the remote's) and a Project's page (its Repository URL in the head when cloned, and a line on which part of the Office identity its base branch's remote needs and what is missing, `remote-needs-words.ts`, read under `REMOTE_NEEDS`, apart from the Projects' key, which `github.changed` refreshes): its onboarding (`onboarding-block.tsx`, from Work's `GET /onboardings`, joined by Project and refreshed by any Task event since it sits under the Tasks' query key), commands, install inputs, publishing mode, default Pipeline, the Engine block (`engine-block.tsx`: the engine cascade's Project levels, the Project default, "Use for every Role" and the Project's Role overrides, each saved at once, with the engine and model pair from `shell/engine-model-fields.tsx` that the Role card uses too; the engines offered come from `/role-card-options`), the environment check, the Project's skills (`skills-block.tsx`: the switch for all of them at the head, then a row each with its own switch, saved at once by the skill's key, each row's mutation in one scope so answers land in order), and the MCP servers' Server values with the Project's own (`server-values-block.tsx`; every value of a server is sent back, a kept secret by its name alone, as one left out is cleared). It reads the service through `src/api/` (see [the web app's map](../../MAP.md)).

**Traps:** `Switch` puts its `label` in a `<label>` round a `<span role="switch">`, which doesn't name it, and `design-system/` stays as exported: each skill row's `role="group"` carries the skill's name for screen readers and the tests. The Project default can't be cleared while "Use for every Role" is on, so the block leaves out its "Office default" choice then; the switch needs a Project default. No event follows a Project's Server values, so a save puts the answer in the query; the query sits under the Project's key, so the library's events, which refresh the Projects, refresh it too.

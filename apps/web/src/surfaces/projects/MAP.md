# Projects surface: map

**Owns:** the Projects page (a card each with its onboarding badge; adding one by asking Devops to onboard it, `AskDevopsButton`, or by path) and a Project's page: its onboarding (`onboarding-block.tsx`, from Work's `GET /onboardings`, joined by Project and refreshed by any Task event since it sits under the Tasks' query key), commands, install inputs, publishing mode, default Pipeline, the environment check, the Project's skills, and the MCP servers' Server values with the Project's own (`server-values-block.tsx`; every value of a server is sent back, a kept secret by its name alone, as one left out is cleared). It reads the service through `src/api/` (see [the web app's map](../../MAP.md)).

**Traps:** no event follows a Project's Server values, so a save puts the answer in the query; the query sits under the Project's key, so the library's events, which refresh the Projects, refresh it too.

# Sign-in surface: map

## Owns

- The sign-in page (`/sign-in`), drawn bare by `RootLayout` (no shell, no event stream): "Create the first user" (`first-user-form.tsx`, setup token first) or "Sign in to The Office" with the ways `GET /sign-in` lists (`sign-in-ways.tsx`'s `SIGN_IN_WAYS`) and those `unavailable` with where they work.
- Ways: passkey (`passkey-way.tsx`), password (`password-way.tsx`, then `first-password-form.tsx` on `set-password`), Continue with GitHub (`github-way.tsx`), Google (`google-way.tsx`), OpenID Connect (`openid-connect-way.tsx`); the code page (`/sign-in/code`, `code-page.tsx`); `OfficeName`.
- `useSignedIn` (`use-signed-in.ts`): an exhaustive switch on the outcome; signed in, it clears every cached query, reads the account and its appearance, then goes to `?returnTo=` (`returnPathOf`).

## Talks to

- `api/users.ts` (`sendToApiRefusedAs`), `api/passkeys.ts`, `api/linked-identities.ts` (`continueWith`); the shell only for `OfficeMark`, `RefusalAlert`, `CodeAnswerField`, `useTryAgainWords` and time words. See [the web app's map](../../MAP.md).

## Traps

- `SIGN_IN_WAYS` is a mapped type over `SignInWayKind`: a new kind fails to compile until it has its view.
- Continue with GitHub is never worded Sign in with GitHub (that is The Office's git identity).
- The pending sign-in rides an `HttpOnly` cookie the page never sees; once ended, `POST /sign-in/code` answers 401 and `sendToSignIn` returns with the code page's own `returnTo`.
- `RootLayout` draws both pages bare by route id (`BARE_PAGES`).
- The query parameter is `returnTo`, never `then` (a thenable search object; `unicorn/no-thenable`).
- The one-time password is held only in the set-password form's memory; Back forgets it.
- Tests mock `@simplewebauthn/browser`; e2e uses a CDP virtual authenticator.

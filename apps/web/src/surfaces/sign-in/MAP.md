# Sign-in surface: map

**Owns:** the sign-in page (`/sign-in`, spec §2.10), the one page shown before signing in, bare: `RootLayout` (`shell/root-layout.tsx`) draws it outside the shell, so no rail, top bar, strip or event stream. `GET /sign-in` (`userQueries.signInPage`) says whether The Office waits for its first user and which ways work at the address the page was opened at. At first run the page is "Create the first user" (`first-user-form.tsx`: Name, Email, Password, every refusal reason in `RefusalAlert`; a 409, someone else created the first user meanwhile, reads the page again, which then offers signing in); otherwise "Sign in to The Office" with only the listed ways, each drawn by its kind from `SIGN_IN_WAYS` (`sign-in-ways.tsx`), a mapped type over the contract's `SignInWayKind`, so a kind added to `signInWaySchema` (Continue with GitHub, Continue with Google, a passkey) fails to compile until it has its view. The password way (`password-way.tsx`) shows the service's refusal words and, once wrong tries cost a wait or locked the password, when to try again (`sign-in-words.ts`: "Try again in 16 seconds." counted down each second up to a minute, "Try again at 14:32." beyond), its Sign in button waiting until then. A sign-in's outcome goes through `useSignedIn` (`use-signed-in.ts`), an exhaustive switch on `signInOutcomeSchema`'s `outcome`, which a second step (an authenticator code) joins with its Task: signed in, it clears every cached query (they may be another user's) and replaces the address with `?returnTo=`, through `returnPathOf` (`api/users.ts`), a path of this app only, else home.

**Talks to:** the service through `api/users.ts` (`GET /sign-in`, `POST /sign-in/first-user`, `POST /sign-in/password`, the latter through `sendToApiRefusedAs`, which hands the checked `signInRefusalSchema` body over as `RefusedAs`); the shell only for `OfficeMark`, `RefusalAlert`, `useClock` and the time words.

**Traps:** the cookie is `HttpOnly`, so the page never knows it is signed in until a request answers; what sends a browser here is a 401 anywhere (`SignedOut`, `app.tsx`) or the event stream's 4401. The query parameter is `returnTo`, not `then`, which would make the router's search object a thenable (oxlint's `unicorn/no-thenable`). The fields are `required` and the email `type="email"`, so the browser checks them before the service's own reasons show.

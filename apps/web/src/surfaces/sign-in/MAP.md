# Sign-in surface: map

**Owns:** the sign-in page (`/sign-in`, spec §2.10), the one page shown before signing in, bare: `RootLayout` (`shell/root-layout.tsx`) draws it outside the shell, so no rail, top bar, strip or event stream. `GET /sign-in` (`userQueries.signInPage`) says whether The Office waits for its first user and which ways work at the address the page was opened at. At first run the page is "Create the first user" (`first-user-form.tsx`: Name, Email, Password, every refusal reason in `RefusalAlert`; a 409, someone else created the first user meanwhile, reads the page again, which then offers signing in); otherwise "Sign in to The Office" with only the listed ways, each drawn by its kind from `SIGN_IN_WAYS` (`sign-in-ways.tsx`), a mapped type over the contract's `SignInWayKind`, so a kind added to `signInWaySchema` (Continue with GitHub, Continue with Google) fails to compile until it has its view; "or" on a rule between two ways, then each way set up that doesn't work at this address (`unavailable`), its reason in words with a link to where it works (`shell/passkey-words.ts`, shared with the account). The passkey way (`passkey-way.tsx`): "Sign in with a passkey", no email asked, `POST /sign-in/passkey/options`, then `@simplewebauthn/browser`'s `startAuthentication`, then `POST /sign-in/passkey` and `useSignedIn`; the browser's window closed (`NotAllowedError`, `AbortError`) is a quiet line, a refusal the service's one answer, and a browser without WebAuthn (`browserSupportsWebAuthn`) says so in place of the button. The password way (`password-way.tsx`) shows the service's refusal words and, once wrong tries cost a wait or locked the password, when to try again (`shell/try-again-words.ts`: "Try again in 16 seconds." counted down each second up to a minute, "Try again at 14:32." beyond), its Sign in button waiting until then. A right one-time password answers `set-password`: the password way then shows `first-password-form.tsx` in its place ("Set your password": the new password twice, the two compared as typed, then `POST /sign-in/set-password` with the one-time password again, which only this form's memory holds; Back forgets it). Every other outcome goes through `useSignedIn` (`use-signed-in.ts`), an exhaustive switch on the rest of `signInOutcomeSchema`'s `outcome`: signed in, it clears every cached query (they may be another user's), reads `GET /account` and shows its appearance (`adoptAccountAppearance`), so the shell's first paint is the user's own, then replaces the address with `?returnTo=`, through `returnPathOf` (`api/users.ts`), a path of this app only, else home; `code-needed` goes to the code page (`/sign-in/code`, `code-page.tsx`, bare too, keeping `?returnTo=`): "Authenticator code" with the shell's `CodeAnswerField` (6 digits, `inputmode="numeric"`, `autocomplete="one-time-code"`, and "Use a recovery code"), the refusal and its wait, and Back to sign in. Continue with GitHub's and Google's callbacks land there by the service's redirect. `OfficeName` (`office-name.tsx`) heads both pages.

**Talks to:** the service through `api/passkeys.ts` (the passkey sign-in) and `api/users.ts` (`GET /sign-in`, `POST /sign-in/first-user`, `POST /sign-in/password`, `POST /sign-in/set-password` and `POST /sign-in/code`, the latter three through `sendToApiRefusedAs`, which hands the checked `signInRefusalSchema` body over as `RefusedAs`); the shell only for `OfficeMark`, `RefusalAlert`, `CodeAnswerField`, `useTryAgainWords` and the time words.

**Traps:** tests mock `@simplewebauthn/browser` (jsdom has no WebAuthn); the e2e signs in with a CDP virtual authenticator. the code page's pending sign-in rides in its own `HttpOnly` cookie the page never sees; once it has ended, `POST /sign-in/code` answers 401 and `sendToSignIn` (`signed-out.ts`) goes back to `/sign-in` with the code page's own `returnTo`. `RootLayout` draws both pages bare by their route ids (`BARE_PAGES`). The cookie is `HttpOnly`, so the page never knows it is signed in until a request answers; what sends a browser here is a 401 anywhere (`SignedOut`, `app.tsx`) or the event stream's 4401. The query parameter is `returnTo`, not `then`, which would make the router's search object a thenable (oxlint's `unicorn/no-thenable`). The fields are `required` and the email `type="email"`, so the browser checks them before the service's own reasons show.

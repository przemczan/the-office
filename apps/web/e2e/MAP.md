# Web end-to-end tests: map

**Owns:** the Playwright tests and what they share: `serve-office.ts` starts the built service on the scripted engine, `office-database.ts` reaches the e2e database (for seeding what the UI can't yet make), `office-data.ts` is the fixed e2e Office data directory, `temporary-repository.ts` makes a Project's repository, with a bare `origin` its `main` tracks when a test needs a remote (`createTemporaryRepositoryWithRemote`, read back by `fileOnRemote`), and commits to it, `git-host.ts` serves bare copies of one on the made-up `https://git.example.test/` (the service's git reads it as a local folder by `insteadOf` in `GIT_CONFIG_COUNT` variables that `serve-office.ts` sets, since a Repository URL is never a local path), `desktop-notifications.ts` the browser's Notification as a recording with the tab's focus set by the test, `fake-github.ts` starts the service's fake GitHub server (`serve-fake-github.fixtures.ts`, run from source with tsx, a dev dependency, since fixtures are left out of the build) on port 4391 before the service, which `serve-office.ts` points at it by `OFFICE_GITHUB_URL`/`OFFICE_GITHUB_API_URL` and stops with it, its repositories' clone URLs on `git-host.ts`'s host (The Office refuses the fake's http website as a remote); tests reach it only over HTTP, so `installApp` installs the App through the fake's own control route, `controlPullRequest` changes a pull request's checks, merge state or head, refuses its merges until allowed again, or sets its repository's merge settings, and `grantPermissions` has an installation accept permissions (`installApp`'s default grants lack Checks, Commit statuses and Actions, so the Office identity card and Work › Pull requests ask for them until granted and Check again); the fake serves no git, so no Publish reaches it: Work › Pull requests' test (in `office-identity.e2e.ts`'s serial describe, as it needs the sign-in) adds a Project, then points its `origin` at the fake's repository (the watch reads the remote's URL and never fetches), opens the pull request on the fake from the Task's `office/<task id>` branch with the signed-in user's token read from `github_sign_in`, which the watch adopts, and presses Refresh until a round reads it (a refresh within 10 s of the last round runs none); the next test there merges one with Squash and merge after GitHub refused it once (`refuseMerge`, then `allowMerge`) and closes another, each read by a round first, as Merge sends the head commit a round read; `office-identity.e2e.ts` checks Add a Project's From GitHub before the App is registered, registers it through the fake from Settings › Office identity, signs in, works Add a Project's GitHub list (installing repositories with their `pushedAt` and `description`, holding the service's answer back with `page.route` for the loader, a repository never served for a failed clone), then signs out (a serial describe, signing out in `afterAll` too), `ssh-host.ts` the one host key the service's scanner finds on every host (`OFFICE_E2E_HOST_KEY`, read by `apps/service/src/e2e.ts`, since no ssh server runs), a host made Unconfirmed by cloning from an ssh URL on a `.invalid` host, `skill-source.ts` a bare repository to install a skill from (by a `file://` URL, with the files hash a seeded Proposal needs), `top-bar.ts` opens the top bar's Create and picks Task or Idea, and `sessions.jsonl` holds the scripted sessions. `mcp-servers.e2e.ts` reviews the service's own fake stdio MCP server (`apps/service/src/platform/mcp/fake-stdio-mcp-server.fixtures.ts`, run by this Node, `--fail` to fail with its token on standard error); a review opens no session, so it runs in parallel. `fake-mcp-server.ts` holds its path and tools and adds it to the library, or adds it and turns it on through the API (review, then the state with its digest), for the Role card's test in `people.e2e.ts` (which unassigns it after, so Ola's later sessions start without it) and a Project's Server values in `projects.e2e.ts`. `office-checkout.ts` makes the e2e service's own checkout (`OFFICE_E2E_CHECKOUT`), two commits behind a local upstream, and `serve-office.ts` sets `OFFICE_UPDATE_FOLDER` as the launcher would.

**Traps:** one run at a time per host or per run environment: on one host the ports (4390, 4391), the database and the `/tmp` folders are shared by every checkout, and `serve-office.ts` clears them, so it takes port 4391 first and a run that loses it stops before clearing anything. Each Task's run environment has its own ports, `/tmp` and Postgres, so Tasks' runs there never meet; it needs no `.env`, since its compose file sets `DATABASE_URL` (which wins over a `.env`), and an Agent runs e2e there through `run_project_command`, never in its own shell on the host. `playwright.config.ts` takes half of `availableParallelism()` as its workers (one in the 2-CPU run environment), since Playwright's own default counts the host's cores and starves a capped container into timeouts. On one worker the files run in name order on one Office, so a test finds what earlier files left (Ideas, Tasks, skills) and names its own things in full rather than assuming it is alone. the service's log (Nest's warnings, such as a daily job that failed) goes to `e2e-results/service.log`, rewritten each run (Playwright shows only its standard error, where errors go); `apps/service/src/e2e.ts` gives its testing module the service's `OfficeLogger`, whose own logger would show errors alone. Sign in with GitHub is the Office's and the files share one database, so every test needing that sign-in lives in `office-identity.e2e.ts`'s serial describe, between signing in and out. The scripted engine hands out `sessions.jsonl`'s scripts in the order sessions open, across files running in parallel, so every test that opens sessions lives in `people.e2e.ts`, the one serial file, its script in order; a session waits at each `send` step, so one mid-turn keeps a Stage running until the test writes. A refused turn's end can carry `resetsInSeconds` on its step, so its usage window resets that long after the replay reaches it and a test sees the Task resume by itself (the usage-window test near the end of `people.e2e.ts`, @full); a Stage Thread reads the context after every turn, a refused one too, so its script has a `read-context-usage` step. The last test of `people.e2e.ts` (@full) adds a second Claude Code engine as the only Stand-in Engine, so the session whose turn the first engine refuses is resumed there in the same run (its next script a `resume`, held at a `wait` mark while the test reads the Task page, the Stage history and the Live view), and removes that engine at its end; its refusal resets 5 s on, so the `queue` project after it finds the first engine free. One engine's scripts serve every Claude Code engine, so a stand-in's resume takes the next script as any session does. A script's `wait` step holds its replay, such as a Process's output between turns, until the test posts its mark to `POST /api/e2e/marks/:mark`, a test-only route that `apps/service/src/e2e.ts` alone registers (`ScriptedSession.reach` on every session), since the scripted sessions run inside the service; the Process test at the end of `people.e2e.ts` opens its view late, then releases the output and the end. A script names places by placeholder but never a record by id, so a session that names Tasks by id (the Planner's in an Initiative's planning Thread) works on Tasks made through the API and then given the fixed ids its script names, in one statement over every row naming them (`giveTasksFixedIds`). Each engine has its caps and Office limits' Save (`settings.e2e.ts`) names every engine, so a test adding an engine (in `people.e2e.ts`, since a Settings › Engines Save sends every engine) removes it at its end through `DELETE /api/settings/engines/:engineId` (`removeEngine`) when nothing later needs it; the remove dialog's test moves references to an engine of its own, never a shared one. Its first test works the fresh Office's People (only the Caretaker, Sam): the set-up hint, the Hire dialog's duties, Sam's set-up Thread with its draft (nothing sent, so no session opens), and a seeded `office-setup` Proposal hiring Jan and Ada on their presets' default duties; the next test hires Ola, Bob and Marta. No e2e test gives a duty to another Role than its default, since later tests rely on the defaults. That file is also the only one that hires, so a test that needs someone hired (an Agent Stage's Role, Edit for this Task's flow editor (a Stage's panel, `flowPanel`, picked on the canvas's "Flow" region; an MCP tool's narrowing needs Devops hired, as Consult Devops is its default), Settings › Engines with a Role card picking an API endpoint's model) lives there too. A Stage failing with no retries left while the CTO is hired opens their Consultation, a session of its own: the sign-in Task's failed Publish does, so its test waits for Bob to pass it on. `queue.e2e.ts` runs alone after every other file (its own Playwright project), since any release weighs the Office's one queue; it seeds queued Tasks in the database and empties the queue after each test, since a Start that queues releases the whole queue (as does any reading of the windows), starting any seeded Task whose desk is free and opening its sessions, and sounds the fire alarm, which pauses every file's started Tasks, holding each at the all clear so no walk starts. A Task's conversation shows no panel until the Planner is hired, so a test in `work.e2e.ts` that reads one, run alone, needs `people.e2e.ts`'s hiring test before it (`--workers=1`, with `-g` naming both). The e2e files share one database, so titles must differ across files (`getByRole` matches substrings), a list's count or empty state holds only narrowed to the test's own Project, the Office instructions are saved only by `settings.e2e.ts`, which empties them again as every file's sessions would get them, Resolve's Brief (a Prompt template every Resolve Stage renders) is saved only by `settings.e2e.ts`, which resets it to its default in a `finally`, and the Notification routing is changed only on "Alarm lifted with work waiting", which nothing raises, and given back. What only an Agent's session makes (a Consultation, a Proposal, a Link card) is seeded in the database in the service's own shape (a Proposal's new Role keeps its skills beside the card), with its `thread_messages` row; a proposed hire takes a title no preset has. A Proposal of a Pipeline's routes is seeded with its `routes` (each changed Stage's routes as they were and as proposed) in the Thread Ask Nina opens, which sends nothing, so no session opens; Show it on the flow and the banner's Apply change need none either. A scheduled Office update or restart holds every Start and Stage, and goes ahead (stopping the service) once nothing is busy: `updates.e2e.ts` runs alone after the queue project, keeps an environment check busy throughout, and cancels what it schedules (an update, then a restart, which `OFFICE_UPDATE_FOLDER` allows). Playwright puts no files on the clipboard, so a test pasting an image dispatches a `ClipboardEvent("paste")` with a `DataTransfer` holding the file on the message box (`people.e2e.ts`'s pasted screenshot, a `page.screenshot` named `image.png` as a browser names one); the scripted engine keeps only an image's name, media type and size, and its replay never compares a message's content, so the session's script needs no image.

**Signed in** (spec §2.10): every request needs a signed-in device, so the `setup` project (`sign-in.setup.ts`) runs first, whatever the command line picks, as every other project depends on it: on the run's fresh Office it gets a setup token from the built host command (`node ../service/dist/setup-token.js --quiet` against the e2e database), tries a wrong one first, creates the shared e2e user (`E2E_USER` in `e2e-user.ts`) through the first-user page, walks First-run setup (Skip, Skip, Off, Finish, a screenshot each) and saves their signed-in device to `E2E_STORAGE_STATE` (`e2e-results/.auth/user.json`, git-ignored), which `playwright.config.ts` gives every other project as `storageState`; the built-in `page`, `request` and any context a test makes take it from `use`, and the ones made by hand (`office-identity.e2e.ts`'s `playwright.request.newContext`, `people.e2e.ts`'s `browser.newContext`) name it too. `sign-in.e2e.ts` starts each test not signed in (`NOT_SIGNED_IN`) and signs in through the page (`signInWithPassword`), with its own devices, since signing out the saved one would sign out every file. **Trap:** `serve-office.ts` starts the service without `OTEL_*` variables (the run environment sets `OTEL_SDK_DISABLED`), so its telemetry is Settings › Telemetry's, off until chosen, and the card isn't read-only. All files share one user, and wrong passwords count against them (3 free, then waits, then a lockout): a test tries a wrong one at most once in a row and a right one right after, which resets the count; never sign out the saved device. The user menu is `openUserMenu` in `top-bar.ts`. `own-user.ts` gives a test a user of its own: `addOwnUser` adds one as the shared user (`POST /api/users`), sets their password with the one-time password in a request context not signed in, and answers their `storageState`, an `api` signed in as them, `chooseAppearance` (`PUT /api/account/appearance`) and `remove`; `asOwnUser` is `test` with an `ownUser` fixture whose device is the test's `page`, `context` and `request`, removed at the test's end. `users.e2e.ts` adds a user in Settings › Users, signs them in on a browser of their own with the one-time password, removes them (their WebSocket closes), and (@full) checks two users' own palettes and densities, which follow a user to another browser and paint from this browser's cache before the account is read. **Trap:** a palette and a density are each user's, kept by the service; local storage is only the cache of the last user's, which the account overwrites, so seeding it sets nothing. A test that chooses one (Account › Appearance, the rail's Theme menu) runs as its own user (`asOwnUser`); one that only needs light or dark follows the system (`colorScheme`, `emulateMedia`) as the shared user, whose appearance no test may change, since every file sees it. A user's removal signs out every device of theirs, so a test removes only the users it added. `office-identity.e2e.ts`'s serial Sign in with GitHub describe, once the App is registered and the git identity signed in, links the shared user's GitHub account (the fake's `office-user`, the git identity's login) from Account › Linked identities, continues with GitHub from a context not signed in, and checks Settings still shows the git identity signed in and its repositories answer; its `afterAll` unlinks. `authenticator.e2e.ts` runs as its own user (`asOwnUser`), so the shared user never gets an authenticator; it makes codes with `@oslojs/otp` on the machine's clock, the service's too, and signs in after setting up with the next step's code, as the confirming step's is taken. `signing-in.e2e.ts` saves a Google OAuth client in Settings › Signing in, opens the sign-in page in a context not signed in, catches Google's authorize page with `page.route` on `accounts.google.com` (Google is never reached) and reads its client id, `localhost` redirect URI, S256 challenge and `openid email` scope, then removes the client; it alone saves one, removing it after each test, so other files see Continue with Google only meanwhile. Its @full test of the OpenID Connect provider starts a discovery server on `127.0.0.1`, saves a provider named Zitadel against it in Settings › Signing in and sees "Continue with Zitadel" on the sign-in page, then removes the provider; it alone saves one. `passkeys.e2e.ts` signs in on a device of its own, adds a CDP virtual authenticator to its page (`WebAuthn.addVirtualAuthenticator`, ctap2, internal, discoverable, user verified, presence automatic; it lives with the page, so adding and signing in happen on one page), adds a uniquely named passkey after the password, seeds one for `old.example.com` in the database for the screenshot and removes it, renames, signs out, signs in with the passkey alone and removes it; its @full test opens the sign-in page at `127.0.0.1`, which hides passkeys and links to `localhost`.

**The full stats** (`stats.e2e.ts`'s serial describe, after its basic test, which needs telemetry Off): it chooses Bundled Grafana through `PUT /api/settings/telemetry` (the e2e service's Bundled Grafana is scripted, so it runs at once) and sets what the scripted Grafana holds with `POST /api/e2e/stats-source` (each call replaces it all; a `failure` answers every read), naming a Task it made through the API; the lane of what was running is Office-wide and its bars are real Stage runs on `claude-code`, so it accepts bars or the empty words; its `afterAll` sets telemetry back to Off and empties the scripted Grafana. A second serial describe does the same for the user's own Grafana: it picks Your own endpoint in Settings › Telemetry through the UI with a read address and token, Tests it (the scripted source answers the check too) and saves, then reads the full stats and, with `failure: {kind: "rejected"}`, the read-token message; its `afterAll` sets telemetry back to Off too.

**Screenshots for a Task's review** go to the worktree's `.office/screenshots/` (`task-screenshots.ts`: `TASK_SCREENSHOTS` and `screenshotScenario`, Light and Dark at 1600, 900 and 390 wide, nothing scrolling sideways, the whole page with `fullPage`, a part brought into view at each width with `inView`); the run's own stay in `e2e-results/screenshots/`.

**The README's screenshots** (`npm run readme-screenshots`, after `npm run build`) are `docs/images/*.png`, made by `readme/readme.screenshots.ts` through `playwright.readme.config.ts`: its own `setup` and `readme` projects, matching `*.screenshots.ts`, which the default and full runs (`*.e2e.ts`) never pick up, and the same web server (`officeServer` in `playwright.config.ts`) with `OFFICE_E2E_ENGINE_SCRIPTS` naming `readme/sessions.jsonl`, the scripts `serve-office.ts` replays instead of `sessions.jsonl`. It builds a demo Office with made-up names only (the shared user renamed, four people hired, two Projects, Tasks in every state of the board, Done ones set in the database), walks one Task through Implement and Tests into a Review & fix the Reviewer works, and leaves three sessions mid-turn at a `wait` step nothing releases, so their people sit working in the Live view (a day ahead at noon UTC, under reduced motion). A change to what it opens changes `readme/sessions.jsonl` in the same order. **Trap:** the same one run at a time as the e2e run: it clears the same database, ports and folders.

**Time of day:** the Live view's light follows the browser's time zone, so the Live view's other tests set `test.use({ timezoneId: "Etc/UTC" })`, a zone with no place that keeps noon's light: in the runner's own zone (Warsaw on the workstation) idle people would go home at night. A test of the hours sets `test.use({ timezoneId })` and `page.clock.setFixedTime` a day ahead, so the Office's hires are over an hour old and nobody shows as just joined (`live-view.e2e.ts`, "at night").

**The default run and the full run:** `npm run test:e2e` (in `npm run verify`) is the default run: one e2e per surface that opens it and does its main action, and the critical flows (hiring, planning to Ready, a Task walked through its Pipeline with a Decision, a Gate and Publish, the Start queue and the fire alarm). A new test that is neither carries Playwright's `{ tag: "@full" }` (on the test or its `test.describe`) and runs only in the full run, `npm run test:e2e:full`. Both run the built app, so `npm run build` first. `playwright.config.ts` leaves `@full` out by its own `grepInvert`, since Playwright applies no CLI `--grep-invert` to a project others depend on (`chromium`, before `queue` and `updates`); `playwright.full.config.ts` is the same config without it. In `people.e2e.ts` the default run is a prefix of the sessions: every session-opening test after the Gate's is tagged, so the scripts `sessions.jsonl` holds for them are left unused at its end, and a session-opening test is tagged only when every one after it is too. Tagging a test that opens no session is safe only when no default test after it needs what it made.

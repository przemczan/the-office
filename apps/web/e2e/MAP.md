# Web end-to-end tests: map

**Owns:** the Playwright tests and what they share: `serve-office.ts` starts the built service on the scripted engine, `office-database.ts` reaches the e2e database (for seeding what the UI can't yet make), `office-data.ts` is the fixed e2e Office data directory, `temporary-repository.ts` makes a Project's repository, with a bare `origin` its `main` tracks when a test needs a remote (`createTemporaryRepositoryWithRemote`, read back by `fileOnRemote`), and commits to it, `git-host.ts` serves bare copies of one on the made-up `https://git.example.test/` (the service's git reads it as a local folder by `insteadOf` in `GIT_CONFIG_COUNT` variables that `serve-office.ts` sets, since a Repository URL is never a local path), `desktop-notifications.ts` the browser's Notification as a recording with the tab's focus set by the test, `fake-github.ts` starts the service's fake GitHub server (`serve-fake-github.fixtures.ts`, run from source with tsx, a dev dependency, since fixtures are left out of the build) on port 4391 before the service, which `serve-office.ts` points at it by `OFFICE_GITHUB_URL`/`OFFICE_GITHUB_API_URL` and stops with it, its repositories' clone URLs on `git-host.ts`'s host (The Office refuses the fake's http website as a remote); tests reach it only over HTTP, so `installApp` installs the App through the fake's own control route; `office-identity.e2e.ts` checks Add a Project's From GitHub before the App is registered, registers it through the fake from Settings › Office identity, signs in, works Add a Project's GitHub list (installing repositories with their `pushedAt` and `description`, holding the service's answer back with `page.route` for the loader, a repository never served for a failed clone), then signs out (a serial describe, signing out in `afterAll` too), `ssh-host.ts` the one host key the service's scanner finds on every host (`OFFICE_E2E_HOST_KEY`, read by `apps/service/src/e2e.ts`, since no ssh server runs), a host made Unconfirmed by cloning from an ssh URL on a `.invalid` host, `skill-source.ts` a bare repository to install a skill from (by a `file://` URL, with the files hash a seeded Proposal needs), `top-bar.ts` opens the top bar's Create and picks Task or Idea, and `sessions.jsonl` holds the scripted sessions. `mcp-servers.e2e.ts` reviews the service's own fake stdio MCP server (`apps/service/src/platform/mcp/fake-stdio-mcp-server.fixtures.ts`, run by this Node, `--fail` to fail with its token on standard error); a review opens no session, so it runs in parallel. `fake-mcp-server.ts` holds its path and tools and adds it to the library, or adds it and turns it on through the API (review, then the state with its digest), for the Role card's test in `people.e2e.ts` (which unassigns it after, so Ola's later sessions start without it) and a Project's Server values in `projects.e2e.ts`. `office-checkout.ts` makes the e2e service's own checkout (`OFFICE_E2E_CHECKOUT`), two commits behind a local upstream, and `serve-office.ts` sets `OFFICE_UPDATE_FOLDER` as the launcher would.

**Traps:** one run at a time on a machine: the ports (4390, 4391), the database and the `/tmp` folders are shared by every checkout, and `serve-office.ts` clears them, so it takes port 4391 first and a run that loses it stops before clearing anything. `playwright.config.ts` takes half of `availableParallelism()` as its workers (one in the 2-CPU run environment), since Playwright's own default counts the host's cores and starves a capped container into timeouts. On one worker the files run in name order on one Office, so a test finds what earlier files left (Ideas, Tasks, skills) and names its own things in full rather than assuming it is alone. the service's log (Nest's warnings, such as a daily job that failed) goes to `e2e-results/service.log`, rewritten each run (Playwright shows only its standard error, where errors go); `apps/service/src/e2e.ts` gives its testing module the service's `OfficeLogger`, whose own logger would show errors alone. sign-in is the Office's and the files share one database, so every test needing the sign-in lives in `office-identity.e2e.ts`'s serial describe, between signing in and out. The scripted engine hands out `sessions.jsonl`'s scripts in the order sessions open, across files running in parallel, so every test that opens sessions lives in `people.e2e.ts`, the one serial file, its script in order; a session waits at each `send` step, so one mid-turn keeps a Stage running until the test writes. A script's `wait` step holds its replay, such as a Process's output between turns, until the test posts its mark to `POST /api/e2e/marks/:mark`, a test-only route that `apps/service/src/e2e.ts` alone registers (`ScriptedSession.reach` on every session), since the scripted sessions run inside the service; the Process test at the end of `people.e2e.ts` opens its view late, then releases the output and the end. A script names places by placeholder but never a record by id, so a session that names Tasks by id (the Planner's in an Initiative's planning Thread) works on Tasks made through the API and then given the fixed ids its script names, in one statement over every row naming them (`giveTasksFixedIds`). Each engine has its caps and Office limits' Save (`settings.e2e.ts`) names every engine, so a test adding an engine (in `people.e2e.ts`, since a Settings › Engines Save sends every engine) removes it at its end through `DELETE /api/settings/engines/:engineId` (`removeEngine`) when nothing later needs it; the remove dialog's test moves references to an engine of its own, never a shared one. That file is also the only one that hires, so a test that needs someone hired (an Agent Stage's Role, the Stage editor's flags, Settings › Engines with a Role card picking an API endpoint's model) lives there too. A Stage failing with no retries left while the CTO is hired opens their Consultation, a session of its own: the sign-in Task's failed Publish does, so its test waits for Bob to pass it on. `queue.e2e.ts` runs alone after every other file (its own Playwright project), since any release weighs the Office's one queue; it seeds queued Tasks in the database and empties the queue after each test, since a Start that queues releases the whole queue (as does any reading of the windows), starting any seeded Task whose desk is free and opening its sessions, and sounds the fire alarm, which pauses every file's started Tasks, holding each at the all clear so no walk starts. A Task's conversation shows no panel until the Planner is hired, so a test in `work.e2e.ts` that reads one, run alone, needs `people.e2e.ts`'s hiring test before it (`--workers=1`, with `-g` naming both). The e2e files share one database, so titles must differ across files (`getByRole` matches substrings), a list's count or empty state holds only narrowed to the test's own Project, the Office instructions are saved only by `settings.e2e.ts`, which empties them again as every file's sessions would get them, and the Notification routing is changed only on "Alarm lifted with work waiting", which nothing raises, and given back. What only an Agent's session makes (a Consultation, a Proposal, a Link card) is seeded in the database in the service's own shape (a Proposal's new Role keeps its skills beside the card), with its `thread_messages` row; a proposed hire takes a title no preset has. A scheduled Office update holds every Start and Stage, and goes ahead (stopping the service) once nothing is busy: `updates.e2e.ts` runs alone after the queue project, keeps an environment check busy throughout, and cancels what it schedules.

**Screenshots for a Task's review** go to the worktree's `.office/screenshots/` (`TASK_SCREENSHOTS` in `settings.e2e.ts`, `screenshotScenario`: Light and Dark at 1600, 900 and 390 wide, nothing scrolling sideways); the run's own stay in `e2e-results/screenshots/`.

**The default run and the full run:** `npm run test:e2e` (in `npm run verify`) is the default run: one e2e per surface that opens it and does its main action, and the critical flows (hiring, planning to Ready, a Task walked through its Pipeline with a Decision, a Gate and Publish, the Start queue and the fire alarm). A new test that is neither carries Playwright's `{ tag: "@full" }` (on the test or its `test.describe`) and runs only in the full run, `npm run test:e2e:full`. Both run the built app, so `npm run build` first. `playwright.config.ts` leaves `@full` out by its own `grepInvert`, since Playwright applies no CLI `--grep-invert` to a project others depend on (`chromium`, before `queue` and `updates`); `playwright.full.config.ts` is the same config without it. In `people.e2e.ts` the default run is a prefix of the sessions: every session-opening test after the Gate's is tagged, so the scripts `sessions.jsonl` holds for them are left unused at its end, and a session-opening test is tagged only when every one after it is too. Tagging a test that opens no session is safe only when no default test after it needs what it made.

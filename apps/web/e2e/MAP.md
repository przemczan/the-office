# Web end-to-end tests: map

## Owns

- The Playwright tests (`*.e2e.ts`) and what they share: `serve-office.ts` (the built service on the scripted engine), `office-database.ts` (seeding what the UI can't make), `office-data.ts`, `temporary-repository.ts`, `git-host.ts` (`https://git.example.test/` via `insteadOf`).
- Also shared: `fake-github.ts`, `ssh-host.ts`, `skill-source.ts`, `fake-mcp-server.ts`, `desktop-notifications.ts`, `own-user.ts`, `e2e-user.ts`, `top-bar.ts`.
- Projects: `setup` (`sign-in.setup.ts`, runs first), `chromium`, then `queue` (`queue.e2e.ts`) and `updates` (`updates.e2e.ts`) alone; the default run (`playwright.config.ts`) and the full run (`playwright.full.config.ts`, `@full`); review screenshots (`task-screenshots.ts`); README screenshots (`readme/`, `playwright.readme.config.ts`).

## Talks to

- The built service and web (`npm run build` first) through `apps/service/src/e2e.ts`, which binds the scripted engine, `ScriptedContainerRuntime`, Devices' `ScriptedAdb`, the stand-in accounts and the test-only routes (`POST /api/e2e/marks/:mark`, `/api/e2e/stats-source`, sign-in approvals).

## Traps

- One run at a time per host or run environment: ports 4390/4391, the database and `/tmp` folders are shared and cleared by `serve-office.ts`, which takes 4391 first. In a Task's run environment run e2e through `run_project_command`, never the Agent's own shell on the host. README screenshots clear the same.
- Workers come from `idle-cpus.ts`; on one worker files run in name order on one Office, so a test names its own things in full and never assumes it is alone. Titles differ across files (`getByRole` matches substrings); counts and empty states hold only narrowed to the test's own Project.
- The scripted engine hands out `sessions.jsonl` in the order sessions open, so every session-opening test lives in `people.e2e.ts`, serial, in order, no retry, 180 s each; Off-board Task tests park their script and drop the Task in `finally` (`dropParkedOffBoardTask`).
- In `people.e2e.ts` the default run is a prefix of the sessions: a session-opening test is tagged `@full` only when every one after it is too. Tagging a test that opens none is safe only if no later default test needs what it made.
- `people.e2e.ts` is the only file that hires; no test gives a duty to a non-default Role. A Task's conversation needs the Planner hired: run with `--workers=1 -g` naming both tests.
- Sign in with GitHub tests live in `office-identity.e2e.ts`'s serial describe. All files share one user: at most one wrong password in a row, then a right one; never sign out the saved device. Use `asOwnUser` for per-user settings (Notifications, authenticator, appearance).
- A script names places by placeholder, never a record id: Tasks get fixed ids through `giveTasksFixedIds`.
- A test adding an engine removes it at its end (`removeEngine`); Settings › Engines' Save sends every engine.
- `queue.e2e.ts` seeds queued Tasks and empties the queue after each test; the fire alarm pauses every file's started Tasks.
- Only `settings.e2e.ts` saves the Office instructions and Resolve's Brief, resetting them after; only `test-instances.e2e.ts` changes `test_instance_settings` and Proxy ports (4396–4399), restoring them in `finally`; only `signing-in.e2e.ts` saves a Google client.
- Agent-only records (Consultations, Proposals, Link cards) are seeded in the service's own shape with their `thread_messages` row; a seeded Proposal sends no event, so reload.
- `serve-office.ts` starts without `OTEL_*`: telemetry follows Settings › Telemetry. Appearance is per user; seeding local storage sets nothing.
- Playwright puts no files on the clipboard: dispatch a `ClipboardEvent("paste")` with a `DataTransfer`.
- `packages/ui`'s `Switch` has no accessible name: click its label text or the switch inside a named group. A `type="time"` field shows the locale: check `toHaveValue`.
- Live view tests set `timezoneId: "Etc/UTC"`; tests of the hours also fix the clock a day ahead.
- No e2e test connects a device over USB (relay helpers never end under `ScriptedAdb`).
- The service's log goes to `e2e-results/service.log`, rewritten each run.

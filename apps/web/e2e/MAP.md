# Web end-to-end tests: map

**Owns:** the Playwright tests and what they share: `serve-office.ts` starts the built service on the scripted engine, `office-database.ts` reaches the e2e database (for seeding what the UI can't yet make), `office-data.ts` is the fixed e2e Office data directory, `temporary-repository.ts` makes a Project's repository, `git-host.ts` serves bare copies of one on the made-up `https://git.example.test/` (the service's git reads it as a local folder by `insteadOf` in `GIT_CONFIG_COUNT` variables that `serve-office.ts` sets, since a Repository URL is never a local path), `desktop-notifications.ts` the browser's Notification as a recording with the tab's focus set by the test, `fake-github.ts` starts the service's fake GitHub server (`serve-fake-github.fixtures.ts`, run from source with tsx, a dev dependency, since fixtures are left out of the build) on port 4391 before the service, which `serve-office.ts` points at it by `OFFICE_GITHUB_URL`/`OFFICE_GITHUB_API_URL` and stops with it, its repositories' clone URLs on `git-host.ts`'s host (The Office refuses the fake's http website as a remote); tests reach it only over HTTP, so `installApp` installs the App through the fake's own control route; `office-identity.e2e.ts` registers the GitHub App through it from Settings › Office identity, signs in, picks a repository in Add Project's From GitHub, then signs out (a serial describe, signing out in `afterAll` too), `ssh-host.ts` the one host key the service's scanner finds on every host (`OFFICE_E2E_HOST_KEY`, read by `apps/service/src/e2e.ts`, since no ssh server runs), a host made Unconfirmed by cloning from an ssh URL on a `.invalid` host, `skill-source.ts` a bare repository to install a skill from (by a `file://` URL, with the files hash a seeded Proposal needs), and `sessions.jsonl` holds the scripted sessions. `mcp-servers.e2e.ts` reviews the service's own fake stdio MCP server (`apps/service/src/platform/mcp/fake-stdio-mcp-server.fixtures.ts`, run by this Node, `--fail` to fail with its token on standard error); a review opens no session, so it runs in parallel. `fake-mcp-server.ts` holds its path and tools and adds it to the library, or adds it and turns it on through the API (review, then the state with its digest), for the Role card's test in `people.e2e.ts` (which unassigns it after, so Ola's later sessions start without it) and a Project's Server values in `projects.e2e.ts`.

**Traps:** sign-in is the Office's and the files share one database, so every test needing the sign-in lives in `office-identity.e2e.ts`'s serial describe, between signing in and out. The scripted engine hands out `sessions.jsonl`'s scripts in the order sessions open, across files running in parallel, so every test that opens sessions lives in `people.e2e.ts`, the one serial file, its script in order. That file is also the only one that hires, so a test that needs someone hired (an Agent Stage's Role, the Stage editor's flags, Settings › Engines with a Role card picking an API endpoint's model) lives there too. A Stage failing with no retries left while the CTO is hired opens their Consultation, a session of its own: the sign-in Task's failed Publish does, so its test waits for Bob to pass it on. `queue.e2e.ts` runs alone after every other file (its own Playwright project), since any release weighs the Office's one queue; it seeds queued Tasks in the database and empties the queue after each test, since a Start that queues releases the whole queue (as does any reading of the windows), starting any seeded Task whose desk is free and opening its sessions, and sounds the fire alarm, which pauses every file's started Tasks, holding each at the all clear so no walk starts. The e2e files share one database, so titles must differ across files (`getByRole` matches substrings), and the Notification routing is changed only on "Alarm lifted with work waiting", which nothing raises, and given back. What only an Agent's session makes (a Consultation, a Proposal, a Link card) is seeded in the database in the service's own shape (a Proposal's new Role keeps its skills beside the card), with its `thread_messages` row; a proposed hire takes a title no preset has. Swapping a Task's Pipeline in "Edit for this Task" starts the Stage editor again once the swap lands, dropping any edit made before it: wait for the Pipeline select to show the new one before editing (a slow database makes the swap land mid-edit).

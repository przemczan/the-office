# Contracts: map

## Owns

- The HTTP and WebSocket contract as zod schemas and their types, one file per area (`work.ts`, `work-states.ts`, `projects.ts`, `pipelines.ts`, `stages.ts`, `conversations.ts`, `people.ts`, `engines.ts`, `users.ts`, `devices.ts`, `activity.ts`, `days.ts`, `live-view.ts`, `prompt-templates.ts`, `telemetry.ts`, `run-environments.ts`, `events.ts`, …).
- Office action declarations (`office-actions.ts`, `officeAction`, `OFFICE_ACTIONS` in `office-action-list.ts`) and the write-route register (`write-routes.ts`).
- Rules both sides read: record links (`record-links.ts`), the Open page (`open-page.ts`), the Project filter (`project-filter.ts`), `messageCommand` (`commands.ts`), message image rules (`message-images.ts`), `engineIdFor`, `usageWindowWords`, mark colours.
- Device frames (`device-frames.ts`, plain bytes, `FrameReader`) and control payloads (`device-control.ts`).

## Talks to

- Nothing: the service's adapters and the web import it. Only the service's adapters import it (the application never does).

## Traps

- Every new action on a record is an Office action declared once here (route and tool derived from it; the web calls `callOfficeAction`); `officeAction` throws for a path parameter its input lacks, a DELETE with a body, or no covering duty.
- A write route that isn't an Office action goes in `WRITE_ROUTE_REGISTER` (`usersAlone` with its heading, or `noAction`); never add to `knownGaps`: `KNOWN_GAPS_LEFT` only goes down; `app.module.test.ts` fails a route in none.
- An event the web sees needs its schema in the union the web parses and the service's WebSocket adapter forwarding it ([module template](../../../apps/service/docs/module-template.md)). A `THREAD_SCOPED_EVENT_TYPES` type reaches only subscriptions scoped to its `threadId`, so its events carry one.
- Files import each other without a cycle: Task and Initiative states live in `work-states.ts` (`work.ts` imports `engines.ts`); a Stage's schema and `stageProblemSchema` live in `stages.ts` (`pipelines.ts` imports `conversations.ts`); `effortSchema` lives in `engines.ts`; run environments in `run-environments.ts`.
- Mirrors kept equal by hand or test: `dutyKeySchema` ↔ People's `DUTIES` (in order), `engineIdFor` and `ENGINE_TYPE_EFFORTS` ↔ Engine's, `usageWindowWords` ↔ Engine's, `device-frames.ts` ↔ `tools/device-helper/frames.go`, `PROJECT_FEATURES` ↔ Projects' registry, `PALETTE_IDS`/`DENSITY_IDS` ↔ `packages/ui`.
- `FrameReader` keeps chunks as a list until a frame is whole (joining at every chunk went quadratic); a pushed chunk must not change after `push`.
- Every new input field is optional or defaulted, so older clients and stored Saved views still parse; the read model always carries it.
- Commands are `installCommand` plus a `commands` list by key (never fixed build/lint/test fields); `install` and `publish` are reserved keys; a change sends name, kind and line whole by key.
- A Stage's `routes` and `place` are optional only for Stage templates; `optional` and a run's `skipped` stay for the previous release. Problems are located by `stageKey` and `at`, never by index.
- A Project's `icon`/`logo` are never null (`{ light, dark }`); `baseBranchFolderQuerySchema` turns comma-joined `extensions` into a list.
- `pairingCode` is carried by no response, event or record.
- `promptTemplateDomainSchema` is a closed list: adding a domain is a deliberate contract change.
- The board's Kind filter shares the name `kind` with the Archive's `?kind=initiatives`.
- Users and Authors: `user: userRefSchema.nullable()`, null on records from before users existed; secrets in settings schemas are `secretSet`, never the secret (an empty secret keeps the saved one).

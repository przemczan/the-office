Four tones, by what an action does

Each action names its tone once, by what it means, never by its colour. The colours are the design system's status tokens, which already have light and dark values, so no colour is written anywhere. Actions that open something or rearrange it have no tone and look as they do today, so the coloured ones stand out.

Task page head

The head's actions in the states that show the most of them. The row is as it is in the app: one line, ending with More; what doesn't fit is hidden, and More always lists it. Hover the buttons to see B's hover.

Initiative page head

An active Initiative has the longest row of all, so it shows best how the tones help: the planning actions read blue, Start Ready Tasks green, Pause amber.

Idea card

The Ideas page shares the same actions row, at the small size.

More menu

Menus have no buttons, so both versions show the menu the same way: its actions keep their tone on the icon, the label stays plain. Drop keeps its danger look, as today.

Notes for the review

Recommendation: Version A, coloured icons

  • B's tinted buttons use the same tokens as the status badges, so in a head beside “In progress” or “Queued” they read like more badges, not like things to press.
  • With four or five toned buttons, B gets loud and competes with the one primary button, which is meant to be the strongest thing in the row.
  • A keeps the row's order of weight (primary, then secondary), and the hue is still enough to find Stop or Pause at a glance.
  • A looks the same on the buttons as in the More menu, so you learn one set of colours.
  • B's strength: it's easier to find at a glance, Stop most of all. If that matters more, choose B.

Primary buttons keep their icon plain

Start, Start anyway, Resume, Mark Ready, Confirm the Initiative and Plan the Initiative are primary. They keep their fill in both versions, and I propose their icon stays in the button's own text colour. The fill already makes them the strongest button in the row.

The palettes set their own primary fill: Cobalt's is blue (#2343b0), Lagoon's teal and Emerald's gold. A blue Plan icon disappears on Cobalt's fill, and a green Go icon fades on Lagoon's. Their tone still shows in the More menu.

“Primary icon: Toned” in the top bar shows the other option, the icon in the tone's base token. How it reads on Light's and Dark's fill (3:1 is the least for an icon):

Icon Light fill gray-900 Dark fill #d9d9d5
--success 5.2 : 1 2.4 : 1
--info 3.6 : 1 3.5 : 1

Green on Dark's light fill falls under 3:1, which is one more reason to keep it plain.

Buttons that have their own control

  • Split buttons (Move up, Shape into a Task): the tone is on the whole button. In A only the main half's icon is coloured, not the arrow. Both are neutral or green here.
  • Links drawn as buttons (Open pull request, Planning Thread, Browse files) take the tone like a button does. Only Planning Thread has one: plan.
  • Ghost buttons (Take out of the queue): in A the icon is red; in B the label and icon are red, with the red tint on hover. That is the design system's danger-ghost look, so the build can reuse it.
  • Plan the Initiative's Auto mode switch stays neutral; only the button takes the tone.
  • Board card's Plan icon button (PlanOnCardButton) gets the same plan tone on its icon, so the board and the Task page match.
  • Disabled buttons keep their tone, faded to the Button's 45% like everything else.

Choices I made that the Plan left open

  • Shape into a Task (Ideas) is go: it turns the Idea into a Task at once, with nobody to talk to first. Plan as a Task with <Planner> and Shape into an Initiative with <Shaper> are plan.
  • Add a Task, Add an existing Task, Back to Shaping and Restore stay neutral: they change what the record holds or where it is, not how the work goes.
  • The More menu's own items (Priority, Kind, Edit Stages, Move to another Project, Archive, Copy link, Edit, Attach) stay as they are. Drop keeps its danger red label.
  • The toned icon uses each tone's -fg token. On Light and Dark it reads at 6:1 or better on the button's surface. The palettes leave the status tokens alone, so every palette gets the same tones.

The rule for docs/spec/4.1-ui-rules.md

The Implement Stage adds this once, and the Task page, Initiative page and Ideas screen pages link to it:

## Action tones

- An action on a record's head names one tone, by what it does: go, plan, hold or stop; an action that opens or rearranges something has none.
- go (Start, Start anyway, Resume, Mark Ready, Start Ready Tasks, Confirm the Initiative, Resume the Initiative, Shape into a Task); plan (Plan with <Planner>, Plan the Initiative, Planning Thread, Plan as a Task, Shape into an Initiative); hold (Pause, Pause the Initiative, Queue behind it); stop (Stop, Take out of the queue).
- Colours: go --success-fg, plan --info-fg, hold --warning-fg, stop --danger-fg; never a colour value.
- A toned button colours only its icon; its surface, border and label stay. [Version B: a toned button takes the tone's -subtle surface, -border border and -fg label and icon, the -border surface on hover.]
- A primary button keeps its fill and its icon in its own text colour.
- The More menu shows each action's icon in its tone; Drop keeps its danger look.

About the mock

Its tokens are copied from design-system/tokens/ with the Light and Dark palettes of packages/ui/src/appearance/palettes/. Its words, icons (Lucide, as Icon draws them), button variants and order come from apps/web/src/surfaces/work/ and the Task, Initiative and Ideas screen pages. Buttons only show a toast. It uses the Geist fonts only where they are installed, and makes no network requests.

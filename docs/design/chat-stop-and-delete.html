Stop and delete in the chat

Two additions to the chat drawer. Stop interrupts a person's answer right away, as in any agent harness, and keeps the session. Select in the Thread list deletes the Threads you no longer need, one or many at a time. Both reuse what the drawer already has: the composer's buttons, the Thread list's rows, the small confirmation window and a toast.

Stop, in each of its looks

Stop sits in the composer, between Mention and Send, and only while the person answers. Send stays: a message still lands at the next safe point, so writing and stopping never share one button. The square takes the stop tone (--danger-subtle, --danger-border, --danger-fg), as Stop does on the Task page.

Delete, in each of its looks

Deleting starts in two places: Select on the Thread list for several Threads, and the trash icon in an open Thread's head for that one. Both go through the same small window, as Drop and Delete do everywhere (4.1, window sizes), with the destructive action first in red and Close on the right.

Choices made

The Task has no Plan yet, so these are my defaults. Send the design back with the one you want changed.

QuestionProposedNot chosen, and why
What Stop ends The turn now, with every Sub-agent and Process it started, in the foreground or the background. They show as Stopped, "when the turn was interrupted". The session is kept, so the next message continues it under the Context policy. What the person already said stays in the log. Ending the session as well: it would throw away a warm cache for nothing. Leaving background work running: "stop" should mean everything stops.
Messages waiting to land They aren't delivered: each reads "Not delivered: you stopped Pam". Your own get Send again, which sends the same words and images as a new message. Sending them as the next turn by themselves: then Stop wouldn't stop whenever a message was waiting. Putting them back in the box: the log already shows them, and another user may have written them.
Confirm before Stop No. One click, as in a harness: nothing is lost, the session is kept. A window: too slow when an Agent is heading the wrong way.
A key for Stop /stop in the message box, an Office command that works while the person answers. No Esc. Esc: it closes one thing at a time, and the chat drawer is one of them (4.1, Closing a window).
Where Stop shows Every Thread you talk to a person in: a chat, a person's Thread on a Task, the Planning Thread, and an Initiative's shaping and planning Threads. A Stage Thread: the Task's Stop and Pause hold the Task there. A Consultation has no composer, and its caller is waiting on it.
Which Threads can be deleted The Threads in a person's chat. Planning and Initiative Threads belong to their record and stay. Task and Initiative Threads: they are the record's history.
A Thread that can't be deleted yet A Consultation still waiting on the person, and a chat Thread whose call to someone is still out: both ends of a Consultation must stay. Their box is off, and its tooltip says why. Withdrawing the call: it would leave the other Thread with a question nobody asked.
What goes with a deleted Thread Its messages, images, context choices, Sub-agent and Process records, and the engine's session. A running answer is stopped first. A Decision waiting in it is withdrawn, and its open Proposals are declined, "Declined as its Thread was deleted". Archiving instead: the user asked to delete, and nothing else reads a chat Thread later.
What stays The records made in it (Tasks, Ideas, Memory notes, applied Proposals) and its tokens in Stats. Removing its tokens: Stats would rewrite the past.
Undo No Undo. The confirmation window says it is for good. A toast with Undo: the delete would have to wait in a soft-deleted state, and the session files with it.
Who can do it The user alone, for both. They become two usersAlone entries in the write-route register, with lines in spec 6, The user's alone. Office actions: an Agent stopping or deleting the user's own conversation isn't its call.

What the build needs

  • Stop: POST /threads/:id/stop. It does nothing between turns. It uses the same session interrupt() as a Stage's Stop. On an engine that can't interrupt, the session ends and the line says so; the next message then starts fresh.
  • Delete: POST /chats/:roleKey/threads/delete with { threadIds }, all or nothing. It refuses, with the reason, when a Thread is locked or isn't in that chat. One route serves both the trash icon and Select.
  • The engine's session files go too: the Claude Code transcript under engines/<id>/projects/, and the Codex thread.
  • Tokens stay in Stats: the usage rows outlive the Thread.
  • Events: the Thread's turn ends as stopped (the line, the marks, the Sub-agents), and thread.deleted with who deleted it. Every browser drops the row, the tab's Thread and People › Conversations' row, and an open Thread shows "This Thread was deleted".
  • Write-route register: both routes as usersAlone, citing 6 › The user's alone.
  • Web: ThreadView gets an onStop where the place allows it (never in a Stage Thread). chat-drawer.tsx gets Select on ThreadList and the trash icon on ShownThread, built from Checkbox (with indeterminate), Button, IconButton, Dialog (small), Tooltip and the shell's toast.
  • Run npm run maps, and update the handwritten part of the chat and conversation MAPs.

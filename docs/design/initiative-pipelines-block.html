The Pipelines block, edited as a whole

One question at a time, in the order they are decided: does a Project work on an Initiative's branch, what is the branch called, and which Pipeline publishes it. The block reads as facts until you press Edit, like the Plan and the Definition of Done. Try it: the mock below is live.

What changes

  1. Edit, like the Plan. While shaping the block's head has Edit; nothing in the body is a control until then. Save writes everything in one go; Cancel throws the draft away. Once confirmed there is no Edit: whether a Project has an Initiative's branch is fixed at Confirm, and another Pipeline comes by a Proposal, as today.
  2. 1 · Initiative's branch first. One switch per Project the Initiative spans: on, it works on initiative/<short name> there; off, its Tasks publish Task by Task. This replaces "None" in the Pipeline picker.
  3. 2 · Its name. The Short name, edited in place with the fixed initiative/ prefix shown, so the field reads as the whole branch. Shown once any switch is on; one for the whole Initiative.
  4. 3 · Pipeline, required. One picker per Project switched on, its Project default picked at first. No None in the list: a branch without a Pipeline can't publish.
  5. Read view as facts. Branch, then each Project's Pipeline with its track, Publishing Task and wait words as today.

Behaviour

  • Switching a Project on picks its Project default Pipeline and, when the Initiative has no Short name yet, fills the branch name from the title, by the rule the service uses (derivedShortName).
  • Switching every Project off dims steps 2 and 3 and says why; Save then writes None in each Project and leaves the Short name as it is.
  • Save checks before it sends: a Project switched on with no Pipeline, or a branch name outside a–z, 0–9 and -, shows its error under its field and keeps the form open. A refusal from the service (a Short name already taken) shows under the branch name.
  • A Pipeline with no Gate keeps today's warning, "Publishes without your review", under its picker.
  • The fold's summary line and foot words stay as they are.

For the build

  • packages/ui as it is: Switch with label and description, Input with iconLeft for the prefix, Button, Alert; PipelinePicker without its None group; the RecordFold side holds Edit, as PartActions does.
  • The numbered steps and the facts list are drawn in work.css from tokens; they replace .initiative-pipelines-choice and .initiative-short-name.
  • One Save is one change: a single call that takes the Short name and every Project's Pipeline (or None) is preferred over today's one call per field, so a refusal leaves nothing half-saved.

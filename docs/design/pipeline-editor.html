        What changes

        • Settings › Pipelines has two tabs, Pipelines and Stage templates, each with its count, kept in the address as today (/settings/pipelines/… and /settings/pipelines/stage-templates/…). Each tab holds one list beside its open item.
        • Everything else around the editor stays as today: the list beside the open item (300px in Settings, 340px on a Project page), its head and foot (Duplicate, Add a Pipeline built from…, Ask Rosa), the head card, the Built on by card, the form card with the editor inside it, the Save row under it, the 1100px cap and the lists-or-the-open-item rule under 1224px.
        • The canvas pans and zooms. A Stage card keeps its size at 100%, so a large Pipeline grows past the canvas instead of squeezing its cards. Drag with the right mouse button (or the middle one, Space + drag, or on the empty canvas) to move around. Zoom goes from 25% to 100%, and Fit shows the whole Pipeline. An Overview in the corner shows where the view is.
        • Full screen gives the editor the whole window: the canvas above, the panel under it, Save at hand. Esc goes back.
        • One editor in four places: Settings, a Project page, the Task's Stages window and a Proposal shown on the flow all use the same editor with the same canvas, controls and panel. They differ only in how an edit is kept: on the Pipeline itself, on the Task, or as a Project Pipeline's Stage changes on top of its base Pipeline.

        The two tabs

        • The tabs sit at the top of the section, above the list and the open item. Pipelines opens by default. A Stage template's address opens the Stage templates tab, and New template opens it too.
        • Pipelines tab: "Office-wide Pipelines" beside the open Pipeline, as today, without the Stage templates list under it.
        • Stage templates tab: "Stage templates" beside the open template. With none in the address, the first one opens, as the first Pipeline does on the Pipelines tab. Under 1224px the back link reads "‹ All Stage templates".
        • The tabs use packages/ui's Tabs, each with its count. Switching tabs keeps each tab's open item, since each has its own address.

        • Where it opens: at 100%, with the Start in view. The canvas is as tall as the Pipeline at 100%, up to 62% of the window's height, at least 300px. A view moved by hand stays where it is while the user edits, and comes back to 100% at the Start when another Pipeline opens.

        One editor, three ways to keep an edit

        Each place today has its own editor component (office-flow-editor, task-flow-editor, project-flow-editor), each wiring the shared FlowEditor slightly differently. The proposal makes the difference explicit: the editor is one, and an editing mode says how an edit is kept.

        FlowEditor                (shell/pipelines/flow/: one component, placed in each form card as today)
 ├─ head                   title, summary, Add / Insert, Flow | List; legend, hint
     ├─ FlowViewport       new: pan, zoom, Fit, Overview, full screen; wraps FlowCanvas or, read-only, a Proposal's flow
     │   └─ FlowCanvas     fixed card size; places from flow-layout in px, not column shares
     ├─ FlowList
     └─ FlowPanel          Stage, route, or empty; plus what the editing mode adds

FlowEditing (the editing mode, one per place)
 ├─ pipelineEditing(pipeline)                Settings: edits change the Pipeline
 ├─ taskEditing(stages, locks)               the Task: the same, with started Stages locked
 └─ stageChangesEditing(project, base)       a Project: each edit becomes a Stage change on its base Pipeline,
                                             with marks, legend, Undo and the compare tables
   each says: what Add offers, which Stages move, marks and legend, the panel's extra sections, and onEdit
        • Settings and the Task keep an edit the same way, without a base Pipeline (the Task adds locks), and a Project adds a base Pipeline, as the Task's description puts it. Each new capability (pan, zoom, Fit, full screen, the Overview) lives once, in FlowViewport, so all four places get it.
        • FlowViewport owns its view (zoom and offset) and nothing of the Pipeline. FlowCanvas keeps the layout, the lines and the drags. Drags convert pointer movement by the zoom.
        • The zoom controls and the Overview are drawn for the canvas alone, from tokens, as spec §4.1 allows for a part made for one feature.
        • The pages around the editor don't change: the list column, the head and Built on by cards and the Save row stay where they are. Pan, zoom, Fit and full screen are what give a large Pipeline its room.

        Moving Stages on a Project Pipeline

        Open question for the user, asked with this design. Today a Project Pipeline's Stages can't be dragged on purpose (draggable={false}): a Stage's place gives the Pipeline's order, and a Project Pipeline keeps its base Pipeline's places, because its Stage changes (Insert before, Insert after, Replace, Change, Remove, Change routes) don't include a place.

        This mock shows the recommendation: keep the base Pipeline's places, and say so where it happens. Dragging a Stage there shows "Its place comes from Full, the base Pipeline: move it there," with Full a link, and the hint says the same. The alternative is a new Stage change, Move, which gives a Stage its place on the Project Pipeline. It would have its own mark and Undo, and would make the Project Pipeline Broken when its Stage leaves the base Pipeline. That is a change to the contracts, the service and spec §2.3.

        The Task's Stages window

        • The window stays as today: L (1180px), with the Pipeline picker above the editor until the Task starts. The editor is the same as in Settings, with started Stages locked (a lock in the card and a grey edge) and their routes out read-only.
        • Full screen works in the window too and covers it: a Pipeline of 15 Stages can be edited at the size of the screen.

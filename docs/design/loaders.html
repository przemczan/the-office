Loaders

Screen State Drawer opens on Palette

The rule

  • Until a block's data first arrives, it shows a loader shaped like what replaces it: rows where a list will be, cards where cards will be, a key-shaped bar where the key will be. Everything that doesn't wait on data (the heading, the card's note, the filter bar, the Hire a Role tile) shows at once, so the page keeps its frame.
  • "Nothing here" is said only once the data has loaded. While loading, a list says nothing about being empty, and a count it would show as 0 isn't shown (the Board's columns, Now's panel headings).
  • A failed read shows its problem in place of the loader, as today: the same alert, in each block that reads the data. The loader never stays after a failure.
  • No flash: the loader fades in 200ms after it appears (CSS only, 160ms fade), so an answer in under about 200ms goes straight to the content. Try "Replay: fast answer".
  • Only the first load: a background refresh leaves the content on screen; nothing shimmers over it. The build keys this on the query's isLoading (first fetch, no data yet), never isPending, which stays true for a query that's switched off.
  • Small inline bits stay as they are: a Project chip, a person's name, the status strip's counts, a select's options, a crumb in the page heading.

The loader: one component, a few shapes

BlockLoader in apps/web/src/shell/, its bars the design system's Skeleton. Its outer element is role="status" with a visually hidden label, "Loading…" unless the block names what it loads ("Loading the Office ssh key…" where several load on one page). The bars are hidden from screen readers, as Skeleton is. With reduced motion on, the bars hold still. The shapes below are its whole vocabulary; a block picks one and how many.

Where it goes

From a sweep of every block that reads data in the six areas the Task names. "Blank" means the block shows nothing under its heading today; "Says empty" means it shows its empty message, or a 0, while it loads. The build confirms each and checks it in both palettes.

For the build

  • Tables: Settings › Skills and MCP servers pass loading to DataTable today, keyed on isPending; its rows have no delay and say nothing to a screen reader. They, and a person's Work tab, take the table shape instead, so there is one loader.
  • A block that waits on several reads (if (!a.data || !b.data) return null, as a person's tabs do) is blank for good when one of them fails. It shows the loader while any is loading and the problem of the one that failed.
  • On a sunken surface (the Board's columns, Now's feeds) a bare Skeleton is the same colour as the surface and vanishes, so the cards and tiles shapes draw the card's frame on --surface and the bars inside it.
  • A record page (a Project, a person, a Task) returns nothing until its record arrives today. It shows its heading's place and the lines shape for its first block, under the page's own frame.
  • Text-only loading lines in the file browser ("Fetching the base branch…", "Reading the folder…") become the rows loader with those words as its label, so they look like the rest.
  • Unconfirmed hosts read the same data as Trusted hosts but show no problem when it fails, so the card is blank. The problem shows in both.
  • Reads that never show their problem today: Now (its feeds stay blank when the read fails), the chat drawer's Thread list (if (!threads.data) return null) and every return null on several reads. Each shows its problem where the loader was.
  • Lists that fall back to empty (data ?? []) say the wrong thing while loading: the chat's person picker lists nobody, then says "No Threads yet" for everyone until their activity arrives; the Board says "Nothing here" with a 0 in every column. The block keeps its loader until every read it says "nothing" about has arrived.
  • The chat drawer opens on the newest Thread unless the user went back to the list, so while its Threads load it shows the turns shape, which the Thread's messages then keep: one loader, not rows that turn into turns. On the Thread list it shows rows. Use "Drawer opens on" above.
  • Reduced motion: Skeleton sets its shimmer as an inline style, which a stylesheet's prefers-reduced-motion rule can't override. The fix belongs in Skeleton: its shimmer moves into the stylesheet it already injects, under @media (prefers-reduced-motion: no-preference), so every Skeleton holds still, not only the loader's.
  • Tests: role="status" takes no name from its content, so a test finds the loader with getByRole("status") and checks its text (toHaveText("Loading the Office ssh key…")), not { name }. The People and Projects grids put the tiles shape in the grid itself (display: contents) so the Hire a Role tile doesn't move when the people arrive; the test checks the status is still found there.
  • Watch: in Light, the Skeleton's bars (--surface-sunken on white) are faint. That is the design system's look and this proposal keeps it; if it reads too faint at the Gate, the change goes into Skeleton itself, not into the loader.

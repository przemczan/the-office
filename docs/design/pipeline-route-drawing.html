Route drawing: Right angles, Curves and Straight lines

The routes between Stages are drawn in one of three ways, switched in the editor’s head so the difference is plain to see. In every one of them a route with a limit is drawn by the same rules as any other route, no line runs through a Stage, a loop’s arrow sits on the Stage it goes back to, and nobody arranges a line by hand.

In short

Eight decisions. Each one is worked out further down the page.

The modes

Right angles, Curves, Straight lines

Right angles is the orthogonal mode: lines go around Stages and stand apart where they share a side or a corridor. Curves draws one smooth curve per route. Straight lines draws the direct line from Stage to Stage.

The default

Right angles

It is the only mode that keeps lines in a shared corridor apart. It draws the test Pipelines with no crossing (as Curves does, but Curves lets lines run close), its lines leave from their own rows, and it is the closest to what the editor draws today.

For the review

Six choices that are yours to change, and two facts that were not checked.

  1. The words. The switch says Right angles, Curves, Straight lines, in plain language. The other choice is Orthogonal, Curved, Straight, as the Task names them.
  2. Own router. Right angles is our own code rather than libavoid-js or ELK (the comparison).
  3. Sides by where the target stands. A line leaves its row’s port only when its target is ahead; a route back or down leaves the top or bottom edge. So a row shows its port dot only when its line leaves there.
  4. A mark with no room. A line too short or too crowded for its ≤N× mark draws none; the route’s row still shows it.
  5. Narrow view. Two Stages side by side in a band stand 24 apart instead of 14, so an arrow fits between them.
  6. Tab. A ≤N× mark takes a press but is not a Tab stop of its own: Tab reaches the route at its row (or at its line, with no row), as today. A second Tab stop per route would say the same thing twice.

Not checked on the web while this was written: libavoid-js’s size and licence, and that ELK’s fixed-position layout draws no routes. Both are from memory; the reasons against each library (an asynchronous load, and Stages that move) don’t depend on them.

How these were drawn: no router ran. The Right angles lines follow points worked out by hand from the rules below; this page then draws Curves from the same ends, and Straight lines between the cards’ centres. The count beside each name is counted by this page from the lines it drew.

Today

  • flow-layout.ts draws routes on and routes back by two different sets of rules. Routes back, which are most often the ones with limits, run in lanes above the Stages between their ends (or under them), so they cross and cover the other lines.
  • A route on that can’t go straight takes a lane below the Stages. Those lanes stack in the lines’ order, not by where the lines lead, so they tangle.
  • Nothing counts crossings, so nothing avoids them.
  • The marks layer takes no presses (pointer-events: none): a press on a ≤N× mark only works where it happens to land on the 12-wide hit line under it.
  • The room the canvas keeps for lines (flowRoom) comes from counting lanes, not from what is drawn.

The drawer boundary

One function per mode, with the same input and output. It is pure: no React, no DOM, nothing asynchronous. The editor calls it today; the Task page’s read-only diagram calls it next. 

// apps/web/src/shell/pipelines/flow/flow-routes/route-drawer.ts
export type RouteDrawing = "right-angles" | "curves" | "straight-lines";

export interface RouteScene {
  readonly orientation: FlowOrientation;               // "across" | "down"
  readonly stages: ReadonlyMap<string, MeasuredStage>; // each card's box and its rows' ports
  readonly end: FlowBox | undefined;                   // undefined until End is measured: no line to End is drawn
  readonly start: string | undefined;                  // the first Stage's key: the start marker keeps its place
  readonly lines: readonly FlowLine[];                 // routes on and back alike, then a Proposal's; a line's
                                                       // limit is its only extra: on or back makes no difference
  readonly mark: { readonly width: number; readonly height: number }; // the ≤N× mark's box: 40 × 18 today
}

export interface DrawnRoute {
  readonly line: FlowLine;
  readonly d: string;                    // the line's SVG path
  readonly hit: string;                  // the 12-wide path that takes the press
  readonly arrow: string;                // the arrow head, on the target's edge
  readonly mark: FlowPoint | undefined;  // where ≤N× sits; undefined with no limit, or no room
  readonly fromPort: boolean;            // the line leaves its row's port, so the row shows its dot
}

export interface DrawnRoutes {
  readonly routes: readonly DrawnRoute[]; // in the lines' order
  readonly bounds: FlowBox;               // around every path and mark
}

export interface RoughDrawing {
  readonly previous: DrawnRoutes;         // the last full drawing
  readonly moved: string | null;          // the Stage being dragged, by its key; null for End
}

export type RouteDrawer = (scene: RouteScene, rough?: RoughDrawing) => DrawnRoutes;

export const ROUTE_DRAWERS: Record<RouteDrawing, RouteDrawer>;
  • flow-canvas.tsx draws whatever the chosen drawer returns: the paths, the arrows, the hit lines and the marks.
  • flowRoom is worked out from bounds, so the canvas keeps exactly the room the lines take.
  • Narrow, that room narrows the cards, which changes what the lines were drawn from. It settles in two steps: the room is taken from a first drawing, the cards are measured again, and the lines are drawn once more for them; the room then stays until the Pipeline or the width changes.
  • The mark’s box, 40 × 18 as today’s MARK_WIDTH and MARK_HEIGHT, is part of the scene, so the drawers and the canvas agree on it.
  • flowLines stops leaving routes back out: every line reaches the drawer, in the Pipeline’s order.
  • Removed from flow-layout.ts: loopLanes, LaidLoop, FlowLoopPath, needsDetour, lineDetours, routePaths, loopPaths, the anchors, markSpot and markSpots.
  • Stay shared: startPath, orthogonalPath, arrowHead, narrowBands / narrowLayout and drawingStart.
  • rough is only for dragging on a large Pipeline (Performance); a drawer may ignore it and draw in full.

In every mode

  1. One pass, one set of rules. Routes on and routes back are drawn together; a limit only adds the ≤N× mark. No route is drawn over another for having one.
  2. No line through a card. Every Stage card and End is an obstacle.
  3. The arrow is on the target’s edge, pointing in. In Right angles and Curves the last 12 of the line run straight into the edge, so the arrow never lies along it.
  4. A route to its own Stage is a loop on the Stage’s top edge (its left edge, narrow): 56 wide and 24 out. It enters at the middle of the edge and leaves 56 to the right of that (below it, narrow); the other lines on that edge keep 16 clear of both its ends. With a card less than 40 over the edge, the loop takes the bottom edge (the right edge, narrow) instead.
  5. No words on lines. A route’s words are its row in the card; the line carries only its ≤N× mark.
  6. The start marker keeps its place, the middle of the first Stage’s left edge (its top edge, narrow); lines that enter that edge spread round it.
  7. The same Pipeline draws the same way every time. Ties go by the Pipeline’s order. Stages never move.
  8. One layer. All lines are drawn in one SVG layer under the cards, in the Pipeline’s order; only the picked route is raised.

Right angles

Level and upright stretches with rounded corners. Lines go around Stages, and lines that share a side or a corridor stand apart. This is the approach of libavoid and ELK, in our own code.

BranchingRight angles · Dark

Which sides a line uses

Decided by where the target stands, the first row that fits:

Where the target stands The line leaves The line enters
Ahead: its left edge is at least 24 right of the Stage’s right edge the right edge, at the route’s row (the middle of the edge with no row) the left edge
Below or above: its top is at least 24 under the Stage’s bottom, or its bottom at least 24 over the top the edge facing the target the edge facing the Stage
Otherwise: behind and level, or closer than 24 on every side the top edge the top edge. Both use the bottom edges instead when fewer cards stand over the span between them there; the top on a tie
  • Wide, a line never leaves a left edge and never enters a right edge.
  • Narrow, the same rules hold with left-to-right and top-to-bottom swapped: ahead is below, lines leave a bottom edge and enter a top edge; a target in another column, beside or higher up, takes the facing left and right edges; a route back in the same column uses the left edges; a line never leaves a top edge or enters a bottom edge; and cards have no ports.
  • A full side: when a side can’t take one more point at 8 apart (End, 44 high, takes three), the line that comes last in the Pipeline’s order enters the nearest other side that is free, for End its top or bottom edge.

On a side

  • One line takes the middle of the side.
  • Several stand 16 apart round the middle, in the order of where their other ends stand, so they don’t cross on the way out.
  • Points keep 12 clear of the card’s corners; a crowded side shrinks the gap evenly, never under 8.
  • On a right edge, a route’s point is fixed at its row.
  • An entering point slides along its side when that makes the line straight.

Finding the way

  • Tracks run along each card’s edges grown by 16, through every port, down the middle of each gap between neighbouring cards, and once outside each outer edge.
  • Each line takes the cheapest way over the tracks (an A* search): its length, plus 48 for each bend, plus 192 for each crossing of a line already drawn.
  • The shortest lines are routed first; ties go by the Pipeline’s order.

Keeping lines apart (nudging)

  • Stretches that would share a track stand 16 apart, centred in their corridor.
  • They nest: the line that turns off first lies on the outside, so they don’t cross where they part.
  • An upright stretch that carries a mark gets 24 to the stretch beside it.
  • A narrow corridor shrinks the gap evenly, never under 6 and never to an overlap.
  • A corridor that can’t take one more line at 6 apart is closed to the next line, which takes its next cheapest way round.
  • A line alone in a corridor runs down its middle, and 16 off the cards it passes where there is room.
  • Corners are rounded by 6. Lines cross only at right angles and never share a stretch.

The mark

  • On its own line: on a level stretch first, the longest one, at the free spot nearest its middle, where the mark with 4 around it touches no card, no other line and no other mark.
  • With no level stretch that fits, an upright one, by the same rule; with none at all, no mark on the line.

Recommended: our own router. A Pipeline is small (a handful of Stages, a dozen lines), so a grid search is fast enough to run on every frame, and a synchronous, pure function is what the drawer boundary and its tests need. ELK is ruled out because it can’t leave the Stages in place.

Curves

One smooth curve per route, using the same sides and points as Right angles.

Loops and limitsCurves · Light
BranchingCurves · Dark
  • Ends: the sides and points of Right angles, so a line still leaves its row’s port and a route back still enters the same edge. The curve leaves and enters square to the edge.
  • The shape: a cubic curve. Its reach is how far each of its two control points stands from its end, straight out from the edge.
  • Between facing sides (right edge to left edge, bottom to top): the curve’s reach at each end is half the gap between the two edges, at least 24 and at most half the distance between the points.
  • Back over one side (top edge to top edge): the reach is 0.3 of the distance between the points, from 40 to 160 (to 64, narrow). A longer span arcs higher, so the arcs over one edge nest instead of crossing.
  • When a card is in the way (the curve would pass within 8 of it): the route takes the shortest way round through the corners of the cards grown by 16, with the same 192 for a crossing, and is drawn as one smooth curve through those corners: a cubic piece per stretch, its direction at a corner along the line between the corner’s two neighbours, its control points a third of the stretch from each end.
  • Each further line round the same corner goes 16 further out, so two curves never run on top of each other.
  • If that curve still comes within 8 of a card, its reach is halved, twice at most; then it falls back to straight stretches with corners rounded by 12.
  • No spreading in corridors: two curves may run close to each other. They never share an end point.
  • The mark: at the middle of the curve by length, slid along it to the nearest free spot.

Straight lines

The direct line from Stage to Stage: the plainest picture of what leads where, and the one that crosses most.

Loops and limitsStraight lines · Light
BranchingStraight lines · Dark
  • Ends float: a line runs between the two cards’ centres and is cut at their edges. No line leaves from a row, so no row shows a port dot.
  • A pair (A to B and B to A): each line moves 8 to its own right-hand side, so the two run 16 apart; 12 each (24 apart) when one carries its mark on a stretch steeper than 45°.
  • Ends less than 12 apart on one edge are pushed to 12, in the order of their angles.
  • When a card is in the way (the line would pass within 8 of it): the shortest way round through the corners of the cards grown by 16 (by 24 where the line carries its mark), choosing among the ways round by their crossings. The line bends sharply, and only at those corners. Each further line round the same corner goes 16 further out.
  • A line that is clear is never bent to dodge a crossing: in this mode crossings are the price of directness.
  • A route to its own Stage: the same squared loop, with sharp corners.
  • The mark: at the middle of the line’s longest stretch, slid along the line to the nearest free spot.

Marks and pressing

  • Readable: a ≤N× mark, a box of 40 × 18, sits on its own line, with 4 clear around it of every card, every other line and every other mark. Its background hides only its own line.
  • Pressable: a press anywhere on a mark picks its route. Today only the line under it takes the press.
  • A line with no room (for example an arrow across a 24 gap) draws no mark; the route’s row shows the same ≤N×, as it always does.
  • Lines: each line keeps its 12-wide hit line along the drawn path, in every mode.
  • Tab: unchanged. A route with a row is reached at its row; a route with no row at its line. The mark itself is not a Tab stop and stays hidden from screen readers, as the row or the line already says “Route from Tests to Implement, at most 3 times”.
  • Port dots: a row shows its dot only when its line leaves from it. Rows whose line leaves the top or bottom edge show none; Straight lines and the narrow view show none at all.
  • The picked route is highlighted on its line, its mark and its row together.

The switch

  • Where: in the editor’s head, after the title and before Auto-align. A SegmentedControl (packages/ui, small) named “Route drawing”.
  • Its words: Right angles, Curves, Straight lines, with the tooltips “Around Stages, lines side by side kept apart”, “One smooth curve per route” and “The direct line from Stage to Stage”.
  • Shown in every host of the editor: Settings › Pipelines, a Project’s Pipelines, read-only flows and a Proposal on the flow. Under 560px it wraps under the title.
  • The Proposal card’s small drawing of route changes (proposed-route-changes.tsx) follows the choice and has no switch of its own.
  • Kept per browser, as a local preference: localStorage key the-office.flow-route-drawing, in a small store like shell/rail-store.ts, so every flow on the page follows a change at once. No service or contract change. The Task page’s diagram reads the same choice.
  • A stored value that isn’t one of the three counts as the default.
  • Switching redraws the lines only: no Stage moves, nothing is saved, and the pick stays.

The default is Right angles. It is the only mode that keeps lines apart in a shared corridor; it draws all three test Pipelines with no crossing, which Straight lines doesn’t; its lines leave from their own rows, so a row and its line read as one; its marks sit on level stretches, where they read best; and it is the closest to today’s drawing and to what Auto-align lays out.

  • Cards show no port dots, as today.

Performance

  • The budget: drawing the routes takes at most 4 ms of a frame while a Stage is dragged.
  • The drawing is remembered for the scene it was made from, so panning, zooming and picking redraw nothing.
  • Curves and Straight lines always draw in full: they are a few sums per line.
  • Right angles draws in full on every frame up to 24 Stages and 40 lines. The first step of building it measures a 24-Stage test Pipeline to confirm that this fits the budget, and lowers the numbers if not.
  • Over that, dragging draws roughly: only the lines of the Stage being moved, and the lines its card now blocks, are routed again; the others keep their paths. The drop draws in full.
  • Everything runs on the main thread; nothing waits for a worker.

Proposals

  • A Proposal’s proposed lines and taken-away lines are lines like any other: they go through the same pass and follow the same rules, in every mode.
  • They keep today’s looks: a proposed line dashed in the accent colour, a taken-away line dotted.
  • The line being drawn while you drag from a Stage’s + stays a straight dashed line in every mode; it takes its mode’s shape once it is dropped.

Building it

Files

  • flow/flow-routes/route-drawer.ts: the types above and ROUTE_DRAWERS.
  • flow/flow-routes/right-angles.ts, curves.ts, straight-lines.ts: one drawer each. What two of them share (the sides and points, the way round a card, the free spot for a mark) sits beside them, each in a file of its own.
  • flow/use-route-drawing.ts: the stored choice, beside use-overview-choice.ts.
  • flow-layout.ts keeps the shared geometry and loses the lane code; flow-canvas.tsx draws the chosen drawer’s result and makes the marks pressable; flow-editor.tsx gets the switch; flow-canvas.css gets the 24 gap and data-route-drawing on the canvas.

Tests

  • Per mode, on the three test Pipelines, wide and narrow: no line through a card; ends on one side stand apart; a loop’s arrow is on its target’s edge; no mark touches a card, another line or another mark; the crossings are at most the table’s; the same input gives the same output.
  • Right angles only: no two lines share a stretch.
  • flow-editor.full.test.tsx: the switch changes the drawing, the choice is stored and read back, and an unknown stored value gives Right angles.
  • An e2e that switches through the three modes and presses a ≤N× mark to pick its route.
  • A timing check of Right angles on a 24-Stage Pipeline against the 4 ms budget.

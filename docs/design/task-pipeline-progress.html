For the review

Five choices that are yours to change, and one rule worth a second look.

Yours to change

  1. “Round 3”, not “×3”, when nothing bounds the rounds. The rail already says “3 runs”, and a Stage resumed after a Decision has more runs than rounds. “×3” beside “4 runs” would read as a mistake. The same word in both forms reads as one idea. Switch it with Unbounded words in Try it.
  2. Extra large, not Large. The UI rules give Extra large to “something to look at closely”. A six to nine Stage diagram needs the width. Large (1180px) also works, with Fit making the cards about 25% smaller.
  3. The arcs over the rail go (see The rail). Keeping them in run order would need arcs going both ways and crossing each other.
  4. No Route drawing switch in the window. It follows the editor’s choice, as the Task asks. A switch there would change every flow in the browser from a read-only view.
  5. The Initiative page’s track shares the new parts (see The Initiative page). The other way is to keep its arcs, and then the two pages count loops differently.

Worth a second look: the bound in “Round n of ≤N” is 1 + the limits of the routes back that span the Stage in Pipeline order. On a branch that the route back’s span covers but the loop never passes, the bound is loose but never wrong. A Send back, Restart from… or one more round of the Definition of Done check can go past it. The chip then drops the bound (see Rounds).

In progress

The rail

What stays: the section “Pipeline · <name>”, the caption, each Stage’s mark, name, worker, state words, runs and tokens, the buttons that open Stage history, Edit for this Task, the 150px a Stage at least, and the sideways scroll that keeps the current Stage in view.

Order

  • Reached: each Stage with a run in this start, in the order of its first run (runs of an earlier start left out).
  • Jumped over: the Stages a Restart from… jumped over (Skipped) come right after the Stage whose held run it ended, in Pipeline order. That is where the walk passed them.
  • Not reached yet: the rest, in Pipeline order: Pending ones faint, Not taken ones fainter, with a dashed mark (as today).
  • Before the Task has any run, the rail is the Pipeline order, as today.

The line and the current Stage

  • The line is solid green under the reached Stages and goes on dashed under the ones not reached yet.
  • The current Stage is the Stage of the latest run of this start. It gets a Now tag over its mark, coloured as its state, and aria-current="step". Once the Task is Done or Dropped no Stage is current.
  • With branches the current Stage may sit left of later columns (Publish runs again after Resolve). The tag and the round chip keep that plain without an arc.
  • The live end of the line (green into blue) shows only when the current Stage is running and is the last column reached.

Arcs give way to rounds

  • The square arcs over the rail and their “2 of at most 3” marks are removed, along with loopBackPath, loopBackEnds and the .pipeline-rail-arc* styles.
  • Where the work went back is still said: the state words keep “· went back to <Stage>”. Stage history says “Went back to Implement (2 of at most 3)”. The diagram draws the route with its count.
  • Pressing a Stage opens its Stage history, as before. The round chip sits inside the Stage’s button, so it is no control of its own.

Stage history follows the rail’s order

  • The Pipeline in small at the top of Stage history lists the Stages in the rail’s order, so ← and → move as the rail reads.
  • Nothing else in Stage history changes.

Rounds

A round of a Stage is one arrival of the walk at it. A run resumed after a Decision, a Pause or a used-up window is the same round. Only a Stage with two rounds or more shows a chip.

Rule What it says
A new round A run starts a new round when the run before it in this start is another Stage’s, or was left by a route to its own Stage. A run after a Gate’s Send back, a Restart from… or a failed Script Stage’s send-back is another Stage’s run, so it counts.
The bound N 1 + the limits of the routes back that span the Stage. A route back spans the Stages from its target to the Stage it leaves, in Pipeline order. Each limit is the latest route.limit a run carries, which includes the times an answer allowed past it, else the Pipeline’s limit.
“Round n of ≤N” When every spanning route back has a limit and n ≤ N. At n = N the chip turns amber: the next time back will ask.
“Round n” When a spanning route has No limit, when no route back spans the Stage (the work came back by Send back or Restart from…), or when n is past N.
Words for a screen reader “Round 3 of at most 4”, “Round 3”; never the ≤ sign.

In Back from Tests twice, Tests → Implement has a limit of 3, so Implement and Tests can each have four rounds: “Round 3 of ≤4”. In Restart from… Implement the limit was used up and the user restarted. Implement is in round 5, past the bound, so its chip reads “Round 5”.

The diagram window

The same window as Open diagram opens, here on the page so it can be read beside its rules. Press a card or a step of the walk to pick a Stage. The situation, Route drawing, palette and width above apply here too.

The window

  • Dialog, Extra large, one height (86%), with Maximize left of the X, as a preview has. Maximize isn’t remembered.
  • Title: “Pipeline diagram: <Pipeline>”, with “· edited for this Task” when it is.
  • Under the head: the rail’s caption words, the publishing wait or Start over line when there is one, then the legend.
  • The bar at the foot: Close on the right, and nothing else.
  • Closing it returns focus to Open diagram.

The canvas

  • FlowViewport and FlowCanvas with readOnly, drawn with useRouteDrawing()’s choice. It follows a change made in the editor at once, in any tab.
  • It opens fitted. The canvas tools are as in the editor (−, the % menu, +, Fit, Overview), without Full screen, as Maximize does that.
  • No + on cards, no ports, no dragging, no keyboard edits, no route picking. Route rows are words, not buttons.
  • Under 560px the Stages stand in bands, top to bottom, as the editor draws them, and the side panel goes under the canvas.

Progress on the canvas

  • Stage: the mark in the card’s icon spot takes the rail’s Stage mark (kind by shape, state by colour and icon), the left edge the state’s colour, and the second line starts with the state words.
  • The current Stage is ringed in its state’s colour. A Stage with rounds has its round chip over its top edge.
  • Taken (heavy ink, 2.5px): a route the walk followed in this start, with its count when over 1 or when it has a limit: “3×”, “2 of ≤3”. Its route row reads bold.
  • Not taken (dimmed to a third): a route out of a Stage that ran and isn’t current, which the walk didn’t follow, and any route into or out of a Not taken or Skipped Stage.
  • Ahead (as the editor draws it): every other route, such as those out of Stages that haven’t run.
  • Hovering or picking a Stage lights its routes in the accent colour.

Pressing a Stage

  • Picks it: the side panel shows its mark, name, worker, state, rounds, runs and tokens, and each of its runs in this start with the route it left by.
  • Open Stage history closes this window and opens Stage history on that Stage. Closing that returns focus to the Stage on the rail. One window at a time.
  • The walk, under it, lists every run of this start in order: “3 Implement · Round 2”, its outcome, and “Went on to Tests”, “Went back to Implement (1 of at most 3)”, “Went to End”, “Restarted from Implement by <user>”. Pressing a step picks its Stage.

Accessibility

The rail

  • The Stages stay one <ol aria-label="Stages">, in the rail’s order, so a screen reader hears them as they ran.
  • Each Stage’s button is named by the Stage. Its aria-describedby points to the column’s words: state, round (“Round 3 of at most 4”) and runs.
  • The Now tag is aria-hidden: aria-current="step" says it.
  • Open diagram is a ghost button with an icon and its words, aria-haspopup="dialog", before Edit for this Task in the tab order.
  • No state is told by colour alone: each has its icon and its words.

The window

  • Tab order: Maximize, X, the canvas (arrow keys pan, + and − zoom, F fits), the Stage cards in the rail’s order, the canvas tools, the side panel, Close.
  • Each card is a button named “Tests, Script Stage: Done, round 3 of at most 4, 3 runs”. The drawing is role="group", named “Ship a change, drawn with Right angles”.
  • Routes take no focus. The walk says, in words, every route the work took, in order.
  • The legend is a list, visible above the canvas, naming each state with its mark and each kind of line.
  • With reduced motion the running pulse stands still.

The Initiative page

  • The Pipelines block’s track keeps its size (96px a Stage, stacked a Stage a row below that). It takes the same order, Now tag and round chips from the same progress model.
  • Its arcs go, as on the Task page. Stacked, a Stage’s row says its round: “Implement · Round 3 of at most 4”.
  • It has no Open diagram: its Stages open the Publishing Task’s Stage history there, as today.

## Rounds

- A round is one arrival of the walk at a Stage; a run resumed after a Decision, a Pause or a used-up window is the same round.
- N is 1 + the limits of the routes back spanning the Stage in Pipeline order, each its latest limit with the times allowed past it.
- "Round <n> of ≤<N>" when every spanning route back has a limit and n ≤ N; else "Round <n>".
- Rules: [2.3.2](../2.3.2-flows.md#a-routes-limit).

## Pipeline diagram

- An extra-large window of one height, "Pipeline diagram: <Pipeline>", opened by Open diagram, with Maximize.
- Under the head: the rail's caption, the wait or Start over line, and a legend of the Stage states and the lines.
- The Pipeline's flow, read-only, drawn in this browser's Route drawing ([pipeline-flow-editor.md](pipeline-flow-editor.md#route-drawing)), with the editor's canvas tools, without Full screen.
- Before the Task has its own copy, the library Pipeline's Stages and End position, all Pending.
- Each Stage shows its state by its mark, its edge and its words; the current one is ringed; a Stage with rounds shows its round.
- A route the walk followed in this start is drawn heavy with its count ("3×", "2 of ≤3"); one out of a Stage that ran and isn't current that it didn't follow, or touching a Not taken or Skipped Stage, is dimmed.
- Pressing a Stage shows it in the side panel: its rounds and runs, and Open Stage history, which closes the window and opens the Stage history.
- The walk: every run of this start in order, with the route it left by; a step picks its Stage.
- Closing returns focus to Open diagram.

**Round** (of a Stage):
One arrival of a Task's walk at a Stage, counted on the Pipeline rail; a run resumed after a Decision or a Pause is the same round.
_Avoid_: Loop, iteration, attempt

Building it

1 · The progress model, surfaces/work/pipeline-progress.ts

A pure function, the one this page’s script runs (progressOf below is its sketch). The rail, the window, the Pipeline in small and the Initiative track all read it. 

export interface PipelineProgress {
  /** The rail's order: reached, then jumped over after the Stage it left, then the rest in Pipeline order. */
  readonly stages: readonly ProgressStage[];
  /** The Stage of the latest run of this start; null before any run, and once Done or Dropped. */
  readonly currentKey: string | null;
  /** The routes the walk followed in this start, by the Stage they leave; `to` null for End. */
  readonly taken: ReadonlyMap<string, readonly TakenRoute[]>;
  /** Every run of this start, in order, for the walk. */
  readonly walk: readonly WalkStep[];
  /** Whether any run of this start ran: before, every route is drawn as ahead. */
  readonly started: boolean;
}
export interface ProgressStage {
  readonly taskStage: TaskStage;
  readonly reached: boolean;
  readonly rounds: number;
  /** N of "Round n of ≤N"; null when nothing bounds the rounds or n is past it. */
  readonly roundBound: number | null;
}
export interface TakenRoute { readonly to: string | null; readonly times: number; readonly limit: number | null }
  • Runs are read oldest first by number, earlierStart ones skipped. A route counts as taken when its run’s route.to is the next run’s Stage, or End. times is the latest run’s route.times.
  • isRouteBack decides which routes span a Stage. loopBacks() and its path helpers are removed.
  • currentStageIndex gives way to currentKey. railCaption keeps its words.
  • Unit tests: straight walk, a loop to its limit, a resumed run, a branch (Publish → Resolve → Publish), Restart from… back and on, Start over, Done with branches Not taken, and no runs.

2 · The canvas, shell/pipelines/flow

  • FlowStageMarkTone becomes "locked" | StageState. A progress mark draws the rail’s StageMark in the icon spot, the left edge, the state words and, for the current Stage, the ring. A round label is optional on FlowStageMark.
  • FlowOverlay gains progress?: { taken, started, quiet: ReadonlySet<string> }. flowLines() reads it into FlowLineLook "taken" (with count) and "not-taken". A route is matched by its from-Stage and to. Two routes from one Stage to the same Stage are both taken (the known limit).
  • flow-canvas.css: .flow-canvas-route-line--taken (--flow-line: var(--fg-1), 2.5px), --not-taken (opacity 0.32). The count rides the limit mark: “2 of ≤3”, or “3×”.
  • Tests beside flow-layout.test.ts: looks from an overlay, counts, End, the same-target pair, and no overlay leaving every look plain.

# 2.11 Stats

The UI spec is [docs/design/stats.html](../design/stats.html). The telemetry it reads and the Grafana it reads it from are in [5.2](5.2-stack.md); the module that owns it is in [5.3](5.3-modules.md#defaults).

**Stats** shows how The Office performs, in two tabs:

- **Tokens and cost** shows what The Office spends in tokens and in the engines' Usage windows, so the user can see what costs the most and make it cheaper. It has two levels:
  - The **basic stats** are always there. They use only data The Office already keeps, so nothing new is collected for them, and they show no cost anywhere: estimated cost isn't stored, only sent as telemetry.
  - The **full stats** show once Grafana answers: the bundled Grafana running, or the user's own Grafana with its read address in Settings › Telemetry. The Office draws them itself from Grafana's data, with estimated cost by model, Role, Stage, Pipeline and Project.
- **System health** shows how well The Office itself runs, now and over time: how long its work waits, its CPU and memory, its requests and its database queries, and what is running now. It lets the user spot a slow spell and find the route or query behind it ([System health](#system-health)).

**Names** (in the [glossary](../../GLOSSARY.md)): **Stats**, **Tokens and cost**, **Basic stats**, **Full stats**, **System health**, **Health reading**, **Statement shape**, **Grafana read address**, **Read token** and **Stage retry**. Never "dashboard" or "analytics" for Stats, "monitoring" or "performance" for System health, nor "rerun" or "attempt" for a Stage retry.

## Place

- **On the rail:** Stats is a surface at `/stats`, titled "Stats", between Projects and the Live view; the Live view stays last. Its icon is `chart-column`. It stays one item: the tabs are inside the page.
- **The tabs:** packages/ui's `Tabs` under the page's head, as Work's are, each tab going to its address: **Tokens and cost** at `/stats`, so earlier links keep working, and **System health** at `/stats/system-health`. The top bar's crumb names the tab ("Stats › System health"). Each tab's range picker sits at the right end of the tabs' row; on a narrow page it wraps under the tabs, as a `Select`.
- **The Project filter** narrows only what belongs to a Task, as `day_tokens` and the Usage windows have no Project:
  - in the basic stats, the top Tasks, Tasks done and Stage retries;
  - in the full stats, tokens and estimated cost over time (by `office.project`), the most expensive Tasks and Initiatives, and the lane of what was running.
- **Office-wide blocks** say so in their head, "Office-wide", whatever the filter: tokens per day, the Usage windows now, the Usage windows over time, and every block of System health. While a filter is set, the badge's `Tooltip` says "The Project filter doesn't narrow this: these figures belong to The Office as a whole."
- **This week** starts on Monday at 00:00 on the service's clock: the office day (`officeDayOf`, [2.7](2.7-notifications.md#defaults), "Today's figures") that is this week's Monday. So "this week", "today" and tokens per day agree near midnight and across a change of clock. Its blocks say "since Mon 16 Nov".

## Basic stats

The basic and the full stats are the Tokens and cost tab, as they were before System health. Each block says what would fill it when it is empty. They are read when the page opens and every minute while it is open.

1. **Tokens per day**, Office-wide: the last 30 office days, ending today, from `day_tokens` (Notifications' day figures). Each day stacks its input, output and cache writes. **Cache reads are shown but left out of the total**, as every token count in The Office leaves them out ([2.7](2.7-notifications.md#defaults), "Today's figures"): they are drawn in a strip of their own under the chart, "Cache reads, not counted". A day's `Tooltip` gives all four kinds and its total. The head reads "12.4M tokens in 30 days · 410k today". A day with nothing shows as 0.
2. **The Tasks with the most tokens this week**: up to 10, from the Stage runs started this week (`stage_runs.tokens`, counted as above), most first. Each row shows the Task's title, a link to its page, its Project's chip, its tokens and a bar against the first row's. Only Stage runs count, so a Task's other Threads (its planning, a person's own Thread on it) and Consultations aren't in it; a hint says so, and these figures aren't meant to match the full stats'. Empty: "No Stage has run this week yet."
3. **Usage windows now**, Office-wide: each engine that has Usage windows, in Settings › Engines' order, with its 5-hour and 7-day windows from `UsageWindowState`. Each window has a meter, how full it is and when it resets ("41% · resets 14:00", "88% · resets Mon 09:00"), amber from 90% and red when used up, as on the status strip. An engine whose windows aren't read yet shows "Not read yet". An engine without Usage windows (a Codex engine on an API key, a Copilot CLI engine, the OpenAI-compatible API) isn't listed. When none has any: "None of your engines has Usage windows."
4. **This week**: **Tasks done**, the Tasks that moved to Done this week, each counted once (from `task_state_changes`), and **Stage retries**, the Stage runs started this week whose Stage already had a run on the same Task, whenever that one ran. So a retry this week of a Stage first run last week counts.
5. **The message**, at the foot of the basic stats while there are no full stats, with its words by state (below): "Turn on Grafana in Settings › Telemetry to see more", a link to Settings › Telemetry, and one line on what the full stats add: "Estimated cost by model, Role, Stage, Pipeline and Project, the most expensive Tasks and Initiatives, and how full the Usage windows were over time."

## Full stats

The Office queries Grafana's data (its metrics and its logs, through Grafana's data source query API, [5.2](5.2-stack.md)) and draws the full stats itself, with the design system's charts. They are never Grafana panels embedded in the page, so they follow the palette, the Project filter and the [UI rules](4.1-ui-rules.md). Every chart has a `Tooltip` per point and "Show as a table", which gives its figures as a table. They are read when the page opens, when the range changes and every minute while it is open.

1. **The range:** 24 h, 7 d (the default) or 30 d, picked above the full stats and kept in the address. 24 h goes by the hour, 7 d by six hours and 30 d by the day (UTC).
2. **The coverage line**, under the range: "The full stats cover what The Office has sent Grafana since it started sending it." The basic stats still cover the time before.
3. **Tokens and estimated cost over time:**
   - **Tokens or Estimated cost**, a switch.
   - **Split by** model, Role, Stage, Pipeline or Project, from the attributes on `office.tokens` and `office.cost`.
   - The chart stacks the five largest values and "Other". The legend gives each value's total in the range.
   - The head reads "4.2M tokens · $38.10 estimated · 7 days".
   - Tokens count as everywhere: cache reads are left out, and the `Tooltip` gives them.
   - Work outside a Stage shows as "Not in a Stage". A Task's calls always carry its Pipeline and Project, in a Stage or not. A chat and an Initiative's Thread show as "No Pipeline" and "No Project".
   - Estimated cost is in US dollars, always called "estimated" ([5.2](5.2-stack.md), "Estimated cost").
4. **The most expensive Tasks and Initiatives:**
   - A Tasks or Initiatives switch shows the 10 with the most estimated cost in the range, from the `office.engine.call` records.
   - Each row shows the title, a link to its page, its Project's chip (an Initiative shows each Project it spans), its estimated cost and tokens, its Stage runs and its Stage retries.
   - Opening a row shows its **cost per Stage**: each Stage with its runs, "Run 1 · $1.20", "Run 2 · retry · $0.90".
   - The row's head says what the retries cost, "Retries: $4.10, 18%".
   - A Task's calls outside a Stage (its planning, a person's own Thread on it) show as "Outside a Stage".
   - An Initiative holds its Tasks and its own Threads, "The Initiative's Threads".
   - The Project filter narrows the Tasks, and the Initiatives to those with a Task in the filter, each still with its whole totals.
5. **The Usage windows over time**, Office-wide:
   - Each engine with Usage windows shows how full its 5-hour and 7-day windows were over the range, from `office.usage_window.used`.
   - Lines mark 90% and 100%, and a reset shows as the line dropping.
   - With several engines, a picker shows one at a time, the fullest first.
   - Under the chart, on the same time axis, runs a **lane of what was running** on that engine, "What was running on <engine>": one bar per Agent Stage run, from Pipelines' Stage runs, one row per Task, in the Task's Project colour. The Project filter narrows it.
   - A bar's `Tooltip` gives its times, the Task and the Stage. A press opens the Task.
6. **The basic stats' Usage windows now and This week** stay under the full stats. Tokens per day and the top Tasks give way to their full versions, items 3 and 4.

## System health

System health shows how well The Office runs, so that a slow spell can be seen and its cause found: the route or the query behind it. Every block is Office-wide, labelled so: the Project filter narrows none of them. Every chart is a line chart over the range's time axis, drawn with the design system's chart styles, with a `Tooltip` per reading or step (on hover and keyboard focus; one tab stop, the arrow keys step, Shift for ten, Home and End) and **Show as a table**, which gives all the block's figures, one row per reading or step. A gap in a line is a time nothing was read, such as The Office stopped for an update; the time before the first reading is hatched, "Before this start" on 1 h and "Nothing sent yet" on the longer ranges.

1. **The range:** 1 h (the default), 24 h, 7 d or 30 d, picked on the tabs' row and kept in the address as `?range=`, 1 h left out. Its steps:
   - **1 h:** each Health reading, every 5 seconds, from The Office's own readings ([5.2](5.2-stack.md), "System health"), whatever Settings › Telemetry says. Read every 5 seconds while the tab is visible.
   - **24 h** by 5 minutes, **7 d** by the hour and **30 d** by 6 hours (UTC), from Grafana, as the full stats are. Read when the range changes and every minute while the tab is visible. A step gives the highest event loop lag and connections waiting in it, the p95 times of all its requests and queries, and the mean of the rest.
2. **The source line,** under the tabs:
   - 1 h: "From The Office's own Health readings: one every 5 seconds since it started at 09:12, kept in memory for an hour." At its right end, "Updated 14:05:00 · every 5 seconds", with a live dot.
   - The longer ranges: "24 h, 7 d and 30 d cover what The Office has sent Grafana since it started sending these measurements." They hold nothing from before the release that added them.
3. **Load now:** three figures, read now whatever the range: **Sessions running** ("Engine sessions working now: in Stages, chats and Threads."), **Stage runs running** ("Agent and Script Stages running now, on any Task.") and **Browser connections open** ("Browser tabs following The Office's events now, from every signed-in device.").
4. **Responsiveness:** the event loop lag over time, **p99** and **Max**, in ms, with a dashed guide at 100 ms, "100 ms: answers feel late", shown when the scale reaches it. The head reads "9.1 ms p99 now · the longest wait 842 ms at 13:42:05" (on a longer range, "the highest p99" and the step's span); the longest wait is amber from 100 ms. The foot says in plain words what the lag is: how long The Office's own work waited for its turn.
5. **CPU and memory,** three charts side by side, one under another on a narrow page:
   - **The Office's CPU**, against one core, since The Office's own work runs on one thread: near 100%, its work queues up. Its `Tooltip` gives the share of the workstation too.
   - **The Office's memory**: **In use** (the process's resident memory) and **Heap used**, in MB.
   - **The workstation**: its **CPU** and **Memory**, in %.

   Each chart's head gives its figure now on 1 h ("now 23% of one core"), its highest on the longer ranges.
6. **Requests:** **Requests a minute** and **p95 time** over time; the head reads "18.4k requests in the last hour · p95 46 ms". Under them, **the slowest routes**: each route by its method and template (`GET /api/tasks/:id/stage-runs`), never the address asked for; a request no route answered is one row, "Unmatched: no route answered". Its columns: Route, Requests, p95, Max and **Total time**, with a bar against the first row's and each route's share of all the time, "4 min 11 s 52%".
7. **Database:** **Queries a minute**, **p95 time** and **Waiting for a connection** (the most queries waiting for one of the pool's connections at once) over time; the head reads "39.2k queries in the last hour · p95 9.8 ms · up to 7 queries waited for a connection", the waiting amber when any did. Under them, **the slowest queries**:
   - On 1 h, each **statement shape** ([5.2](5.2-stack.md), "System health"), in monospace, whole.
   - On the longer ranges, by **operation and table** (`SELECT stage_runs`), as Grafana's metrics carry no shape, "Slowest queries, by operation and table". The foot says so: "Grafana keeps queries by operation and table only, never their statements. Pick 1 h to see each statement's shape."

   The columns are as the slowest routes', with Statement shape (1 h) or Operation and table for Route, and Queries for Requests. On 1 h the foot says how a shape is made: "A statement's shape has its values and parameters made ?, its IN lists and VALUES rows made one ?, and is cut at 200 characters. The Office keeps the 500 shapes seen most."
8. **The slowest tables** are sorted by total time at first, what kept The Office busiest. Each figure column's head is a sort button (`aria-sort` on the column sorted by), largest first. They show the first 10 rows and **Show all 14**, then **Show the first 10**. Their foot says how many there are and their time in all.

## States

What Stats shows follows Settings › Telemetry and whether Grafana answers. Whatever goes wrong with Grafana, the basic stats stay.
- The three Basic states' words are the message at the foot of the basic stats, said once.
- Every other state's words go in an `Alert` above the stats, and there is no message at the foot.

| State | When | Its words | Its next step |
| --- | --- | --- | --- |
| **Basic** | Telemetry is Off. | "Turn on Grafana in Settings › Telemetry to see more." | The link to Settings › Telemetry. |
| **Basic**, your own endpoint | Your own endpoint, with no Grafana read address. | "Add your Grafana's read address in Settings › Telemetry to see more." | The link to Settings › Telemetry. |
| **Basic**, set by the environment | Any OTEL_* variable sets telemetry ([5.2](5.2-stack.md)), so The Office can't tell which Grafana to read. | "The environment sets telemetry, so Stats shows the basic stats only." | "Remove the OTEL_ variables to choose in Settings › Telemetry", with its link. |
| **Grafana starting** | Bundled Grafana is chosen and starting. | "Grafana is starting…", then "The first start pulls its image, which can take a few minutes." | None: the full stats show by themselves once it runs, read every few seconds while it starts. |
| **Couldn't start** | Bundled Grafana is chosen and couldn't start. | "The bundled Grafana couldn't start", then its problem as Settings › Telemetry says it. | The link to Settings › Telemetry, where Try again is. |
| **Unreachable** | Grafana is running or its read address is set, but a query fails to reach it: no connection, no answer within 10 seconds, or an answer that isn't Grafana's. | "Couldn't reach Grafana at http://127.0.0.1:3300", then the reason in plain words. | **Try again**, then the link to Settings › Telemetry. It is tried again every minute too. |
| **Read token rejected** | Your own Grafana answered 401 or 403. | "Grafana refused the read token", then "Grafana at <address> answered 401. Give a Viewer service account token in Settings › Telemetry." | The link to Settings › Telemetry. |
| **No data yet** | Grafana answers but holds nothing The Office sent. | "Grafana has no data from The Office yet. The full stats start with the next engine call." | None. The basic stats show as in Basic, with no message. |
| **Full** | Grafana answers with data. | The coverage line. | None. |

- **An engine without Usage windows** is left out of the Usage windows now and over time. With no engine that has any, both blocks say "None of your engines has Usage windows."
- **While the full stats load**, each full block shows its `BlockLoader` shape; the basic stats don't wait for them.
- **A query that fails partway**, such as the logs answering and the metrics not, shows the blocks that answered and Unreachable's words on the ones that didn't.

### System health's states

- **1 h always shows,** whatever the states above: it reads The Office's own Health readings, never Grafana.
- **Loading:** until the first answer, each block shows its `BlockLoader` shape (`lines`, with `rows` under it for the slowest tables), and Load now its figures' places. A new range keeps the last answer with the blocks' loaders.
- **Couldn't read:** a read that fails puts an `Alert` above the blocks, "Couldn't read System health", then "The Office didn't answer within 10 seconds. The figures below are its last answer, from 14:04:55.", with **Try again**. The blocks keep the last answer; with none yet, the Alert stands alone. The source line says "Last answer 14:04:55", with no live dot.
- **Just started:** 1 h holds only the readings since The Office started, the time before hatched "Before this start", and the slowest tables only what they have seen since. A block with no reading yet says "Nothing read yet. The first Health reading comes within 5 seconds of The Office starting." A table with no row says "No request in the last hour. Each route shows here once The Office answers one." or "No query in the last hour. Each statement shape shows here once The Office runs one."
- **The longer ranges follow the table above,** in the same words and links as Tokens and cost, and Load now shows on every range:
  - **The three Basic states:** in place of the charts, a message card with the state's words and its next step, "24 h, 7 d and 30 d read the measurements The Office sends Grafana. The last hour needs no Grafana: it comes from The Office's own Health readings.", and **Show the last hour**, which picks 1 h.
  - **Grafana starting, Couldn't start, Unreachable, Read token rejected:** the state's `Alert` above, with its next step, and the same card, titled "24 h, 7 d and 30 d show once Grafana answers." While Grafana starts, the charts show by themselves once it runs.
  - **No data yet:** its `Alert`, "Grafana has no data from The Office yet.", then "24 h, 7 d and 30 d start with The Office's next export, within a minute.", and the card.
  - **A query that fails partway** shows Unreachable's words on the blocks it fed, as in Tokens and cost.

## Defaults

- **Estimated cost** is priced from Settings › Engines › Model prices, as Daily caps and Usage estimates are. The engine's own reported cost is used only for a model with no price. Codex, Copilot CLI and OpenAI-compatible engines always report 0. See [5.2](5.2-stack.md), "Estimated cost".
- **Tokens per day and the Usage windows are Office-wide** and labelled so. `day_tokens` has no Project, so the Project filter narrows only what belongs to a Task.
- **"This week"** starts Monday 00:00 on the service's clock, the same clock as "today" (`officeDayOf`).
- **The Task attribute** is `office.task` everywhere.
- **Metric attributes carry names** (Role key, Stage name, Pipeline name, Project name), never ids. Ids appear only on spans and in the `office.engine.call` record. The one exception is `office.engine`, the engine's id: engines are few, and their names can change.
- **System health is Office-wide** and labelled so: The Office's own performance belongs to no Project.
- **Routes are named by their template, statements by their shape.** No address, id or value reaches System health: a route is its method and template, a query its statement shape in memory and only its operation and table on a metric ([5.2](5.2-stack.md), "System health").
- **1 h is the default range** of System health, and Tokens and cost keeps 7 d: the last hour needs nothing set up and shows a slow spell as it happens.

# 5.1 Shape

- **One long-running Node service** on the workstation hosts the API, the web UI, the agent supervisor and the database connection. Agents are child processes (the SDK spawns the Claude Code binary per session). No separate runner, no remote protocol; the supervisor sits behind its own boundary so it could become a separate host later. Tier 1 serves `localhost` only unless the user sets `OFFICE_HOST` to an IP address (decided with the user on 2026-10-31, for a host that runs The Office away from the workstation; no sign-in, so only on a trusted network); the LAN with a PIN and HTTPS come with the phone in tier 2. Any page the user opens in a browser can still reach `localhost` (browsers apply no cross-origin rule to WebSockets, and DNS rebinding points a site's own name at `127.0.0.1`), so the service refuses every HTTP request and WebSocket whose `Host` is not `localhost`, `127.0.0.1` or the IP address it arrived at, at its port, or that carries an `Origin` other than The Office's own.
- **Windows and Linux.** The workstation runs either, and every tier is built and checked on both. What differs (the Office data directory, shells and their rules, finding a command that can't run, ending a process tree, path length limits, where secrets live) sits behind one platform layer in the service; nothing else branches on the operating system.
- **Fresh code; functionality copied, not code.** What [03](../../.scratch/the-office/issues/03-factory-reference.md) marks "keep" is re-implemented from its described behaviour ([research/factory-reference.md](../../.scratch/the-office/research/factory-reference.md)): the lean harness with a stable cached prefix, the resume-vs-fresh rule with a standalone brief, the flat Stage result envelope, Office-owned git with a worktree per Task, the environment as data verified in a fresh worktree, loop limits and budgets, telemetry tagged with prompt features, tool output filtering and the flaky-test re-run, the screenshot trust model, the layered settings merge. Dropped: remote runners, leases, the runner protocol, the `/factory` plugin and MCP entry.

## Defaults

Gaps no ticket settled, filled with the simplest choice consistent with the tickets and accepted by the user; each says when.

- **Windows and Linux** are both supported from tier 1 ([5.1](5.1-shape.md)). (added while slicing tier 1, [24](../../.scratch/the-office/issues/24-slice-tier-1.md), accepted 2026-10-24)
- **Only The Office's own pages reach the service:** the `Host` and `Origin` checks of [5.1](5.1-shape.md), for HTTP and WebSocket alike. A request with no `Origin` (a local tool such as `curl`) passes the `Origin` check; the threat model leaves local processes out. (added while building tier 1, accepted 2026-10-25)
- **Updating The Office:** The Office updates its own git checkout, never by rebuilding itself while it runs. A daily check (the first at boot) and "Check for updates" in Settings › Updates fetch the checkout's upstream and list the commits it is behind, installing nothing. Update is refused, with the reason, when the checkout has local changes, has diverged from its upstream or has none, or the service runs without its launcher; on Windows updating isn't offered (Linux only). Once the user schedules an Office update (held in memory, so a restart cancels it), new Starts join the queue with "An update is scheduled." and each Task waits before its next Agent or Script Stage; Cancel releases both. The update waits for the busy work (an Agent mid-turn in a Stage, a chat or a Consultation; a Script Stage; a Publish; a clone or an environment check), not for a Task waiting on the user, a paused Task or an idle Thread. When nothing is busy the service writes the request, stops gracefully and exits with code 75; the launcher (`npm start`, under systemd) fast-forwards to the target commit, runs `npm ci` and the build, and starts the service again. A failed fetch, install or build goes back to the previous commit and rebuilds it. At its next start the service raises an Office Notification that it updated, or that the update failed at which step, with the log in Settings › Updates. How to run it: [docs/running-the-office.md](../running-the-office.md). (added with the Office update task, accepted 2026-11-03)

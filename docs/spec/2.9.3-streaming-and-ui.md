# 2.9.3 Streaming and the UI

Covers: reading the list, web events, subscriptions, catching up, the read-only view, the line and the view.

## Live streaming to the web

- The pattern is the Conversations web events' (`ThreadWebEvents`, through the platform's `WebEventForwarding` and `EventStream`): each event names the Thread and its home.
- Unlike a Thread's other events, which are signals to refetch, these carry what changed, as `thread.tokens-counted` carries its tokens, since output is too frequent to refetch.

## Reads

They are on Conversations' controller.

- `GET /api/threads/:threadId/sub-agents-and-processes`: the Thread's current session's Sub-agents and Processes.
  - Each has its `callId`, `engineTaskId`, kind, who started it, description or command line, state, ending, times, and the sequence of its last message or output chunk.
  - It holds no messages and no output.
- `GET /api/threads/:threadId/sub-agents/:callId/messages?after=<sequence>`: its messages and tool calls after that sequence (all of them, as kept, without it).
- `GET /api/threads/:threadId/processes/:callId/output?after=<sequence>`: its output after that sequence, with how much earlier output wasn't kept.

## Web events

| Web event | Carries | Sent to |
| --- | --- | --- |
| `thread.sub-agent-started`, `thread.sub-agent-changed`, `thread.sub-agent-ended` | `threadId`, `home`, `item`: the whole Sub-agent as the list reads it | every page subscribed to the type |
| `thread.process-started`, `thread.process-ended` | `threadId`, `home`, `item`: the whole Process as the list reads it | the same |
| `thread.sub-agent-messages` | `threadId`, `home`, `callId`, its new messages and tool calls, each with its sequence | only pages subscribed to that type **for that Thread** |
| `thread.process-output` | `threadId`, `home`, `callId`, `chunk`: one chunk of new output with its `sequence` (masked, whole lines) | the same |

## Scoped subscriptions

- Output reaches only the Thread it belongs to.
- A subscription is an event type with an optional `threadId` (`platform/websocket/event-stream.ts`, the contracts' `clientMessageSchema`, the web's `apps/web/src/api/event-stream.ts`).
- `thread.sub-agent-messages` and `thread.process-output` are sent only to subscriptions scoped to their `threadId`; a subscription without a scope gets the other types.
- A page subscribes to the two, scoped to its Thread, while the view is open, and unsubscribes as it closes.

## The list needs no catch-up

- Each start, change and end event carries the whole item, and the page puts it in its list by `callId` (the contracts' `withSubAgentOrProcess`).
- A state only moves forward: once ended, an item never goes back to Running.
- An older copy never replaces a newer one: each item counts its changes (`revision`), and the higher wins.
- So these events apply safely in any order, before, during or after the list's read.

## Catching up when a page opens late

- A page that opens late catches up a Sub-agent's messages and a Process's output without missing or doubling anything:
  1. It subscribes first, scoped to the Thread, and holds the events that arrive.
  2. It reads the open item's messages or output, which answer up to a sequence.
  3. It applies what it holds, and then each live event, only after that sequence; an event at or before it is already in the read and is dropped.
  4. An event whose sequence skips ahead (a missed one), or the WebSocket reconnecting, reads again from the last sequence it has (`?after=`).

## Read-only

- The view has no stop controls: no Stop on a Process, no Stop on a Sub-agent, no Stop all.
- Only the Agent stops them (TaskStop), or the session's end does.
- The window says so in its bar ("Only the Agent can stop them").

## The UI

### The line

- It is above the message input of a Thread, wherever a Thread has one: in the chat drawer, on a Task page's conversation and in a Stage run's Thread tab in the Stage history.
- Where a Thread takes no message, it is above the line saying why.
- It shows only once the session has had a Sub-agent or a Process.
- While any runs: a live dot and "2 sub-agents, 1 process running", singular "1 sub-agent running", a kind with none left out, then "· 3 ended" when some ended, with "1 failed" in red.
- Once none runs: "3 sub-agents, 1 process ended", no dot.
- The whole line is one button.
- It shares its row with the context reading ([2.5](2.5-context-policy.md)), which keeps the row's right end at its own width, so neither moves the other.

### The view

- It is a list and details.
- In the chat drawer and on the Task page it opens in a large window, "Sub-agents and processes", which keeps one height.
- In the Stage history, which is already a window, it is the run's third tab, beside Summary and Thread.
- On a narrow page the list and the details stack, with a "‹ All" row back to the list.

### The list

- Running is on top, then Ended, the one that ended last first, each in a line or two.
- A line has a mark for its kind, the description or command, its state and how long it ran.
- A Sub-agent also shows its context size beside the time ("3m 12s · 45k context"), updated while it runs as the engine reports progress and kept from its end; with no figure from the engine nothing shows, never a 0.

### The details

- A picked Sub-agent shows its prompt's first lines with "Read it in full", then its messages and tool calls in Rows with the Details switch on its row, as a Thread has them.
- A picked Process shows its command whole, then its output in monospace, following the end while it runs until the user scrolls up, with Jump to the end.

## Defaults

### What the web events carry

- A Thread's other events are signals to refetch; the Sub-agent and Process events carry what changed.
- Output reaches only pages subscribed for its Thread.

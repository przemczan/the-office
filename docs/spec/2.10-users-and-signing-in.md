# 2.10 Users and signing in

The Office has several **users**, and everyone signs in before using it, localhost included. Every user can do everything. A user is never a person of The Office: people are the Roles the users hire ([2.2](2.2-people.md)).

- **Users:** the first user is created at first run, in **First-run setup**: while no user exists, the sign-in page asks for the **setup token** and the first user's name, email and password instead. The installer creates no user. The setup token unlocks that step, so whoever reaches The Office first over the network can't claim it: the service's first start (or `npm run setup-token` on the host) makes one and prints it with the address to open, and The Office keeps only its hash. A missing, wrong or replaced token is refused with how to print a new one, before any field is checked. A start with a token already waiting prints none, only how to get one, so a restart never replaces the installer's. The first user uses the token up. Then First-run setup walks the first user through the basics, each skippable: the engine and its login, Sign in with GitHub for git, and telemetry ([5.2](5.2-stack.md)). Every signed-in page leads there until they finish or skip the rest, which closes it for good; an Office that already had users never sees it. After that, any signed-in user adds an account for someone else in Settings › Users with their name and email; The Office shows a **one-time password** once, which the adding user passes on, and the new user sets their own password at their first sign-in. A user can be removed there, which signs out all their signed-in devices at once; what they did keeps their name. Emails are unique, compared without case.
- **Ways to sign in:** a password, **Continue with GitHub**, **Continue with Google** or a **passkey**. After a password, Continue with GitHub or Continue with Google, The Office asks for an **authenticator code** once the user has set up an **authenticator** on their account; a passkey is enough on its own. A **recovery code** may stand in for an authenticator code.
- **Linking:** each user links their own GitHub and Google identities and adds their passkeys from their account, signed in. Continue with GitHub and Continue with Google sign in only a **linked identity**, found by the provider's own id for it (GitHub's numeric user id, Google's `sub`), never by matching an email or a login; an identity linked to one user can't be linked to another. Unlinking or removing a passkey is the user's own, from their account.
- **Continue with GitHub is not Sign in with GitHub.** Sign in with GitHub is The Office's own git identity ([5.5](5.5-git-and-isolation.md)), one and shared. Continue with GitHub signs a user in through the same GitHub App, by its user authorization flow, with no new registration: The Office reads who the GitHub user is, revokes the token GitHub handed out at once and keeps nothing of it, and never touches the git identity's sign-in or token. It is offered whenever the App is registered. Continue with Google needs a Google OAuth client the user creates and enters in Settings › Signing in, one shared by every user, its secret kept as the GitHub App's is ([6](6-permissions-and-safety.md)).
- **Which ways work on which address:** The Office is used at `localhost`, by IP on the local network over plain HTTP (a trusted network), or at its **public address**, behind a reverse proxy the user sets up with HTTPS and a domain ([5.1](5.1-shape.md)). The sign-in page shows only the ways that work on the address it was opened at:

  | Address | Password | Continue with GitHub | Continue with Google | Passkey |
  |---|---|---|---|---|
  | `localhost` | Yes | Yes | Yes | Yes |
  | A loopback IP (`127.0.0.1`) | Yes | Yes | No | No |
  | A local network IP over HTTP | Yes | Yes | No | No |
  | The public address (HTTPS) | Yes | Yes | Yes | Yes |

  Passkeys need a secure page and a name, not an IP; Google sends a user back only to `localhost` or HTTPS. A passkey works only at the address it was added at (its relying party is that name), so a user who uses both `localhost` and the public address adds one at each. GitHub sends a user back only to a callback URL listed in the App's settings, so Settings › Office identity shows the URLs to add for this address and the public address. An authenticator code is asked for wherever the way before it works.
- **Staying signed in:** signing in sets a cookie that is `HttpOnly`, `SameSite=Lax` (so GitHub's and Google's redirects back carry it), `Path=/`, and `Secure` when the page came through the public address over HTTPS. Its token is random and stored only as a hash, one per **signed-in device**, with the browser it came from, the kind of address, when it signed in and when it was last used. A signed-in device is never called a session ([glossary](../../GLOSSARY.md)).
- **Signed-in devices:** each user sees theirs on their account, this one marked, and signs out any of them; a device signed out answers its next request with the sign-in page, and its open WebSocket closes. **Sign out** in the top bar's user menu signs out this device. Removing a user or the host command signs out every device of that user.
- **Slow-down and lockout:** wrong passwords, authenticator codes and recovery codes count against the user they were for. The first few cost nothing; then each try waits longer, and then the user's password and codes are locked for a while, with the time to try again shown. An unknown email gets the same answer, in about the same time, as a wrong password. The count is kept in the database, so a restart doesn't reset it. A passkey still signs in during a lockout. The numbers are in the Defaults.
- **Recovery:** a user who lost their authenticator signs in with a recovery code, each one used once, shown once when the authenticator is set up and made anew on request (the old set then stops working). A user who lost their password, or every way in, gets back in through a command on the host, `npm run set-password -- --email <email>`, which asks for a new password twice, lifts the lockout and signs out all that user's devices; with `--clear-authenticator` it also removes their authenticator and recovery codes, for a user who lost both. Anyone who can run commands on the host can already read The Office's data, so the command asks for nothing more. A lost setup token is printed anew the same way, `npm run setup-token`, which ends the earlier one; once a user exists it refuses and points to `set-password`.
- **Who did what:** records name the user who did each thing ([2.1](2.1-work.md), [2.4](2.4-conversations.md)), and an Agent's Brief says which user asked ([2.5](2.5-context-policy.md)).
- **Per user and shared:** each user's own are their account (name, email, password, authenticator, recovery codes, linked identities, passkeys, signed-in devices), their palette and density ([4](4-ux-direction.md)), and where Since you left begins for them ([2.7](2.7-notifications.md)). Shared by every user: The Office's people, Projects, Pipelines, Memory, Office instructions, Notifications and Needs you (a Notification handled by one user is handled for all), and every Decision, which any user can answer. The Office identity, Sign in with GitHub and the Office ssh key, stays one, shared, for git.
- **What every request needs:** every HTTP request to `/api` and every WebSocket needs a signed-in device, from `localhost` too, except the sign-in pages and their callbacks (`/api/sign-in/**`), `/api/health` (it says only whether the database is up, and the launcher and the tests poll it) and the Claude Code `-p` hook, which has its own token ([5.4](5.4-the-engine.md)). The web app's own files (`index.html`, scripts, styles) are served to anyone: they hold no Office data, and the sign-in page needs them.

## Defaults

- **Password rules**: at least 12 characters and at most 256, any characters, no other rule; a password that equals the user's email is refused. Hashed with Node's `scrypt` ([6](6-permissions-and-safety.md)). Changing one's own password asks for the current one and signs out every other device of the user.
- **The one-time password**: 16 random characters from an alphabet without look-alikes, shown once to the user who added the account, with Copy; it works for one sign-in within 7 days, which goes straight to setting the new user's own password; an unused one can be made anew in Settings › Users, which ends the old one.
- **Slow-down and lockout**: per user, the first 3 wrong tries in a row cost nothing; each further one waits 2, 4, 8 and then 16 seconds before the next try is taken (the service answers when to try again, never sleeps); the 10th wrong try in a row locks the user's password and codes for 15 minutes, and each lockout after that, before a right try, for twice as long, up to 24 hours. A right sign-in resets the count. The host command lifts it.
- **How long a device stays signed in**: 30 days after its last use, so a device used at least once a month stays signed in until it is signed out; the last use is written at most once a minute.
- **Recovery codes**: 10, each 10 characters in two groups of 5, from an alphabet without look-alikes, stored only as hashes.
- **The authenticator**: the standard 6-digit, 30-second codes (TOTP, SHA-1), with one step of drift either side; set up by scanning a QR code or typing its key, and confirmed with a first code; a code is taken once. Removing the authenticator asks for a current code or a recovery code.
- **Removing users**: a user can't remove themselves, and the last user can't be removed.
- **The setup token**: 24 random characters from the one-time password's alphabet (about 119 bits), printed in groups of four and read with or without the dashes, in either case; kept only as its SHA-256, compared in constant time, in no log record or event. One at a time, with no expiry: a new one ends the old, and the first user uses it up. The service writes a new one straight to standard output, never through its logger, so journald and `docker logs` show it and telemetry never exports it. `npm run setup-token -- --quiet` prints the token alone, for an installer; it exits with 1 once a user exists and 2 for other arguments.
- **Skipping the basics**: `OFFICE_SKIP_SETUP_BASICS=true` lets an automated install leave out First-run setup's basics; never the setup token or the first user. Like every Office variable, no Project command inherits it.
- **Records from before users**: whatever a record says the user did before users existed names the first user.
- **Since you left per user**: The Office keeps each user's last activity, so Since you left begins after each user's own five idle minutes ([2.7](2.7-notifications.md#defaults)).

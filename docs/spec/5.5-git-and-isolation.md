# 5.5 Git and isolation

- **A worktree per Task** at a stable path under the Office data directory; The Office owns every git change: branch and worktree creation, a commit per Stage (message from the Stage result and handover note), worktree restore after each test run, discarding an interrupted Stage's uncommitted edits, push and PR or merge at Publish.
- **Guards:** a git-mutation deny list for Agents plus a HEAD and branch check after every Stage, since command patterns can be bypassed.
- **Environment as data:** the Project's environment (`set`, `unset`, `prependPath`) is stored outside the checkout and applied to every command and Agent; the environment check runs in a fresh worktree of the base branch before it is saved.

## Defaults

Gaps no ticket settled, filled with the simplest choice consistent with the tickets and accepted by the user; each says when.

- **Install inputs:** a Project lists the files whose change makes a worktree install again (a lockfile, say), given when it is added and edited on its page beside the install command. A worktree installs when it is created and again when the install command or one of those files changes; with none listed, once. (added while building tier 1, accepted 2026-10-25)
- **The base branch's upstream** is where the freshly fetched base comes from: worktrees start at the remote branch it tracks, fetched first. A base branch that tracks nothing is used as it is, unfetched, and the environment check says so. (added while building tier 1, accepted 2026-10-25)
- **Clones** (tier 3): a Project added by Repository URL is cloned, in full, into `<office-data>/repositories/<host>/<owner>/<repo>`, so a second add of the same URL is caught; the clone runs in the background with its progress shown, and a folder left by a failed add is reused. (the user, 2026-11-01)
- **The Office identity** (tier 3, the user's answer of 2026-11-01): every git command The Office runs, for a Project (added by path too) or not (a Skill's Source, Devops reading a URL), uses only The Office's own credentials, shared by all Projects and separate from the user's:
  - a GitHub https remote: the Sign in with GitHub user token, handed to git for that one command by a credential helper Office code answers; never in an environment variable, a remote URL, a git config file or a command line, which hooks, filters and Agents could read;
  - an ssh remote, on any host: the Office ssh key alone, generated and kept by The Office in its data directory, its public half shown in Settings for the user to add to the host; ssh runs with no agent, none of the user's ssh config or keys, and The Office's own known hosts: GitHub's host keys from GitHub's published list, any other host's key trusted only once the user confirms its fingerprint;
  - any other https remote: anonymously, so public repositories only.

  git is kept from the user's credentials: their credential helpers are cleared for every command, and git never prompts (`GIT_TERMINAL_PROMPT=0`, `GCM_INTERACTIVE=never`). A Project's page says which part of the identity its remote needs and what is missing. Pull requests are opened through GitHub's API with the token; without Sign in with GitHub there are none.

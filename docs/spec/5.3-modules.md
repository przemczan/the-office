# 5.3 Modules

Hexagonal + DDD, modules as bounded contexts: **Work**, **People**, **Pipelines** (definitions and the Stage interpreter: an interpreter of Pipeline data, never a class with a method per Stage), **Conversations**, **Projects** (git, worktrees, environment, commands), **Engine**, **Skills**, **MCP servers**, **GitHub**, **Notifications**, **Telemetry**.

- Each is layered inside: domain (entities, rules, events), application (use cases), ports, adapters (Postgres, engine, filesystem, HTTP, WebSocket).
- Modules talk through application services and domain events only; no module reads another's tables.
- Every state change emits a domain event, consumed alike by the WebSocket push, Now, telemetry, Notifications and (tier 2) the Office Manager's read-only view.

## Defaults

Gaps no ticket settled, filled with the simplest choice consistent with the tickets and accepted by the user; each says when.

- **Skills is its own module,** next to People and Engine, since it owns the library, versions and assignment, and builds each session's folder from them; the Engine takes the folder and the options from the session's owner and never reads Skills (agreed with the user on 2026-10-25) ([12](../../.scratch/the-office/issues/12-architecture.md) predates [23](../../.scratch/the-office/issues/23-skills.md)). (accepted 2026-10-24)
- **MCP servers is its own module,** shaped like Skills: it owns the MCP server library, its review, assignment to Roles, the Server values (Office-wide and per Project) and each session's servers; the Engine takes the session's servers in its options and never reads the module (the user, 2026-10-31).
- **GitHub is its own module:** it owns Sign in with GitHub (the GitHub App registered by its manifest, the device flow, the user token and its refresh) and the list of the user's repositories; Projects and Skills reach the token through ports of their own, bound to it in the app module. The Office ssh key and the git environment that keeps every Office git command to the Office identity sit in the platform layer, with where secrets live ([5.1](5.1-shape.md)) (the user, 2026-11-01).
- **Now lives in the Notifications module** (the user's answer of 2026-10-27): Needs you and Since you left are the Notifications' inbox (2.7), so Now and the status strip are one read model there, built from the other modules' events and application services; no module calls Notifications. (added while building tier 1)

# 5.4 The engine

- **An `AgentEngine` port, not Claude-shaped:** start a session with a brief, send a message with priority, interrupt, resume, read usage, the tool-permission hook; each adapter declares which capabilities it has and The Office degrades where one is missing. A Role picks its engine and model.
- **Adapters:** the TypeScript Claude Agent SDK on the user's own login (tier 1); `claude -p` as fallback (tier 2); others later. One long-lived streaming `query()` per session.
- **Native features used:** message `priority` for barge-in (`next` between tool calls, `later` after the turn); `interrupt()` for Stop, the only way to stop a running command (`now` is not used: it ends the turn but leaves a running command to finish or run on in the background); resume by session id; the 1-hour prompt cache on the main conversation; in-process Office tools via `createSdkMcpServer()`; `rate_limit_event` and the experimental usage query for the 5-hour and 7-day windows (never the CLI's OAuth token).
- **Engine features turned off:** claude.ai connectors (`disableClaudeAiConnectors`); the engine's built-in plugins (each set false in `enabledPlugins`); auto-memory (`autoMemoryEnabled` and `autoDreamEnabled` false), whose folder outside the worktree is shared by every worktree of a repository and written without a prompt. Memory is The Office's own (Shared memory, tier 2). The built-in tool set is an explicit `tools` list, the same on both platforms (the engine's Windows default today, PowerShell on Windows only), since the engine's Linux default drops Grep and Glob for shell search; trimming it per Role is open, with its cost measured in [engine-check.md](../engine-check.md).
- **Cache breakers to avoid mid-session:** changing model, effort, MCP servers (with tool search off) or the Claude Code version.
- **Versions are pinned** (the SDK bundles the binary) and bumped deliberately, re-checking what was read from the binary ([5.6](5.6-skills-per-session.md), [6](6-permissions-and-safety.md)) with the engine check ([engine-check.md](../engine-check.md)).

## Defaults

Gaps no ticket settled, filled with the simplest choice consistent with the tickets and accepted by the user; each says when.

- **The `-p` fallback matches the Agent SDK adapter:** the Office tools reach its sessions through the binary's own stream, as the SDK does (an in-process MCP server answering the binary's `mcp_message` requests), and the Office rules through a hook that asks the service on `localhost`, so any Role can work with it. Not an MCP endpoint on `localhost`: over HTTP a tool's answer can overtake a barge-in message on the binary's input, which the engine check saw on Windows (amended 2026-10-30). The hook's token is made per session and reaches its Agent's commands, so it reaches nothing beyond its own session's hook, which judges by that session's rules (accepted 2026-10-30); what it can't match, as the engine check finds, it declares missing. A Role picks it in its Engine field ("Claude Code -p"); there is no Office-wide switch. It runs the pinned Claude Code binary the SDK bundles, with the same models, and has its own runs in the [engine check](../engine-check.md) on Windows and Linux. (added while slicing task 29, accepted 2026-10-30)
- **The OpenAI-compatible API engine is The Office's own agent loop** ([8](8-open-questions-and-risks.md)), for local LLMs and any server on that API: the user lists the API endpoints in Settings → Engines (a name, the base URL, a key kept in the database and never sent back, empty for a local server, and the models with their context windows), and a Role picks it in its Engine field ("OpenAI-compatible API"), its Model field naming an API endpoint and one of its models. Replies stream. The loop gives the model the built-in tools under the Claude Code engines' names and inputs (Read, Grep, Glob, Edit, Write, the shells, WebFetch, WebSearch, Skill), so the same Office rules judge every call before the loop runs it, and runs commands in the background as the SDK's sessions do (started, their output read, stopped; ended on Stop and when the session ends). WebSearch goes through a search endpoint set Office-wide behind a port, SearXNG's JSON API the only one built. It lists exactly the session's skills and loads them by name ([5.6](5.6-skills-per-session.md)), keeps the conversation under the session's folder in the Office data directory so it resumes, and reads its context usage for the Context policy ([2.5](2.5-context-policy.md)); it has no usage windows and reports no cost. Any Role may pick it; The Office refuses only what it declares it can't do. (added while slicing task 35, accepted 2026-10-31)

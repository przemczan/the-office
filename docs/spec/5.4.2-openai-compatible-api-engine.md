# 5.4.2 The OpenAI-compatible API engine

Covers: the agent loop, API endpoints, Sees images, built-in tools, search endpoint, skills, context usage.

## Defaults

### The OpenAI-compatible API engine is The Office's own agent loop

- It serves local LLMs and any server on that API.
- The user lists the API endpoints in Settings → Engines.
- An API endpoint has a name, the base URL, a key and the models with their context windows.
- The key is kept in the database and never sent back; it is empty for a local server.
- Each model has **Sees images**, off by default.
- With Sees images on, the model gets a message's images as image parts.
- With it off, the message names each image and its Attachment id and says the model can't see pictures.
- Each API endpoint is an engine of its own, its models the engine's.
- Replies stream.
- The loop gives the model the built-in tools under the Claude Code engines' names and inputs: Read, Grep, Glob, Edit, Write, the shells, WebFetch, WebSearch, Skill.
- So the same Office rules judge every call before the loop runs it.
- The loop runs commands in the background as the SDK's sessions do: started, their output read, stopped; ended on Stop and when the session ends.
- WebSearch goes through a search endpoint set Office-wide behind a port; SearXNG's JSON API is the only one built.
- The loop lists exactly the session's skills and loads them by name ([5.6](5.6-skills-per-session.md)).
- It keeps the conversation under the session's folder in the Office data directory so it resumes.
- It reads its context usage for the Context policy ([2.5](2.5-context-policy.md)).
- It has no usage windows and reports no cost.
- Any Role may pick it; The Office refuses only what it declares it can't do.

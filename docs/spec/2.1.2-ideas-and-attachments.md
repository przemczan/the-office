# 2.1.2 Ideas and Attachments

Covers: Idea, Dropping and Restoring an Idea, an Idea's History, shaping an Idea, Attachment, replacing an Attachment, text files, PDFs, pasted images.

## Idea

- Captured quickly, in a Project or Office-wide.
- States: new, shaped, dropped.
- It may record the Task it was found while working on, set only as it is captured and never changed ([2.1.3](2.1.3-tasks.md#found-while-working-on)); its record and its card on the Ideas page show it ([Ideas](screens/ideas.md)).
- Its title, notes and Project are editable until it is shaped, by the user and, with `edit_idea`, by whoever captures Ideas in a Thread ([5.4.1](5.4.1-engine-kinds.md#office-actions)).
- An Idea not shaped yet can be Dropped, and a Dropped one Restored, new again: by the user, and with `drop_idea` and `restore_idea`.
- Each call is ruled by the person's [Authority](6-permissions-and-safety.md#authority) for Ideas, which can differ on their own work and on others' ([6 Authority by role](6-permissions-and-safety.md#authority-by-role)).
- Its History lists its state changes and the edits of its title, notes and Project, naming who ([2.1.3 History](2.1.3-tasks.md#history)).
- Shaping makes an Initiative or a Task and keeps the Idea as the origin link; its Attachments move with it.
- An Agent shapes with `shape_idea_into_task`, `shape_idea_into_initiative` and `plan_idea_as_task` (Plan as a Task, which opens the Planner's Thread), the same routes as the user's click, ruled by the person's Authority for Ideas, where an Idea they captured is their own work; the Idea shows Shaped afterwards.
- A Task shaped from an Idea takes the Idea's notes as its Description, editable until Start.
- Shape into a Task makes a Feature, or a Bug or a Chore when chosen ([Task kind](2.1.3-tasks.md#task-kind)); a Bug shaped from an Idea with no notes takes the Bug outline as its Description ([New Task](screens/shell.md#create)).
- Plan as a Task makes a Feature.
- An Initiative shaped from an Idea captured in a Project starts in that Project ([2.1.5](2.1.4-initiatives.md#an-initiative-starts-in-its-ideas-project)).
- Shaping into an Initiative works with or without a CTO ([2.1.5](2.1.4-initiatives.md#shaping-without-a-cto)).

## Attachment

- A document (Markdown), image or screenshot, file or link.
- Attached by the user or an Agent to an Idea, Initiative or Task, or by the user to a message in a Thread.
  - An image pasted into a Thread is kept as an Attachment of the Task or Initiative the Thread is on, else of the Thread itself ([2.4](2.4-conversations.md)).
- Can be a Task's result.
- Diffs and Stage logs are parts of a Task, not Attachments.
- A Task's Attachments are shown by round, each the work between one Gate send-back and the next.

## Replacing an Attachment

- `attach_file` attaches to a Task either a file from the Task's worktree, in a Thread that has it, or an image the user sent in the Thread, by its Attachment id; the replace rule below holds for worktree files only.
- A worktree path from a Thread without the Task's worktree, or an image the Thread didn't get, is refused by the tool's check before the call is held, so no approval is spent on it ([5.4.1 One ruling step](5.4.1-engine-kinds.md#one-ruling-step)).
- An Agent attaching a file to a Task (with `attach_file`, or a screenshot its Stage result lists) **replaces** the Attachment an Agent attached from the same worktree path to that Task since the user last acted at a Gate on it (any Gate action; before any, since the work started), so a Gate shows each file once, at its latest copy.
- What a Gate already showed the user is never changed.
- The replaced Attachment keeps its id and its place (`addedAt`, so its round stays), and takes the new file's bytes, size, media type, text judgement and text, and who attached it last.
- The old copy isn't kept.
- Links, anything the user attached and anything on an Idea or an Initiative are never replaced.

## Text files and PDFs

- A file Attachment is a **text file** when its bytes are text: valid UTF-8 with no NUL byte in the first 8 KB, the NUL test being the one the API engine's Read and Grep use.
- A document is always a text file; an image or a PDF never is, as each is read and shown as what it is.
- The Office judges it once, as the file is attached, and keeps it with the Attachment; its kind doesn't change, so a `.css` is still a file.
- A PDF's text is pulled out once as it is attached, a page marker line before each page, and kept beside the file.
- A PDF with no text, such as a scan, reads as having no text.

## Pasted images

- An image, such as a screenshot, can be pasted from the clipboard in "New Task", Capture an Idea and Attach.
- One without a real file name is named "Pasted image <date> <time>.png", with no character Windows forbids in a file name.
- A paste that also holds plain text pastes the text and attaches nothing.

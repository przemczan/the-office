# 2.4.4 Messages

Covers: barge-in, Office actions in Threads, Mentions, Copy, images in a message, Open page, commands in the message box.

## Barge-in

- The user writes into a running Stage Thread at any time, from its Thread in the Stage history.
- The user writes into every other Thread while the person is answering: a chat, a person's Thread on a Task (the Planning Thread included) and an Initiative's Threads.
- The message is logged at once, shown "Lands at the next safe point", and lands at the next safe point (between tool calls) of the turn running, then shows "Delivered".
- One sent before its turn took it keeps the person answering until they have answered it too.
- One that never reached the person, because the answer failed, was stopped or the session ended, shows "Not delivered: <name> finished first" (a Stage Thread's: "the Stage ended first").
- Answering a Decision while the person is answering stays refused.
- Stop and Pause: [2.4.5](2.4.5-stopping-and-restarts.md).

## Office actions in Threads

- See [5.4](5.4-the-engine.md).
- Every Thread the user talks to a person in (a chat, a person's Thread on a Task, the Planner's, an Initiative's shaping and planning Threads, a Consultation) also has the tools of the Office actions the person's held duties cover.
- A Thread whose tools create a record (`create_task`, `capture_idea`, `create_initiative`) also has the tools of the Office actions that record's creators cover: changing, Dropping, Archiving and Restoring Tasks, Ideas or Initiatives ([5.4.1](5.4.1-engine-kinds.md#office-actions)).
- So everyone but the Default person to talk to changes Tasks, everyone changes Ideas, and whoever may create Initiatives changes them, in every Thread the user talks to them in ([6](6-permissions-and-safety.md#a-persons-office-tools)).
- An Agent Stage has none.
- In an Initiative's shaping Thread, its Tasks' dependencies and which Tasks it has change straight away through them, even once it is active, the person's Role authority being the gate.
- Its other changes are still drafted as Proposals.

## Mentions

- Any Task, Initiative, Idea or Decision can be mentioned in any chat (link or `@`), and the Agent there can read its record.
- Every session's standing instructions say to write a Task, Initiative, Idea or Project as a Markdown link to its page with its full ID, never a shortened one.
- They also say to put text the user is meant to copy in a fenced code block.
- A message shows a link to a Task, Initiative, Idea or Decision as its chip.
- A link to any other page of the app opens it in place, and any other link in a new tab.

## Copy

- Every fenced code block and every quote in a message or a Markdown document has Copy in its top-right corner.
- It copies exactly its text (a code block's code, a quote's words) and says so in a toast.
- Where the browser offers no clipboard, such as over plain http from another computer, the toast says it couldn't be copied.
- Copy link on a record and the Office ssh key's Copy work the same way.

## Images in a message

- The user pastes or drops PNG, JPEG, GIF or WebP images into any Thread's message box: a chat, a person's Thread on a Task and its first-message box, a Stage Thread, a Consultation, an Initiative's shaping and planning Threads.
- Limits: 3 MB each, 10 per message and 15 MB in all; the message box and The Office both check.
- A message may be images alone; a skill command carries none.
- Each image is uploaded at Send and kept as an Attachment: of the Task in a Thread on a Task, of the Initiative in an Initiative's Thread, else of the Thread itself.
- A retry after a failed send reuses the uploaded ones.
- The message keeps its images and shows them as thumbnails that open full size in the Attachment viewer; one whose Attachment was removed shows "Image removed".
- A Claude Code, Codex or Copilot CLI engine gets them as pictures with the message, a new session's first message and a barge-in included.
- An API endpoint model gets them as pictures only when it **Sees images** ([5.4](5.4-the-engine.md)); else the message names each image and its Attachment and says the model can't see pictures.
- A fresh session's Brief lists a past message's images by name and Attachment id, or "Image removed", and `read_attachment` reads them.

## Open page

- A message sent from the chat drawer can go with the page open beside it, when that is one of:
  - a Task's (a Decision window on it still counts as the Task);
  - an Initiative's;
  - an Idea open on Work › Ideas;
  - a person's or a Project's page, any tab or section of it.
- It goes only when the message mentions it as `@open page`, which the `@` picker offers first; a message that doesn't goes without it.
- The page is the one open as the message is sent: the mention names no record, so it follows navigation.
- Any other page has none, and `@open page` there is ordinary text.
- A Task's or an Initiative's own conversation sends none, being about its record already.
- The person answering is given its record under its own heading, after the message and its Mentions:
  - a Task's, Initiative's or Idea's as a Mention's;
  - a person's as its short record in `list_people`;
  - a Project's as its record in `list_projects`.
- A Project's record holds what the Project's page shows:
  - its commands, publishing, default Pipeline, Project limit and Run environment;
  - its environment (each Secret variable by name and whether a value is set, never its value) and last environment check;
  - its engine levels, its skills and its Server values (a secret one by name alone).
- A record the message mentions already isn't given twice.
- Within one session the same Open page is given again only once it changed since the previous message.
- A session that starts on the message has it in its Brief.
- The log keeps the message's Open page, shown under it as "With <chip> open".

## Commands in the message box

- A message is a command only when "/" is its first character and its first word names an Office command or one of the Thread's skill commands, an Office command first.
- Any other message, a "/" elsewhere or an unknown first word included, is sent and logged as an ordinary message.
- Every Thread the user writes in offers commands but a Stage Thread, where a "/" message stays ordinary.
- Typing "/" lists the Office commands first, then the skill commands, each labelled by kind with its description, narrowing as the user types.

### Office commands

- They never reach the engine, so they work the same on every engine (Claude Code's own commands are not passed through).
- Each is an action the Thread already has.
- **/clear** chooses Start fresh for the next message, as the context control does ([2.5](2.5-context-policy.md)).
  - The history stays on screen and the next message starts a new session with the Brief rebuilt from the record.
  - With no session yet to start fresh from, the composer says so.
- **/help** lists the Office commands and the Thread's skill commands above the composer, with no request and no model call, and nothing is logged.
- There is no /stop: no action stops the turn of a person's Thread (a Task's Stop holds the Task and discards the Stage's edits), so a person's Thread has no Stop.

### Skill commands

- "/<skill> [input]" runs that Skill in the session, as Claude Code's slash commands do ([2.6](2.6-skills.md)).
- The Thread offers the library Skills the session that takes the next message has (its recorded ones when it continues or resumes, else those a new session would get), never a Project's Skills nor one whose name an Office command takes.
- It reaches the engine as a skill command, with no user-message heading and no Mentions or Open page around it.
- A new session's Brief still carries them and goes first, and the command follows.
- The log keeps the message as written and shows it as a skill command.
- One sent while the person is answering is refused, saying to send it once they finish, and isn't logged: a skill command is never a barge-in.

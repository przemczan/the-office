# 5.2 Stack

- **TypeScript end to end on Node 22.**
- **Backend:** NestJS (modules, DI, ports as interfaces, adapters as providers); WebSocket push to the browser.
- **Web:** React + Vite, TanStack Query and Router, the design system's components.
- **Data:** PostgreSQL with Drizzle (typed SQL, repositories in the adapter layer); full-text search; JSONB for Stage results and Attachment metadata. Attachments are files in an Office data directory with metadata in Postgres. Engine transcripts stay where the engine keeps them, referenced by session id; The Office's own message log per Thread is what the UI shows.
- **Infrastructure:** one `docker compose` with PostgreSQL and `grafana/otel-lgtm` (optional from tier 3, when the user sends the telemetry to their own Grafana instead: [3](3-capabilities-by-tier.md#tier-3-on-need)). The Office exports OpenTelemetry over OTLP: one trace per Task, spans per Stage and per engine call with token counts; metrics for tokens, cost, queue depth and Stage durations; logs.
- **Signing in** ([2.10](2.10-users-and-signing-in.md); chosen by the CTO for the Initiative "User authentication", 2026-11-13): Node's built-in `node:crypto` `scrypt` for password, one-time password and recovery code hashes, and its random bytes and SHA-256 for sign-in tokens; `@simplewebauthn/server` and `@simplewebauthn/browser` for passkeys; `@oslojs/otp` for authenticator codes; `arctic` for Continue with Google; the GitHub module's existing GitHub App for Continue with GitHub. No auth framework: better-auth and its like bring their own user, session and account tables and names, which would split the [glossary](../../GLOSSARY.md)'s one language, and "Session" there means only the engine's session.

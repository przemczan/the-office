# 5.2 Stack

- **TypeScript end to end on Node 22,** in npm workspaces: `apps/service`, `apps/web`, `packages/contracts` (the HTTP and WebSocket contract as zod schemas, the one thing the service and the web share), `packages/ui` (the design system for React) and `tools/`. Checks: TypeScript strict, oxlint, Prettier, Vitest, Playwright.
- **Backend:** NestJS on Express (modules, DI, ports as interfaces, adapters as providers); WebSocket push to the browser (`ws`); the Claude Agent SDK, the pinned `@openai/codex` and the MCP SDK for the engines ([5.4](5.4-the-engine.md)).
- **Web:** React + Vite, TanStack Query and Router, the design system's components; react-markdown for long text; PixiJS for the Live view.
- **Data:** PostgreSQL with Drizzle (typed SQL, repositories in the adapter layer); full-text search; JSONB for Stage results and Attachment metadata. Attachments are files in an Office data directory with metadata in Postgres. Engine transcripts stay where the engine keeps them, referenced by session id; The Office's own message log per Thread is what the UI shows.
- **Infrastructure:** one `docker compose` with PostgreSQL for a checkout; `grafana/otel-lgtm`, the bundled Grafana, unless the user turns telemetry off or sends it to their own Grafana. The Office runs the bundled Grafana itself, on every install kind (checkout, direct install, Compose install), as its own Compose project `the-office-grafana` from a compose file it writes to `grafana/compose.yaml` in the Office data directory: the image pinned in the service's code, Grafana at `http://localhost:3300` and OTLP at 4317 (gRPC) and 4318 (HTTP), all published on `127.0.0.1` only, its data in a named volume, `restart: unless-stopped`. It needs a Docker The Office can reach, as run environments do. Choosing Bundled Grafana starts it at once in the background, and Settings › Telemetry shows it starting, running with its link, or why it couldn't start, with Try again. At every start of The Office it is started when Bundled Grafana is saved or that run exports to it, and stopped (its container and data kept) when Off or the user's own endpoint is saved and nothing exports to it; while nothing wants it and The Office never started one, The Office doesn't call Docker for it. With any of the OTEL_* variables below set, The Office neither starts nor stops it. An earlier bundled Grafana (the `otel-lgtm` service of Compose project `the-office`, or a container named `the-office-grafana` started by hand) is stopped, never removed, before The Office starts its own, and the log and the card name it. The Office exports OpenTelemetry over OTLP, as **Telemetry** below lists. Telemetry is a setting, in First-run setup and Settings › Telemetry: Off, the bundled Grafana (its OTLP endpoint at `http://127.0.0.1:4318`) or the user's own OTLP over HTTP endpoint with optional headers and export timeout; saved in the Office data directory readable by its owner only, as headers can hold credentials, never sending a header's value back to the browser, and the exporters switch to it the next time The Office starts. Any of `OTEL_SDK_DISABLED`, `OTEL_EXPORTER_OTLP_ENDPOINT` or `OTEL_EXPORTER_OTLP_HEADERS` in the environment wins over it, and the card then says so, read-only; with neither, telemetry is off.
- **Telemetry**, what The Office sends. The service is `the-office`; every name is in the `office.` namespace, as the GenAI conventions count cached tokens inside input tokens.
  - **Traces:**
    - One trace per Task. Its first span, `walk`, carries `office.task` and `office.pipeline` (the Pipeline's id, as a span may carry ids). It is kept with the Task, so a walk after a restart or a Gate joins the same trace.
    - A `stage` span per Stage run, with `office.stage`, `office.stage.kind` and `office.stage.run`.
    - An `engine call` span per engine call (a turn), with:
      - `office.engine.session`, `office.engine.model`, `office.prompt.features`, `office.engine.outcome` and `office.engine`;
      - the four token counts (`office.tokens.input`, `office.tokens.output`, `office.tokens.cache_read`, `office.tokens.cache_creation`) and `office.cost.usd`, the estimated cost;
      - the caller's own attributes: on a Task, `office.task`, `office.thread`, `office.role` and, in a Stage, `office.stage`; on an Initiative, `office.initiative`.
    - HTTP requests and database queries, traced by OpenTelemetry's HTTP, Express and pg instrumentations.
  - **Metrics:**
    - `office.tokens` (`{token}`), a counter by `office.token.type` (`input`, `output`, `cache_read`, `cache_creation`).
    - `office.cost` (`USD`), a counter of the estimated cost.
    - Both carry `office.engine.model`, `office.prompt.features` and `office.conversation.home` (`task`, `initiative`, `chat`), and also ([2.11](2.11-stats.md)):
      - `office.role`, the Role key;
      - `office.stage`, the Stage's name, `""` outside a Stage;
      - `office.pipeline`, the Pipeline's name;
      - `office.project`, the Project's name.
      Each is `""` where none applies.
    - Metric attributes are names with few values, never ids: a Task, Thread, Initiative or session id goes only on spans and in the `office.engine.call` record. `office.engine` is the one id on a metric, as engines are few and their names can change.
    - The HTTP instrumentation's request durations.
  - **The `office.usage_window.used` gauge** (`%`, 0 to 100) shows how full each Usage window is. It carries `office.engine` (the engine's id) and `office.usage_window` (`five_hour`, `seven_day`), and is recorded at each reading of the windows, whatever its Reading source. A window not begun records 0.
  - **Logs:**
    - The service's log lines, each with the trace and span it was written in.
    - One **`office.engine.call`** record (INFO) per engine call that ends with a turn. It is written in the call's span, so it carries its trace; a call that ends without a turn writes none. It holds:
      - `office.task`, `office.initiative` (the Task's Initiative, or the Initiative whose Thread it is), `office.thread`, `office.stage`, `office.stage.run`;
      - `office.role`, `office.pipeline`, `office.project`;
      - `office.engine`, `office.engine.model`, `office.engine.outcome`, `office.engine.call.duration_ms`;
      - `office.tokens.input`, `office.tokens.output`, `office.tokens.cache_read`, `office.tokens.cache_creation`;
      - `office.cost.estimated_usd`, when the call has an estimated cost, and `office.cost.engine_reported_usd`, when the engine reported a cost. The reported cost is never added to the estimate.
      An attribute that doesn't apply is `""`. These records are what the full stats total per Task, Initiative, Stage and run, and what draws the lane of what was running.
  - **Estimated cost:** an engine call's cost is priced from its tokens by Settings › Engines › Model prices (`ModelPrices`), as Daily caps and Usage estimates are. The engine's own reported cost is used only for a model with no price. Codex, Copilot CLI and OpenAI-compatible engines always report 0, so without a Model price their calls cost 0. It is always called "estimated": a subscription doesn't pay list prices.
- **Stats reads Grafana** ([2.11](2.11-stats.md)):
  - **The bundled Grafana** is read at `http://127.0.0.1:3300` with no token, while it runs.
  - **Your own Grafana:** with "Your own endpoint" chosen, Settings › Telemetry also takes, under the export fields, a **Grafana read address** (the Grafana the endpoint feeds, such as `https://grafana.example.com`) and a **Read token** (a Viewer service account token, made in Grafana under Administration › Service accounts).
    - Both are optional: without the read address, Stats shows the basic stats.
    - The token is kept as the export headers are, in the Office data directory readable by its owner only. It is never sent back to the browser: its field says "Saved, never shown. Leave it empty to keep it."
    - Both apply as soon as they are saved, with no restart, as only Stats reads them; the exporters aren't changed.
    - **Test** queries the Grafana with the address and token as typed, before Save, and says one of three things:
      - **Reachable**, "Grafana answered at <address>.", naming the Prometheus and Loki data sources it found;
      - **Rejected**, "Grafana refused the read token (401).";
      - **Unreachable**, "Couldn't reach Grafana at <address>: <reason>."
      A Grafana that answers with no Prometheus or Loki data source the token may query is reported as reachable, with "but it has no Prometheus and Loki data sources the token can query."
  - With any OTEL_* variable set, Stats reads no Grafana and shows the basic stats only.
  - **Querying:** both are read through Grafana's data source query API (`POST /api/ds/query`): PromQL on its Prometheus data source for `office.tokens`, `office.cost` and `office.usage_window.used`, and LogQL on its Loki data source for the `office.engine.call` records.
    - This sits behind the Telemetry module's port **`StatsSource`** ([5.3](5.3-modules.md#defaults)), with a Grafana adapter and a scripted adapter for tests. The scripted one replays recorded answers: data, empty, unreachable and rejected.
    - A query that takes more than 10 seconds counts as unreachable.
    - Titles, Projects' chips, people's names and titles (by Role key) and engine names come from The Office's own modules, never from Grafana.
- **Signing in** ([2.10](2.10-users-and-signing-in.md)): Node's built-in `node:crypto` `scrypt` for password, one-time password and recovery code hashes, and its random bytes and SHA-256 for sign-in tokens; `@simplewebauthn/server` and `@simplewebauthn/browser` for passkeys; `@oslojs/otp` for authenticator codes; `arctic` for Continue with Google and Continue with <name> (its OAuth 2.0 client, with the provider's endpoints read from its discovery document by Node's `fetch`); the GitHub module's existing GitHub App for Continue with GitHub. No auth framework: better-auth and its like bring their own user, session and account tables and names, which would split the [glossary](../../GLOSSARY.md)'s one language, and "Session" there means only the engine's session.

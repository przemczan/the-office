# 2.15 Actions

Covers: Action, its kinds (Project command, Test target, Workflow), Leaves the workstation, what an Action runs from (a branch, a Task or an Initiative), Action run, where a run runs, what The Office sets, its states, its log, its history, when a run stops, how runs count against limits, who starts an Action, defining Actions on the Project page and by Devops' Proposal, the Actions feature switch, Actions at once, an Action's time limit, Action runs kept.

## Action

- An **Action** is a named entry in a Project's settings: something the user runs on demand, outside the Task queue, such as "Install on my phone" or "Release".
- It has:
  - a key, by the same rules as a Project command's key ([2.1.1](2.1.1-projects.md#project-commands)), fixed once added;
  - a name, at most 60 characters;
  - a kind ([Kinds](#kinds));
  - the settings of that kind;
  - whether it **Leaves the workstation** ([Leaves the workstation](#leaves-the-workstation)).
- It is stored in the database only, as a Project setting, never in a repository.
- Each value records who set it last: the user, or a Proposal, naming the Agent who drafted it, as a test target's does ([2.12](2.12-test-instances.md#test-target)).
- Agents read a Project's Actions in its record (`list_projects`): each one's key, name, kind, settings and whether it leaves the workstation, and its last run's state.
- It is never an Office action ([2.4.4](2.4.4-messages.md#office-actions-in-threads)), which is something the user or an Agent does on a record, nor a GitHub Actions run, which is a CI run ([2.1.6](2.1.6-board-and-search.md#the-ci-tab)).

## Kinds

- Each kind runs machinery The Office already has; an Action adds no way of running code of its own.
- **Project command:** runs one of the Project's commands by its key ([2.1.1](2.1.1-projects.md#project-commands)). Its settings:
  - the command's key;
  - optional: the commands before it, some of the Project's commands by their keys, `install` among them, in order, as a test target's ([2.12](2.12-test-instances.md#commands-before-the-entry-point));
  - optional: one of the Project's devices ([2.13](2.13-connected-devices.md#a-projects-device)), held by the run's environment while it runs;
  - optional: its own time limit ([Defaults](#an-actions-time-limit)).
  - It never takes a command line: the command line is the Project command's, set in Commands.
- **Test target:** launches one of the Project's test targets ([2.12](2.12-test-instances.md#kinds)). Its settings: the target's key.
  - The run is a test instance: it counts as one, shows in Test instances, and has a test instance's states, log and rules.
  - Build to install and Install on a device are the kinds it is meant for; a Hosted target works too, the run lasting while the instance runs.
- **Workflow:** starts one of the repository's Workflows that declares a start by hand (GitHub's `workflow_dispatch`), as Work › CI's Start a workflow does ([2.1.6](2.1.6-board-and-search.md#the-ci-tab)). Its settings:
  - the Workflow's file, by its name as Work › CI lists it, such as `release.yml`;
  - its inputs, each fixed when the Action is saved, checked against what the file declares on the base branch, as Start a workflow checks them;
  - the run starts on the branch chosen, with those inputs; nothing is asked at start.
- A kind's setting that names something the Project doesn't have (a command key, a target key, a device, a Workflow the base branch doesn't declare) is refused when written, naming it; one gone since fails the run at its start, naming it.

## Leaves the workstation

- An Action is marked **Leaves the workstation** when what it runs pushes, publishes, deploys or releases: anything that reaches people or systems outside this Office.
- The user marks it; an Action is marked as it is added as a Workflow, or changed to one, and the user may clear it.
- A Proposal may mark an Action, never clear the mark ([Defining Actions](#defining-actions)).
- Its rules are in [6 Actions](6-permissions-and-safety.md#actions).

## What it runs from

- Each start chooses what the Action runs from:
  - a **branch** of the repository or its remote;
  - a **Task** of the Project that has a branch, which means its branch, as The Office last committed it (work not yet committed in its worktree isn't in it);
  - an **Initiative** with a branch in the Project, which means the Initiative's branch ([5.5](5.5-git-and-isolation.md#the-initiatives-branch)).
- The base branch is chosen until the user picks another.
- The choice is the Project page's Branch picker, the one test instances launch with ([project-page.md](screens/project-page.md#the-branch-picker)).
- The branch's tip is fetched and run, as a test instance's is ([5.5](5.5-git-and-isolation.md#a-test-instances-checkout)).
- An Action that leaves the workstation runs from the base branch only ([6](6-permissions-and-safety.md#actions)).
- A Workflow runs on the code host, so it runs from a branch the remote has; a Task's or Initiative's branch the remote doesn't have is refused, naming it.

## Action run

- An **Action run** is one start of one Action, on what was chosen.
- It records:
  - its Action, by key, and the Action's name and kind as they were at its start;
  - what it ran from: the branch, or the Task or Initiative with its branch;
  - the commit it ran, the branch's tip at its start (a Workflow run's, as the CI run reports it);
  - who started it, and when;
  - its state ([States](#states)), when it ended, and its exit code or why it ended;
  - for a Test target run, its test instance; for a Workflow run, its CI run and its page on the code host.
- A test instance an Action launched shows in Test instances as any instance, saying "Run as <Action>".

## Where a run runs

- **A Project command run** runs in its own detached checkout of the commit, made as a test instance's is ([5.5](5.5-git-and-isolation.md#an-action-runs-checkout)), with nothing installed.
  - With the Project's Run environment On, in its own compose project from the `.devcontainer/` of that checkout, in the definition's service, as a Task's checks run ([5.5](5.5-git-and-isolation.md#an-action-runs-checkout)).
  - With Run environment Off, on the workstation, in the checkout, as checks run there ([2.3.1](2.3.1-stages.md#script-stages-in-the-run-environment)); an Action naming a device needs Run environment On, as a device does ([2.13](2.13-connected-devices.md#what-it-attaches-to)).
  - It gets the Project's environment and Secret variables, as a Task's checks do, masked in its log ([5.5](5.5-git-and-isolation.md#secret-variables)), and what The Office sets ([What The Office sets](#what-the-office-sets)).
  - It never gets The Office's own credentials: no Office identity, no GitHub sign-in, no engine. An Action that pushes or publishes keeps its token in a Secret variable, as Publish's before and after lines do ([2.3.4](2.3.4-publish.md#publishs-before-and-after-lines)).
  - Its checkout has no `.git` ([5.5](5.5-git-and-isolation.md#a-test-instances-checkout)), so git in it reads nothing and pushes nothing.
- **A Test target run** runs where its test instance does ([2.12](2.12-test-instances.md#test-instance)).
- **A Workflow run** runs on the code host; The Office only starts it, with its own sign-in, as Start a workflow does, and follows it as a CI run.

## What The Office sets

- In a Project command run, in the commands before it and the command alike:
  - `OFFICE_ACTION`, the Action's key;
  - `OFFICE_ACTION_BRANCH`, the branch it runs from;
  - `OFFICE_ACTION_COMMIT`, the commit it runs;
  - `OFFICE_CONNECTED_DEVICES` and, with one phone, `ANDROID_SERIAL`, when it names a device ([2.13](2.13-connected-devices.md#what-agents-see)).
- A Project variable of the same name is refused when a Project command Action is saved, naming it, and so is saving a Project variable of one of these names while the Project has one.

## States

- **A Project command run:** **Running** → **Succeeded** (the command ended with 0), **Failed** (with why) or **Stopped** (with who or what stopped it).
  - Failed says why: a command before it or the command ending with exit code N, a command or the device missing, the `.devcontainer/` invalid (with its problems), the device not answering, the run passing its time limit.
- **A Test target run:** its test instance's states ([2.12](2.12-test-instances.md#test-instance-states)), Built or Installed counting as succeeded, Stopped as stopped, Failed by the user's Stop ("Stopped by you.") as stopped, and any other Failed as failed.
- **A Workflow run:** **Starting** while The Office asks the code host and waits for the CI run to show, then the CI run's status ([2.1.6](2.1.6-board-and-search.md#the-ci-tab)).
  - Its CI run is the first run of that Workflow on that branch, started by hand by The Office's sign-in, created after the start was asked.
  - One that doesn't show within 60 seconds ends the run Failed: "<code host> didn't show the run in 60 seconds; it may still run there.", linking the Workflow's runs.
  - A start the code host refuses is Failed, in its words.
  - A CI run ending in success counts as succeeded, cancelled or skipped as stopped, and any other end as failed.
  - Its commit is the one the CI run reports; one other than the commit the confirm step showed is written on the run, "It ran <commit>: <branch> moved as it started.".
- A run is **running** until it reaches an end state: Succeeded, Failed or Stopped for a command run, Built, Installed, Stopped or Failed for a Test target run, and a CI run no longer queued, waiting or running for a Workflow run.
- Which runs raise an Outcome Notification, and when: [2.7](2.7-notifications.md#action-run-outcomes); a Test target run raises its test instance's, never one of its own.

## Log

- Each run has one log.
- A Project command run's: the checkout, then each command's output, each named first, then how it ended.
- A Test target run's is its test instance's log ([2.12](2.12-test-instances.md#log)).
- A Workflow run's: the start, its inputs and the CI run's link; the job logs stay on the code host, linked from it.
- It is masked as Stage runs are: a Secret variable's value shows as `[secret NAME]` ([5.5](5.5-git-and-isolation.md#secret-variables)).
- It streams while the run is running, and is kept with the run ([Action runs kept](#action-runs-kept)).

## History

- Each Action lists its runs, newest first: what each ran from, its commit, who started it, when, how long it took and its state.
- Each run's log opens from its row.
- The runs kept are in [Action runs kept](#action-runs-kept).

## When a run stops

- A Project command run stops:
  - when a user presses Stop (Stopped, naming them);
  - at its time limit (Failed, "The run ran out of its N minutes.");
  - when something else ends its device's hold while it runs, such as Run environment turned Off or the relaying tab closed (Failed, "<device> was let go of: <why>.");
  - under the fire alarm's Safe pause ASAP (Stopped, "Stopped by the fire alarm.", [2.8](2.8-fire-alarm.md#actions-during-the-alarm));
  - when the Project's Actions feature is switched off (Stopped, "Actions were switched off for <Project>.");
  - in the sweep when The Office starts, which stops every command run left running (Stopped, "The Office restarted while it ran.").
- Stopping removes its containers, its volumes and its checkout and lets go of its device; its log stays.
- What an Office update or restart does with a running command run: [5.1.2](5.1.2-updates-and-restarts.md#updating-the-office).
- A Test target run stops as its test instance does ([2.12](2.12-test-instances.md#when-an-instance-stops)); Stop on the run stops the instance.
- A Workflow run is the code host's: The Office never cancels it, and Stop isn't offered; the CI tab's own controls apply.

## Limits

- An Action run counts against none of:
  - the queue for Start ([2.1.5](2.1.5-planning-and-start.md#a-queue-for-start));
  - the Project limit ([2.1.1](2.1.1-projects.md#project-limit));
  - any person's Task limit, or the Office-wide limit on running Tasks ([2.2](2.2-people.md#limits));
  - Run environments at once ([5.5](5.5-git-and-isolation.md#the-other-limits-of-run-environments)).
- A Project command run counts toward [Actions at once](#actions-at-once).
- A Test target run counts toward Test instances at once instead ([2.12](2.12-test-instances.md#test-instances-at-once)).
- A Workflow run counts toward no limit of The Office: it runs on the code host.
- **One run of each Action at a time:** a start while its last run is running is refused, "<Action> is running already, started by <user> <when>."
- A start over a limit is refused, naming the limit and what holds it; it is never queued.
- The run environments' CPU, memory and process limits apply to a command run's services as to a Task's ([5.5](5.5-git-and-isolation.md#the-cpu-limit)).

## Who starts an Action

- Any signed-in user, from:
  - the Actions tile on the Project's Overview ([project-page.md](screens/project-page.md#actions-tile));
  - the Project page's Actions section ([project-page.md](screens/project-page.md#actions)).
- No Agent starts an Action: no Office tool starts one.
- The run records who started it, as every record does ([2.1.3](2.1.3-tasks.md#who-did-what)).

## Defining Actions

- In the Project page's Actions section ([project-page.md](screens/project-page.md#actions)): add, change and remove.
- Or by an Agent whose Change Project settings allows it, with `change_project_settings`, which refuses an Action marked Leaves the workstation ([6 Project settings by Agents](6-permissions-and-safety.md#project-settings-by-agents)).
- Or by Devops' Proposal: the Office tool `propose_actions`, a Proposal of kind `actions`, the one way an Agent sets up an Action that leaves the workstation:
  - it may add Actions, change an Action's values by key and remove Actions by key;
  - it follows the rules of the test targets' Proposal ([2.12](2.12-test-instances.md#writing-test-targets)): the user applies it all or nothing on its card, it is refused once a value it changes has changed since it was drafted, and a value the user set is never overwritten silently;
  - it may mark an Action Leaves the workstation, never clear the mark;
  - it is checked by the same rules as the Project page.
- Devops adds them, or drafts one:
  - **at onboarding,** in the Onboard Task, once the Project's commands and test targets are set: the Actions its repository suggests, such as a manual release Workflow or an install of a debug build ([2.1.1](2.1.1-projects.md#onboarding-a-project));
  - **on request,** from the chat **Ask <Devops> to propose Actions** opens on the Actions section.
- Removing an Action removes its runs and their logs; a running one is stopped first. A test instance one of its runs launched stays in Test instances by its own rules.

## The Actions feature switch

- Actions is a Project feature switch, key `actions`, needing no other feature, on by default ([2.1.1](2.1.1-projects.md#project-settings)).
- Switched off: the Project page's Actions section and the Overview's Actions tile are gone, the service refuses every start, write and Proposal of the Project's Actions, "Actions are switched off for <Project>.", and running command runs stop.
- The Actions and their history are kept, and come back when it is switched on.
- While it is off, the guard on a Workflow file a Leaves the workstation Action starts is lifted: Work › CI's Start a workflow and an Agent's `start_workflow` start it as any other ([6](6-permissions-and-safety.md#actions)).

## In a test instance of The Office

- A test instance of The Office (`OFFICE_TEST_INSTANCE=true`) refuses every Action start, "A test instance of The Office (OFFICE_TEST_INSTANCE) doesn't run Actions." ([6](6-permissions-and-safety.md#test-instances)).

## Defaults

### Actions at once

- How many Project command runs may be running together across The Office: 2 by default, 1 to 6.
- Set in Settings › Office limits' Actions card ([settings.md](screens/settings.md#office-limits)).
- A start over it is refused, naming the runs: "2 Actions are running: Build web on main, Lint on fix-login. Stop one to start another."
- Lowering it stops none: the next start is refused until fewer are running.

### An Action's time limit

- A Project command run may run 60 minutes, its commands before it included, unless the Action sets its own, 1 to 240 minutes.
- A Test target run keeps its kind's ([2.12](2.12-test-instances.md#build-time)); a Workflow run has none of The Office's.

### Action runs kept

- The newest 20 runs of each Action are kept with their logs; an older one is removed as a newer one ends.
- A Test target run's test instance is kept by its own rules ([2.12](2.12-test-instances.md#kept-build-to-install-files)); the run's row keeps its link.

### Implementation notes

- Storage:
  - `actions`, owned by Projects: `project_id`, `key`, `name`, `kind`, `settings` (jsonb), `leaves_the_workstation` and who set each value;
  - `action_runs`, owned by Actions: the Action's key, name and kind at its start, what it ran from (`source_kind`: `branch`, `task` or `initiative`, with the Task's or Initiative's id), the branch, the commit, who started it, its state, its times, its exit code or why it ended, and its test instance or CI run;
  - Actions at once, as an Office setting.
- Module: `apps/service/src/modules/actions/` ([5.3](5.3-modules.md#the-modules)).
- The Proposal kind `actions`; the tool's name constant sits beside `PROPOSE_TEST_TARGETS_TOOL`.
- Files: each command run's checkout `<office-data>/action-runs/<run id>/`, removed as it ends, and its log `<office-data>/action-runs/<run id>.log`, kept with the run.
- HTTP routes:
  - `GET` and `PUT /projects/:id/actions`;
  - `GET /projects/:id/actions/runs`, each Action's runs, newest first;
  - `GET /projects/:id/actions/source`, with the source as query parameters: the commit and subject a start from it would run, as the Run window shows them, or why it can't be read;
  - `POST /projects/:id/actions/:key/runs`, `{source: {kind: "branch", branch} | {kind: "task", taskId} | {kind: "initiative", initiativeId}, commit?}`; `commit` is required for an Action that leaves the workstation, the one its confirm step showed, and the start is refused when the branch moved since ("main moved to f00ba12 since you looked. Run it again to run that commit.");
  - `POST /action-runs/:id/stop`;
  - `GET /action-runs/:id/log`;
  - `GET` and `PUT /settings/actions`.
- Web events: `action-run.changed`, carrying the Project and the Action's key; `action-settings.changed`, as Actions at once changes.

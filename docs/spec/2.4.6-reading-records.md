# 2.4.6 Reading records

Covers: reading the Stage history, reading the Threads.

## Reading the Stage history

- Every person's chat, Thread on a Task and Consultation, and every Agent Stage, reads a Task's Stage history with the Office tools, to diagnose its runs.
- The whole history gives each run in the order they ran, with:
  - its Stage, start and end, outcome, Handover note, Decisions and their answers, engine, model and tokens;
  - its Project commands with their filtered output;
  - for an Agent Stage's run, how many messages its Stage Thread logged during it.
- The earliest runs are left out when their words alone would crowd the outputs out of the cap.
- One run can be read with each command's whole output, as the Stage history shows it.
  - For an Agent Stage's run it also gives its Stage Thread's messages from the run's start to its end (or to now while it runs), worded as `read_threads` words them.
- One run's answer is capped at 60 000 characters.
  - The outputs and the messages share what its words leave, each getting at least half and the rest of what the other doesn't need.
  - Each output keeps its end.
  - Cut messages say how many are left out and that `read_threads` reads on, with the Task, the run's times and the message to read on after.
- A Task with no runs gets a plain sentence: The Office has no Task of that id, or the Task hasn't started and the state it is in.
- It reads the Stage run records and The Office's log only, never a file under the Office data directory or an engine's transcript.
- It names a test run's moved files by their worktree paths.
- An Agent Stage reads it so a retry, Review & fix or Verify that needs a command's whole output, or what an earlier Agent tried, doesn't repeat a failed approach: its Brief carries only the last failure's filtered output.

## Reading the Threads

- Every person's chat, Thread on a Task and Consultation reads the Threads' messages with the Office tool `read_threads`.
- It reads those logged in a range of dates or times, narrowed by:
  - a person (their Role);
  - a Task;
  - a Project (its Tasks' Threads and those of the Initiatives spanning it; chats have none);
  - a text.
- The answer is grouped by Thread with its subject (the Task's or Initiative's title, or whose chat it is).
- Each message has its time, its speaker (the user, the person by name and Role, or The Office) and its text.
- Tool activity shows as its one-line summary.
- Decisions show as their questions with the answers and comments, or asked again with the general comment.
- Proposals show as their title with their state.
- The answer is capped at 60 000 characters: one long message keeps its start and its end, and a full answer says how many messages it leaves out and the message to read on after.
- A filter that names nothing, a range ending before it starts or one with no messages gets a plain sentence.
- It reads The Office's log alone, never a file or an engine's transcript, so nobody needs the database; it writes nothing.
- An Agent Stage doesn't read it: it reads Thread messages only through a run's Stage Thread, in the Stage history.

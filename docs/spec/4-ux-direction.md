# 4. UX direction

From [11](../../.scratch/the-office/issues/11-surfaces.md), [16](../../.scratch/the-office/issues/16-layout-mockups.md), [17](../../.scratch/the-office/issues/17-task-page-mockup.md), [18](../../.scratch/the-office/issues/18-people-mockup.md), [19](../../.scratch/the-office/issues/19-work-mockup.md), [01](../../.scratch/the-office/issues/01-export-design-system.md).

**The click-through is the UI spec**, but for the chat, whose spec is [the adopted chat drawer](../design/chat-drawer.html), and for a Project page's Pipelines section and Settings › Pipelines' office-wide Pipelines with Built on by and the warning on saving a base Pipeline, whose spec is [the adopted Project Pipelines design](../design/project-pipelines.html). [prototypes/app/](../../.scratch/the-office/prototypes/app/index.html) is a complete, interactive layout of every surface, accepted in three steps ([17](../../.scratch/the-office/issues/17-task-page-mockup.md), [18](../../.scratch/the-office/issues/18-people-mockup.md), [19](../../.scratch/the-office/issues/19-work-mockup.md)). The real shell is built from it: its structure, flows and copy, re-implemented in React with the design system's components. Where the click-through shows a tier 2 or 3 feature, tier 1 leaves it out rather than stubbing it.

- **Five surfaces:** **Now** (home: Needs you, Running, Since you left, today's tokens; nothing else), **Work** (per Project: Ideas, the Task board by state, Initiatives with their graph), **People** (a grid of same-size cards; a page per person with Overview, Work, Conversations, Role card, Memory; hiring), **Projects** (a page per Project: commands, default Pipeline and publishing, onboarding checks, the repository's skills, Appearance with its mark, Icon and Logo, and from tier 3 its Engine block: the Project default, "Use for every Role" and the Project's Role overrides), **Settings** (Pipelines and the skill library, Office limits, Notifications, Appearance; from tier 3 the Office identity: Sign in with GitHub and the Office ssh key, in Office limits the measures usage estimates show and the Window caps and Daily caps (per account for the Claude Code engines, one set for the OpenAI-compatible API), and in Engines the Model prices; and the Office instructions, a page of their own ([2.2](2.2-people.md)); Users, where users are added and removed; and Signing in, where Continue with Google is set up ([2.10](2.10-users-and-signing-in.md))). Outside the five surfaces, the sign-in pages stand alone, without the shell, and the top bar's user menu holds the signed-in user's name, **Account** (their own page: name, email, password, authenticator, recovery codes, linked identities, passkeys, signed-in devices) and **Sign out**.
- **Project Pipelines** (2026-11-12, the Initiative 5006c803; [2.3](2.3-pipelines.md#defaults), "Project Pipelines" and "A Broken Project Pipeline"): Project Pipelines live on their Project's page, in its **Pipelines** section (which replaces Default Pipeline): the default first, its picker offering the Project's own Project Pipelines and the office-wide ones and flagging the default when it is Broken, then the Project's own Pipelines, the default marked, with "Add a Pipeline built from…"; the editor opens beside that list. Settings › Pipelines lists the office-wide Pipelines only, one that Project Pipelines are built from saying "Built on by N Project Pipelines" and listing the Projects with how many each has, each a link to that Project's Pipelines, never the Project Pipelines by name; each one the warning on saving a base Pipeline lists is a link to its Project's page (the user, 2026-11-12). The Task's Pipeline picker lists the Project's default first, then its other Project Pipelines, then the office-wide ones, a Broken one listed and flagged with why but not choosable. The editor shows one view of what the Project gets: the built Stages in order, each marked as from the base Pipeline, inserted, replaced, changed (each field beside the base Pipeline's value) or removed (kept in place, struck through), each Stage change with its own Undo; a Broken one says why in plain words where it is and is fixed there (the Task "Design: the Project Pipeline editor", [docs/design](../design/README.md#project-pipelines-what-it-proposes), adopted for the Project page's Pipelines section and Settings › Pipelines by the Task "Edit Project Pipelines in the library, with the warning when a base edit breaks one"; the Task's picker and Devops' Proposal card are adopted by their own Tasks).
- **Shell A3 · Desk** ([prototypes/shell-a3.html](../../.scratch/the-office/prototypes/shell-a3.html)): a 56px icon rail with the five surfaces, which a toggle at its foot expands to show each one's name beside its icon (the choice kept in this browser); a top bar with title, search (tier 2), "Create" (a menu: Task, which opens "New Task", and Idea, which opens "Capture an Idea", each starting in the Project of the page or the one the filter shows; the one place to create either, as Work has no "+ Task", the user, 2026-11-09) and the fire alarm (tier 2); a fixed **status strip** (needs you, desks in use, tokens today, the usage figure: one engine's 5-hour and 7-day windows with the 5-hour meter and reset time, each engine's 5-hour window for two or three, the highest 5-hour window and a count for four or more, with a click on it for several engines listing each one's windows and reset times; Tasks touched, done since you left; on the right the **Workstation figure**, the CPU use now and the logical cores of the computer The Office runs on, opening a panel with its CPU, memory, The Office's own memory and uptime, refreshed every 2 s while the tab is visible; alarm state); content as three panels filling the width, folding to two then one; every item a card with air around it; **each block's left edge coloured by its type or status** (a deliberate deviation from the design system).
- **Progressive disclosure by frequency** ([prototypes/feature-ranking.md](../../.scratch/the-office/prototypes/feature-ranking.md)): many-times-a-day features on the surface, daily ones one step away, occasional and rare ones folded where they apply.
- **The Task page** (round 2, the user's answers of 2026-11-04 and 2026-11-05; the design in [docs/design](../design/README.md), round 2): a full-width **Pipeline rail** shows every Stage with its person or command, state, runs, time and tokens, loop-backs drawn square, and the Planner's Pipeline proposal at its foot, centred. Below it, record left, conversation right at task 48's widths.
  - **The record's column:** **Needs you** first, with the Task's open Decisions and waiting Gate; with nothing waiting, **Before Ready** takes its place, a read-only list (Plan confirmed, Definition of Done confirmed, Pipeline chosen, No Decision open) whose unmet lines each say where they are settled and link there, shown in Backlog only once a part is written. Then the tabs Overview (foldable blocks: the **Description** above the Plan, with Edit, reading "None: the title is all there is" when empty, and below its text the Task's **Dependencies**, with Add before the Task starts, and its **Origin**, when it has one; the Description starts open in every state (the user, 2026-11-11); the Plan and the Definition of Done, each with Confirm beside its Not confirmed badge), **Changes** (files, diff and test results) and Attachments. The head's actions: in Backlog, Plan with…, and Mark Ready once both parts are confirmed; in Planning, Mark Ready.
  - **A Decision** with nothing to look at is answered in place: the question, the context, each answer on its own line with the recommended one marked and its reason, and the user's own words last. One with Attachments shows its question, the recommended answer with its reason and Accept, and Open details, which opens a large window: the context, the pictures, each answer as a choice with the recommended one picked, "In your own words", and Answer in its bar.
  - **The Gate's card** shows what it waits for, a line of its facts, Continue and Show details. Show details opens a large window with the four facts (files changed, lines, tests, Definition of Done), the Attachments no earlier Gate on the Task showed, up to the end of this Gate's run or until now while it waits (pictures as thumbnails, everything else as chips; an HTML file opens in a sandboxed preview), and Continue, Open Changes, Send back with notes… and Drop in its bar; Send back's notes open over the bar.
  - **The Stage history:** selecting a Stage opens a large window of one height. Its head has the Stage's name, its person or command, its state and the ← → hint; its body starts with the Pipeline in small (each Stage's mark and name, pressed or reached with ← and → to move to it). The runs list on the left, newest first, a line or two each (number, state, times, tokens, ↺ when briefed with a failure, two lines of its outcome); everything about the run picked on the right. An Agent run has **Summary** (the outcome, the carried failure, the Gate action and the Handover note at reading width) and **Thread** (with the Details switch on that tab's row), opening on Thread while it runs; a running Stage's Thread follows live and takes a message, which lands at the next safe point, and an ended one's is read-only with "Ask <name> about it". A Project command's run has its outcome and each command's line, result, duration and output (the last 64 KB). A Gate's run has what it waits for and a link to Needs you. In a Thread, a Handover note shows its first four lines and "Read it in full", which opens that run's Summary.
  - **The conversation:** a tab per person ([2.4](2.4-conversations.md)): the holder of Plans first (amended 2026-11-13), then each person who ran an Agent Stage of the Task, then each Consultant; a live dot while their Stage runs, a count of unseen messages. The first tab shown is the one whose Thread holds an open Decision, else the person whose Stage runs, else the holder of Plans. A tab holds that person's one Thread, a **Details** switch, and one composer that always writes there, with a To line marking the cache before the person's name ([2.5](2.5-context-policy.md)) and Auto, Continue and Start fresh under it. While the person's Stage runs, a banner says so and opens the Stage history: "To write into that work, open its Stage history." In Backlog the holder of Plans' tab has no composer and offers **Make a plan**; while nobody holds Plans the tab shows "Nobody holds Plans" with a link to Settings › Duties ([2.1](2.1-work.md)). Stage Threads show only in the Stage history; a Decision's link to its Stage run opens the Stage history at that run.

- **The Work board:** a Task's card shows its title in words and everything else as marks in one row under it, after [docs/design/task-card-icons.html](../design/task-card-icons.html), Foot row (the user's choice of 2026-11-13): the Project's mark, then what needs the user (Waiting on you, Paused, Dropped), what holds the Task (the lock with how many Tasks block it, the Queued clock), the quiet ones (Planning, the Usage estimate), and at the right end who is working on it or, in Backlog, Plan; the priority stays before the title and the Task menu after it. Each mark's words show on hover, or in a popover on a press for the lock and the clock ([4.1](4.1-ui-rules.md#components)). Who is working on it right now: their avatars with a live dot, at most three and then "+N", the names in its tooltip. A person counts while one of their Threads on the Task (a Stage Thread, their own Thread or a Consultation) is answering with no open Decision. When the Task's current Stage is worked by one of them, the tooltip names it too; Planning, a Script Stage or a Gate, and someone else's Thread name no Stage. The card shows no Tags: they stay on the Task page, in "New Task" and in the board's search (the user's request, 2026-11-09).
- **The Initiative page:** its foldable blocks left, and right its conversation as the Task page's: a tab per person, the holder of Shapes Initiatives' first and the holder of Plans', each always shown, one tab when one person holds both, and while a duty is unheld its tab shows the fallback and points to Settings › Duties (amended 2026-11-13), then anyone else with a Thread on it; each tab with the person's name and title, what they do here, and Details, over that person's Threads (one shown directly; with several, the earlier ones folded to a line until pressed) and a composer whose To line goes to their newest Thread and lets the user pick another of theirs. - **A Thread reads like a team channel** (the Rows design of [docs/design/thread-dialog.html](../design/thread-dialog.html), the user's answer of 2026-11-05): each Turn has its avatar, name and time on the left, and the user's and the person's differ by their avatar and name only, the user's avatar neutral. A person's avatar is their Avatar, or their initials and tint without one ([2.2](2.2-people.md)). Decisions, Handover notes and the other cards stay as they are.
  - **Tool calls:** neighbouring ones fold to one line with their count and the latest call, and open to every call; a lone one is a plain line with nothing to open. Details hides them; with Details off, the latest call sits beside "is working" on one line and opens to show it whole. A call's whole text is kept, line breaks included, and shows at any width: it wraps, and only a very long one scrolls in its place. Messages already stored stay cut at 200 characters, as the rest was never kept (chosen while planning, for the user to review).
  - **The Office's lines** have no box: a run or a day sits on a hairline, the others are small centred notes, and a Thread that spans days opens each day with a line. A failure and an MCP server that didn't start show as a tinted strip.
- **Every item shows its Project mark and name.** The mark is chosen when a Project is added and changed at any time in the Project page's Appearance section. Its colour may be any colour: one of the four offered, or a custom one the user picks, with the label turning dark or white to stay readable. **Icon and Logo:** Appearance also takes an Icon and a Logo, each a PNG, JPEG, WebP or SVG of at most 2 MB, read from the file's contents and shown as uploaded. Either is uploaded or chosen from the repository in the Repository file browser, which shows only those four kinds by their extensions; a chosen file is copied into The Office and is then treated as an upload, so a later change to it in the repository does nothing until it is chosen again. The Icon shows in place of the mark's letters and colour wherever the mark shows. The Logo has no tile and shows at its own proportions on the Project's page and card, in place of the mark. Each takes a light and a dark version, each uploaded, chosen, replaced or removed on its own and saved as soon as it is picked; wherever the image shows, the version for the palette shown (Account › Appearance) is used, and switching the palette swaps it without a reload. One version alone shows in both palettes, and a version that can't be loaded gives way to the other. Each version shows in its own tile on the Images card, on that palette's page colour whatever palette is shown, taking a dropped file or a press to browse, and an empty tile says which version shows instead. Either can be removed; Logo falls back to Icon, and Icon to the letters and colour, also when an image can't be loaded. An SVG is only ever shown as an image, so a script inside it can't run. Appearance previews the result beside what is being changed, the Project's page head, its card and its mark beside an item, in the palette shown or the other one, so a mark shows as it will look before it is saved. The Project filter (tier 2) narrows every surface, never Office-wide numbers or the rail badge.
- **Colour, palettes and densities:** muted text, borders and surfaces; status colours, accent, badges and icons at the design system's values; dark mode is dark gray; logos in brand colours. Tier 1 ships Light and Dark; tier 3 adds Graphite, Paper and the densities. The values below are the mockup's `themes.css`, attached to the Initiative of build task 41 (the user's answers of 2026-11-10); Midnight, Mocha, Mist and Sage were added at the user's request of 2026-11-11, and Aubergine, Lagoon, Cobalt and Lavender at their request of the same day for "something more brave, yet still pro-looking": these four tint their surfaces and sidebar more strongly and colour their primary buttons, while the text, accent and status rules still hold; Emerald and Citrine were added at their request of the same day for "something really special, extraordinary": each pairs its tinted surfaces with a contrasting metal or ink, gold buttons and a gold active sidebar item on emerald, and indigo buttons on a butter-yellow page with a golden active sidebar item.
  - **Three layers:** the design system's tokens (ramps, type, motion) are never changed; a **palette** remaps the colour aliases (backgrounds, surfaces, text, borders, status); a **density** remaps the spacing, control and text-size aliases. Components use aliases only, so a palette or a density changes colours and air, never layout. Brand marks use the design system's ramp colours directly, so no palette mutes them. The status colours (badges, edges, dots) and the accent are aliases too, but every palette keeps the design system's values.
  - **Palettes**, picked in Account › Appearance or from the rail's Theme menu: **Light** (the default, muted), **Dark** (dark gray, not black), **Graphite** (dark, cool) and **Paper** (light and warm, from the brand system's beige), **Midnight** (dark, a deep blue-tinted navy, not black), **Mist** (light, a cool soft blue-grey), **Mocha** (dark, a warm brown-grey) **Sage** (light, a soft muted green-grey), **Aubergine** (dark, a deep plum-violet with lavender buttons), **Lavender** (light, a soft violet page with deep violet buttons), **Lagoon** (dark, a deep teal with sea-green buttons) and **Cobalt** (light, crisp white on a clearly blue page with cobalt buttons), **Emerald** (dark, a deep emerald green with champagne-gold buttons and a gold active sidebar item) and **Citrine** (light, crisp white on a butter-yellow page with deep indigo buttons and a golden active sidebar item), or following the system, which shows Light or Dark.

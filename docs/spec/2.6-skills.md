# 2.6 Skills

From [23](../../.scratch/the-office/issues/23-skills.md), [22](../../.scratch/the-office/issues/22-skills-per-session.md).

- **The library** is Office-wide (Settings → Skills): one folder with each skill once in its own subfolder; the database holds a record per skill (name, description, source, version, enabled, files hash), the Role → Skill mapping and an "everyone" flag.
- **Adding:** install from a source (tier 2; an install, so Devops does it and the user confirms), upload a `.md` or a zipped folder, or write one in place. Every new skill arrives off; the user reviews its files before turning it on. Pinned versions update by Proposal (tier 2).
- **Project skills** stay in the repository and apply unless the Project page turns them off; listed read-only.
- **A session gets** its Role's skills plus the "everyone" skills plus the Project's when allowed, and nothing else (mechanism in [5.6](5.6-skills-per-session.md)).
- Short descriptions matter: the listing gets about 1% of the context window.

## Defaults

Gaps no ticket settled, filled with the simplest choice consistent with the tickets and accepted by the user; each says when.

- **Skills the user writes or uploads** also arrive off and are turned on after review, as [23](../../.scratch/the-office/issues/23-skills.md) says for every new skill; for one's own text the review is one click. (accepted 2026-10-24)
- **A skill's new version waits for review too:** a saved change that changes its files turns it back to off, waiting for review, as a new skill arrives; turning it on again is one click. Running sessions keep the version they started with. An applied update is the exception (below). (added while building tier 1, accepted 2026-10-25; amended 2026-10-28)
- **Installing from a source** (the user's answers of 2026-10-28): a source is a git repository (`owner/repo` on GitHub, or a git URL). Devops lists the skills it holds and drafts one Proposal per skill; applying it is the user's confirmation, and The Office's own code fetches the skill at its pinned version into the library, off until reviewed. Devops never writes to the library. With no Devops hired, Install says installing needs someone with the Devops Role.
- **The pinned version** is the source's newest tag when the skill is installed or updated, or its default branch's newest commit when it has no tags. (the user's answer of 2026-10-28)
- **Updates are flagged, then proposed:** The Office checks each pinned source daily with `git ls-remote`, which spends no quota, and only marks the skill "Update available". The user asks Devops, who drafts the update Proposal with notes. (the user's answer of 2026-10-28)
- **An applied update is its review:** the update Proposal shows the files' diff, and applying it saves the skill's next version and leaves it on or off as it was. Running sessions keep the version they started with. (the user's answer of 2026-10-28)
- **A skill drafted as a Proposal:** someone in a chat drafts a written skill; applying it adds the skill off, reviewed as any new skill. (the user's answer of 2026-10-28)
- **A skill's description** may run to the engine's own limit of 1,536 characters and over several lines, for every skill however it is added, so published skills install as they are; Review flags one over 500 characters, a sixteenth of the listing at 200k. (the user's answer of 2026-10-29)
- **Editing a skill** is in its Review: Edit for a written skill (the Write form, filled in), Upload a new version for an uploaded one. (added while building tier 1, accepted 2026-10-25)
- **A skill's frontmatter is read as the engine reads it:** a plain value holding `: `, which YAML refuses, is the text after the first `: `; only what the engine can't read either is refused. (added while building tier 1, accepted 2026-10-25)
- **A skill's frontmatter is flagged, not refused:** Review warns of each key that changes a session (its own hooks, model or effort, tool rules, a subagent, `when_to_use`, `disable-model-invocation`), as it does of scripts. (added while building tier 1, accepted 2026-10-25)

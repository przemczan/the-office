# 2.1 Work

From [07](../../.scratch/the-office/issues/07-work-model.md), with [08](../../.scratch/the-office/issues/08-pipelines.md) and [19](../../.scratch/the-office/issues/19-work-mockup.md).

- **Project:** a repository The Office works on, with its own commands (install, build, lint, test), install inputs, default Pipeline, publishing mode (push + PR, or merge, run by The Office's own code; see [9](README.md#defaults)), environment and skills setting.
- **Idea:** captured quickly, in a Project or Office-wide. States: new, shaped, dropped. Shaping makes an Initiative or a Task and keeps the Idea as the origin link; its Attachments move with it.
- **Initiative** (tier 2): Office-level, spans Projects; each of its Tasks is in one Project. States: shaping (with the CTO), active, done (all Tasks done), dropped. Order inside it is dependencies plus manual order.
- **Task:** one unit of work in one Project, done when its **Definition of Done** is met: a published change, an Attachment, or both.
  - States: **Backlog → Planning → Ready → In progress → Done**, side states **Waiting on you** and **Paused**, exit **Dropped**. Ready requires a Plan and a Definition of Done, both confirmed by the user, no Pipeline proposal left open and no Decision on the Task left open (the user's answer of 2026-10-26). In progress shows the current Stage.
  - **Plan** (how) and **Definition of Done** (what must be true) are separate first-class parts of the Task, co-written with the Planner in a thread on the Task, confirmed by the user.
  - **Dependencies** (tier 2): on any Task in any Initiative or Project; a blocked Task cannot start.
  - **Organisation:** three priority levels plus manual order per Project (tier 1); tags, full-text search, saved views (tier 2); archive after a while (tier 3).
  - **Moving** between Projects (tier 3) until In progress; the Plan is then marked for the Planner to re-check.
- **Attachment:** a document (Markdown), image or screenshot, file or link, attached by the user or an Agent to an Idea, Initiative or Task; can be a Task's result. Diffs and Stage logs are parts of a Task, not Attachments. Versions are tier 3.

## Defaults

Gaps no ticket settled, filled with the simplest choice consistent with the tickets and accepted by the user; each says when.

- **Start in tier 1** is refused with the reason when the Project already has a Task in progress, the person is at their Task limit or the Office-wide limit is reached (as the click-through does); no queue. (accepted 2026-10-24)
- **Waiting on you while planning:** a Task in Planning with an open Decision stays in Planning and shows a Waiting on you badge; the Waiting on you state stays a side state of In progress. (added while building tier 1, accepted 2026-10-25)
- **Plan as a Task with the Planner** on an Idea shapes it into a Task and opens its planning at once, as the click-through does. (added while building tier 1, accepted 2026-10-25)
- **Tasks of an Initiative still being shaped** (the user's answer of 2026-10-28) are planned and started like any Task: Start is already the user's call for each. Confirming the Initiative says its outcome and Task list are agreed and makes it active.
- **Shaping without a CTO** (the user's answer of 2026-10-28): an Idea is shaped into an Initiative whether or not a CTO is hired. With one, the shaping Thread opens at once and the CTO starts on it; without one, the user writes the Initiative by hand, and its Thread opens when they start it once a CTO is hired.
- **The CTO's changes to an Initiative** (the user's answer of 2026-10-28): while it is shaping, the CTO writes the outcome, Tasks and dependencies straight onto it, and the user confirms the whole once; once it is active, each change the CTO wants is a Proposal the user applies.
- **A Dropped blocker** (the user's answer of 2026-10-28) no longer blocks; the Task that waited for it still lists it, marked as dropped.
- **An Initiative is done** (the user's answer of 2026-10-28) once it is active and every one of its Tasks that isn't Dropped is Done, at least one of them; a shaping one waits for Confirm, which makes it done at once when its Tasks already are. Dropping an Initiative leaves its Tasks as they are.

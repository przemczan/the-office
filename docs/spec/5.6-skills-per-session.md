# 5.6 Skills per session

Covers: the session's skills folder, SDK options and settings, the allowlist, what a session must list at start, the start check, `CLAUDE_CONFIG_DIR`, the other engines.

## The session's skills folder

- No Claude Code engine option names skill folders, so the Skills module writes `<office-data>/sessions/<session-id>/skills/` outside the worktree and the library.
- The session's owner hands the folder, the allowlist and the overrides to the Engine, whose adapter checks them at start.
- The folder holds `.claude-plugin/plugin.json` (`{"name":"office"}`) and a copy of each skill at its pinned version, regular files only (links and junctions refused).
- It is removed once the session can't be resumed.
- It is rebuilt from recorded versions on resume, never with a changed set: the engine announces only added skills on resume, so a removed one would stay named in the conversation.

## SDK options and settings

- Options: `settingSources: ['project']`; the folder in `plugins`; `skills` listing `office:<name>` for each skill plus the keys of the Project's skills that are on.
- Settings: `syncClaudeAiSkills` and `syncClaudeAiPlugins` false, `disableBundledSkills` true, `disableSkillShellExecution` true (a skill's text runs no command when it loads; the Agent runs it, through the hook).
- `skillOverrides: "off"` per Project skill and command the Project turned off, one by one or all together.
- Each override is keyed as the allowlist matches it: a skill by its folder name, whatever its frontmatter calls it, at any depth; a command by its path under `commands/` with `:` between folders.
- A key leaves the library's `office:<name>` of the same name on (`skills.overrides-library`).
- The hook lets the file tools read the folder ([6](6-permissions-and-safety.md)).
- No `additionalDirectories` grant is needed with the engine's read fence off, and the `additionalDirectories` option would also load the folder's `.claude` as a project source.

## The allowlist

- The allowlist only filters the context and matches names by suffix.
- Allowed Project names are checked against the session's other skill names.

## What a session must list at start

- Its library skills, and the Project's skills and commands that are on at the repository's top, by the names the listing gives them (a skill's frontmatter name).
- Nested ones are listed only once a file below them is read.

## The start check

- Before the first message, `reloadPlugins` (holding on any cache impact) lists the plugin with no errors and the skill names in `getContextUsage()` equal the expected set, or the session doesn't start.
- The engine sends `init` only with the first message; an `init` that disagrees ends the session.

## CLAUDE_CONFIG_DIR

- `CLAUDE_CONFIG_DIR` is per engine, never per session (credentials and transcripts move with it).
- Each Claude Code engine has its own, per account ([5.4](5.4-the-engine.md#defaults)): every session of that engine shares its credentials and transcripts.
- The settings above keep that folder's own setup out, as they do `~/.claude`'s.

## The other engines

- The Codex engine and the OpenAI-compatible API engine list exactly the session's skills through their `Skill` tool and load them by name.
- The Copilot CLI engine loads the session's skills folder through the SDK's `skills.directories`, with the runtime's bundled skills kept out.
- Each is checked against the expected set at start ([5.4](5.4-the-engine.md#defaults)).

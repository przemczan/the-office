# 06 · The Engine module: port, Agent SDK adapter and Office rules

Status: in progress

## Goal

The Engine module runs sessions behind an `AgentEngine` port that isn't Claude-shaped, with two adapters: the Agent SDK on the user's own login, and a scripted adapter that replays recorded sessions so every later test runs without model calls. Every tool call passes one `PreToolUse` hook that applies the Office rules in code and the permission profile it is given as data. Usage and the 5-hour window come out of the stream.

## Definition of Done

- [x] The port covers: start a session with a brief and options, send a message with a priority, interrupt, resume by session id, end (with its process tree), and a typed stream of messages, tool calls, usage and rate-limit events; each adapter declares its capabilities. Check: the port's contract tests run against both adapters.
- [x] The Agent SDK adapter starts sessions with the Office's session options (spec §5.4, §5.6 and §6, measured in [engine-check.md](../engine-check.md)), and two sessions in different worktrees of one repository share their cached prefix. Check: the adapter's integration test reads cache tokens on the second session.
- [x] The hook refuses, with a reason the Agent reads: a git command that changes anything; reads of the secrets of spec §6; Agents' writes to the protected paths; anything outside the given profile. Path decisions are the hook's, with no path-scoped deny rules. Each shell rule has a PowerShell twin on Windows, and the secret paths come from the platform layer for each operating system. Check: unit tests per rule for Bash and PowerShell on both platforms' paths, and one live session that is refused and reads the reason.
- [x] Every engine call is a span with input, output, cache-read and cache-write tokens and cost; each `rate_limit_event` triggers a read of the usage query, which updates an Office-wide window state (5-hour and 7-day utilization and reset time) published as a domain event. Check: the trace in Grafana and the event in a test.
- [x] Ending a session ends every process it started (dev servers, watchers): its process tree on Windows, its process group on Linux, both behind the platform layer. Check: a session that starts a long-running process, then end it and look for the process, on both platforms.
- [x] Office tools: modules register in-process tools on one registry, and a session gets the ones its caller names. Check: a test tool called from a live session.

## Steps

- [x] 1. The port in `modules/engine/ports/`: session options (cwd, model, effort, brief, skills folder, profile, Office tools, output schema), the stream types and the capability flags. The scripted adapter replays a recorded stream file and records new ones from the SDK adapter. Contract tests against the scripted adapter. Commit.
- [x] 2. The Agent SDK adapter: one long-lived streaming `query()` per session, the Office's session options, priority on sent messages, `interrupt()`, resume by session id, and the stream mapped onto the port's types. Contract tests against it with the cheapest model. Commit.
- [x] 3. The Office rules hook: git read-only (`status`, `diff`, `log`, `show`), secrets refused by file tools and in command text, protected paths, reads fenced to the worktree and the session's folders, writes fenced to the worktree (the engine auto-allows some of its own paths outside it), each shell rule with its PowerShell twin, and the profile (read, edit, run, web) applied as data. Refusals carry a reason and are emitted as events for the Thread log, taken from the hook's own decisions, `permission_denied` messages and `result.permission_denials` (spec §6). Commit.
- [x] 4. Usage and the window: per-call usage on spans and metrics tagged with the prompt features used (skills, Office tools), the window state read from the usage query on each `rate_limit_event`, and its event, and an "engine down" event when the binary can't start or the stream dies. Commit.
- [x] 5. Process cleanup on end, and the Office tools registry built on `createSdkMcpServer()`. Commit.
- [x] 6. Check on the Test Project: a read-only session in a worktree that reads a file, is refused a git commit and an `~/.ssh` read, and reports usage; record its stream for the scripted adapter's fixtures. Commit.

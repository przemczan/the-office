# 27 · Notifications: the kinds × channels grid, quiet hours, batching; the fire alarm

Status: in progress

## Goal

The user decides in Settings which kinds of Notification go to which channel, on a grid of the kinds tree, a row inheriting from its group until set; sets quiet hours, in which nothing is pushed but "an Agent engine down" and after which one summary comes; and gets Outcomes landing close together as one Notification. One Office-wide **Sound the alarm** in the top bar stops every Stage, waiting Task and Consultation at the next safe point (a hard stop after 60 s), lets chats go on without tools unless the user lets one person act in one Thread, and **All clear** first shows on Now what will resume, how and at what cost, with Resume, Hold or Drop per Task. Spec [2.7](../spec/2.7-notifications.md) (the grid, quiet hours, batching, the at-desk hold), [2.8](../spec/2.8-fire-alarm.md), [2.5](../spec/2.5-context-policy.md) (how a Task resumes); tickets [20](../../.scratch/the-office/issues/20-notifications.md), [15](../../.scratch/the-office/issues/15-fire-alarm.md); coverage rows for task 27 in [coverage.md](coverage.md).

Task 28 brings the phone: HTTPS on the LAN, the PIN, the installed app, the Web Push adapter, the Phone card's set-up and test notification, and the alarm on the phone. This task builds the phone as a channel in the routing and the delivery rules (the grid's Phone column, "Not set up yet"; the at-desk hold and the away delay), sent through a port whose only adapter records; 28 plugs Web Push into it (the user's answer of 2026-10-29).

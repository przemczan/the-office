# 08 · People: Role cards, presets and a person's page

Status: done

## Goal

The People module and surface: the user hires the Planner, a Developer and a Reviewer from presets, names each person, and edits their Role cards. The Role card holds everything a session of that person needs (instructions, model, effort, engine, capabilities, permission profile, Hard switches, Task limit, session default, Skills), and a change applies from the person's next session. People shows a grid of same-size cards and a page per person.

## Definition of Done

- [x] Hiring from a preset creates a named person with the preset's Role card: capabilities, Task limit, Hard switches and profile as in [spec §2.2](../spec.md#22-people), [§6](../spec.md#6-permissions-and-safety) and [§9](../spec.md#9-defaults-chosen-in-this-spec). Check: hire all three, compare each card with the tables.
- [x] The Role card form edits name and title, responsibilities, instructions, model, effort, engine, Chat, Consultant, Task limit (1–6 or none), the session default (Context policy, Always start fresh, Prefer to continue) and Skills; and each Hard switch (Allowed, Consult *person*, Ask me, Never), marked as enforced by The Office or followed by the Agent, with Change Roles kept at Never ([spec §9](../spec.md#9-defaults-chosen-in-this-spec)); Shared memory shows and stays off until tier 2; the permission profile shows read-only.

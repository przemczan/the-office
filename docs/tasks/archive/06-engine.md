- 2026-10-25 · step 2: `AgentSdkEngine` in `adapters/agent-sdk/`: one streaming `query()` per session with the Office's options (`sdk-options.ts`, the engine check's set; the shells come from the new `OperatingSystem.agentShells`), Office tools on an in-process `office` server allowed by rule, the stream mapped onto the port (`sdk-events.ts`, unknown kinds ignored). The contract passes live on Windows with `claude-haiku-5-5` (`OFFICE_ENGINE_TESTS=live`, about 40 s), and `OFFICE_ENGINE_TESTS=record` replaced the hand-written recordings with live ones; the cached-prefix test across two worktrees passes. Next: step 3, the Office rules hook. Surprising: `total_cost_usd` is cumulative and a resumed session's includes the turns before the resume, so the port reports `sessionCostUsd` rather than a turn's cost (step 4 takes deltas); `result.usage` is per turn, and zero for an interrupted turn; an output schema runs as a `StructuredOutput` tool call, which the hook must allow; the port's options gained `environment` (spec §5.5, the Project's command environment), from which the adapter drops `CLAUDE*`, `ANTHROPIC*`, `MCP_*`, `OTEL_*`.
- 2026-10-25 · step 3: the Office rules in `domain/` (`OfficeRules.decide` on an engine-neutral `AgentAction`; `shell-commands.ts` reads Bash and PowerShell command lines into simple commands by position, substitutions, here-documents and nested `bash -c`/`eval`/`cmd /c`/`pwsh -Command`/`iex`/`Start-Process` included, and refuses `-EncodedCommand`; git read-only; secrets by path, by the session's variables and by home-relative names; protected `.git`/`.claude`/`.mcp.json`; read and write fences; the profile as data, with output redirection refused where commands are restricted). The platform gives `secretPaths` and path semantics (`resolve`, `isWithin`, `names`, Git Bash paths on Windows); `PermissionProfile` moved to the domain. The SDK adapter classifies each tool (`tool-actions.ts`, unknown tools refused), registers the one `PreToolUse` hook (allows explicitly, fails closed) and reports `tool-refused` events from the hook, `permission_denied` and `permission_denials` once each (`tool-refusals.ts`); it also drops The Office's own variables (`DATABASE_URL`) from the session environment. The contract gained a `refusal` scenario, passing live and recorded. Next: step 4, usage and the window. Open: on Linux the engine reads a background command's output under `/tmp/claude-*/…/tasks/`, which the read fence now refuses; to check on the Linux host and ask the user whether that counts as one of the session's folders.
- 2026-10-25 · step 4: `EngineSessions` (application, exported with `EngineModule`, now in `AppModule` with `AgentEngine` bound to the SDK adapter) watches each session: an `engine call` span per turn from when it begins to its end, with tokens, cost (the difference of `sessionCostUsd`, left out for a resumed session's first turn when its total before is unknown), model and prompt features (`skills`, `office-tool:<name>`), and `office.cost` beside `office.tokens` in `Telemetry`; on a rate-limit signal it reads the usage windows into `UsageWindowState`, which publishes `UsageWindowsChanged` when they differ; `EngineDown` when a session can't start or its stream dies, the SDK adapter naming the end of the engine's stderr. The scripted engine now answers usage-window reads whenever they come, from the windows its script recorded, since the Office decides when to read. `AsyncChannel` moved to `platform/streams/`. Fixed a flaky Projects test that compared an event's timestamp. Next: step 5, process cleanup on end and the Office tools registry; the Grafana check of the trace is left to step 6, which runs a live session with telemetry exported.

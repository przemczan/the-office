# Progress log: 05 · Git, worktrees and the environment check

Moved from [05-git-worktrees.md](../05-git-worktrees.md) when the logs were archived. One line per commit, newest last.

- 2026-10-25 · step 1: `RepositoryLocks` and `CommandLineGit` behind the `Git` port: fetch (into `refs/remotes/<remote>/<branch>`), push (never forced), worktree add (new branch or detached) and remove (prune when the folder is gone), commit (everything, message on stdin, `--no-verify`: a Project's hooks are its own tooling, run as Stages), HEAD and branch, restore (tracked files only, so screenshots survive) and discard (tracked and untracked, ignored files such as dependencies stay). Push was added here because the DoD's concurrency check names it; commits take the lock too, since a branch's ref lives with the shared refs. The lock key is git's `--path-format=absolute --git-common-dir` through `realpath`, so the main checkout and a worktree name it alike. The remote is a parameter; step 2 decides which one. Next: step 2, Task worktrees. Surprising: the user's global `core.autocrlf=true` reached the temp repositories, so the fixture turns it off.

- 2026-10-25 · step 3: the Project's environment (`set` as name and value pairs, `unset`, `prependPath`) is a `jsonb` column (migration `0002_project_environment`), empty until an environment check saves one, and in the API's Project. `ProjectCommandRunner` takes the environment as an argument, so step 5 can try an unsaved one, and builds the variables with `commandEnvironment`: the service's own without `isOfficeOwnVariable` (beside `readOfficeConfig`: The Office's config, `DATABASE_URL` included, the compose and `OTEL_*` settings, npm's variables from `npm start` such as `npm_config_local_prefix`, and `NODE_ENV`), then unset, set, prependPath; on Windows a name in another case changes the inherited variable. A user's npm config given only through `npm_config_*` variables is dropped too; `set` puts it back. `ShellCommandRunner` runs the platform's shell, keeps the end of the output, stops reading 0.5 s after exit (a process left running holds the pipes), and at a timeout ends the whole tree. The platform layer gained `processTrees` (a process group on Linux, `taskkill /t` on Windows; task 06's leftover processes can reuse it), `sameVariableName` and `Shell.couldNotRun` (126/127 on Linux; on Windows a program, not a built-in, that cmd.exe would not find in the folder, PATH and PATHEXT). Output is filtered to failure markers with 3 lines around, plus the last 30 lines, capped at 6,000 characters. Next: step 4, Task worktrees; decide there whether git on a Project gets the command environment (hooks: `worktree add` runs post-checkout, and `push` runs pre-push, which Git LFS needs). Surprising: Node on Windows ends a child's children when it exits unless they are detached, so the leftover-process test detaches its process.
- 2026-10-25 · step 4: `TaskWorktrees` (application) prepares a Task's worktree at `<office-data>/worktrees/<project>/<task>` on branch `office/<task>`: a new one starts at the base branch's upstream, fetched first, or at the local base branch when it tracks none (`freshBase`, which step 5 reuses); an existing folder is given back as left, and a branch left from a removed worktree is checked out as it is. Install runs through the command runner and records a fingerprint (version, install command, environment, each install input's hash) in the worktree's own git records (`worktreeRecordPath`), written only when it passes; the environment is in the fingerprint too, since a changed toolchain needs a fresh install. Git on a Project now gets its command variables (a `GitVariables` argument on every call that can run hooks or filters), so post-checkout and pre-push hooks, Git LFS's among them, run with the Project's environment; commits still skip hooks. Read-only git calls keep the service's own variables, with English messages. `OfficeDataDirectory` is a global platform provider (`OfficeDataModule.forRoot`). Next: step 5, the environment check. Note: git's own timeout ends git, not a hook's children.
- 2026-10-25 · step 5: `EnvironmentChecks` runs the check in the background: a throwaway worktree (`_<8 hex>` beside the Tasks' folders, which no Task id can name; earlier ones are removed first, as a process may have held one), install, then build, lint and test, each run even when another fails, so every failure shows at once; a failed worktree or install skips the rest. Command lines are frozen at the start, the worktree check records the base commit and `origin/main` (or nothing when the base branch tracks none), and the environment is saved through `ProjectService.changeEnvironment` only when everything passed, before the finished check is kept (`environment_checks`, one row per Project, migration `0003`). A running check lives only in memory; `beforeApplicationShutdown` stops it (commands now take an `AbortSignal` and end as `stopped`), removes its worktree and keeps it as stopped, so a restart never finds one left running. `POST /projects/:id/environment-check` answers 202 or 422 with every reason (names, relative PATH folders, one already running); `GET` answers the running or last check. Events: started, one per check's state, finished; the web gets `project.environment-check-changed` and `project.environment-changed`. `TaskWorktrees` became `Worktrees`, as it also makes the throwaway ones.

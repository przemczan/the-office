# 36 · MCP servers for Agents

Status: done

## Goal

A Role's Agents can use the tools of MCP servers the user chose for it. The user adds each server to an Office-wide library in Settings → MCP servers, reviews it before it can be used, and assigns it on the Role card. A server's Server values are set Office-wide and overridden on a Project's page. Every MCP tool has its own setting in the Role card's permission profile, starting at Consult Devops, and the Office rules judge each call before it runs, on all three engines.

## Definition of Done

- [x] The user adds an MCP server by a form or by pasting its JSON config: a local command (stdio) or a remote URL (Streamable HTTP), with its Server values (environment variables or headers; plain or secret; required or not). Each value has an Office-wide value; a secret is never sent back. The user edits and removes servers. Check: service tests of the library, its validation and its routes; the contract's schemas.
- [x] A server is off until reviewed: the review shows its command or URL, its values and the tools it lists on a test connection, and turning it on records that tool list. Changing the server turns it off until it is reviewed again. Check: service tests against a fake stdio MCP server and a fake HTTP one.
- [x] A Role card assigns servers, and a Project's page overrides Server values. A session starts with its Role's servers that are on, with its Project's values (the Office-wide values in chat), fixed for the session and kept on resume. A server missing a required value is left out, and the brief says so. Check: service tests of the session's servers; a Conversations test of a Stage and a chat getting them.
- [x] Each MCP tool has a setting in the permission profile (Allowed, Consult a person, Ask me, Never), starting at Consult Devops; a Stage narrows it, never widens it. The Office rules judge each call: Allowed runs, Consult and Ask me hold the call as a Hard switch's call is held, Never refuses in the rules' words. Check: domain tests of the profile; rule tests through `toolDecision`.
- [x] The Agent SDK and `-p` engines run the session's servers with only the Office's MCP config (never a Project's `.mcp.json`), and the OpenAI-compatible API engine runs them through an MCP client in its loop, ending a local server's process tree at the session's end. Check: `describeAgentEngineContract`'s MCP scenario on each engine (the scripted engine, the API engine on its fake server); `npm run verify` and `npm run verify:linux`.
- [x] The web: Settings → MCP servers (the list, add by form or JSON, review, on and off, Office-wide values); the Role card's MCP servers and each tool's setting; the Project page's Server values. Check: e2e tests of each.
- [x] Seen once live on the Test Project with the Agent SDK engine and the cheapest model: a Role with a local MCP server calls one Allowed tool and one at Consult Devops, which waits on a Consultation and then runs. Check: the run summarised in State and recorded in [engine-check.md](../engine-check.md).
